## T5.1 装哪几个扩展就够了

新手最容易犯的错是**看到推荐就装**，最后装了二十个扩展，编辑器卡、功能互相打架。

**只装这四个（第五个按需）**：

| 扩展 | 作者 | 作用 | 必要性 |
|---|---|---|---|
| **Python** | Microsoft | 基础支持：运行、调试、解释器管理 | 必装 |
| **Pylance** | Microsoft | 智能提示、跳转定义、类型检查 | 必装（装 Python 时通常自动带上） |
| **Ruff** | Astral Software | 代码检查 + 格式化 + 整理 import | 强烈建议 |
| **Jupyter** | Microsoft | `.ipynb` 笔记本支持 | 做数据分析必装 |
| SQL Server (mssql) | Microsoft | 连 SQL Server 跑查询 | 按需 |

### 明确不要装的

| 不要装 | 原因 |
|---|---|
| Pylint、Flake8、autopep8、isort、Black Formatter | **Ruff 一个工具就把这些的活全干了**，而且快一到两个数量级。装了会重复报错、格式化互相冲突 |
| IntelliCode | 功能已被 Pylance 覆盖 |
| 各种"Python 全家桶"合集 | 里面夹带一堆你不需要的东西 |

### 为什么是 Ruff

到 2026 年，Ruff 已经是 Python 代码质量工具的事实标准——它用一个程序替代了原来 Black（格式化）、isort（整理 import）、Flake8（检查）三件套，[官方定位就是 Black 的直接替代品](https://docs.astral.sh/ruff/formatter/)，格式化结果与 Black 几乎完全一致。

**对你的实际意义**：少装两个扩展、少配两处设置、保存时的格式化几乎无感（它用 Rust 写的，快得离谱）。

> 如果你在别处看到教程让你装 Black + isort + Flake8，那是 2023 年前的做法，**不用照做**。

## T5.2 必改的六个设置

打开设置文件的方法：`Ctrl+Shift+P` → 输入 `Preferences: Open User Settings (JSON)`。

**直接把下面这段贴进去**（如果文件里已有内容，把这些键合并进去，注意逗号）：

```json
{
  // ① 缩进：Tab 转成 4 个空格
  //    这就是第 2.2 节要求你设置的那一项——Python 混用 Tab 和空格会直接报 TabError
  "editor.insertSpaces": true,
  "editor.tabSize": 4,

  // ② 显示空白字符：让缩进问题肉眼可见
  //    "boundary" 只显示行首行尾和连续空格，比 "all" 干净
  "editor.renderWhitespace": "boundary",

  // ③ 保存时自动清理：去掉行尾多余空格、文件末尾补一个换行
  //    这两项能减少大量无意义的版本差异
  "files.trimTrailingWhitespace": true,
  "files.insertFinalNewline": true,

  // ④ 打开终端时自动激活虚拟环境（配合第 19 章）
  "python.terminal.activateEnvironment": true,

  // ⑤ 默认解释器指向项目里的 .venv（配合第 19.13 节）
  "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python",

  // ⑥ Python 文件专属设置：用 Ruff 格式化 + 保存时自动修复
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff",
    "editor.formatOnSave": true,
    "editor.codeActionsOnSave": {
      "source.fixAll.ruff": "explicit",
      "source.organizeImports.ruff": "explicit"
    }
  }
}
```

### 几个需要说明的地方

**关于 ⑤ 的路径**：`.venv/bin/python` 是 macOS / Linux 的路径。**Windows 上是** `.venv\\Scripts\\python.exe`（JSON 里反斜杠要写两个），或者干脆写 `.venv/Scripts/python.exe`（正斜杠 Windows 也认）。

**关于 ⑥ 的 `"explicit"`**：这是较新版本的写法。如果你的 VS Code 比较老、这个值不生效，改成 `true` 试试：

```json
"editor.codeActionsOnSave": {
  "source.fixAll.ruff": true,
  "source.organizeImports.ruff": true
}
```

**`source.fixAll` 和 `source.organizeImports` 分别做什么**：前者自动修复能安全修复的问题（删掉没用的 import、补上缺的空行）；后者按规范排序 import（回收第 18.15 节的三组顺序）。**保存一下，import 就自动排好了**，不用手工整理。

### 用户设置还是项目设置

上面改的是**用户设置**（对所有项目生效）。如果某个项目要特殊配置，在项目根目录建 `.vscode/settings.json`，**项目设置会覆盖用户设置**。

**建议**：缩进、空白字符这类个人习惯放用户设置；解释器路径、项目特有的检查规则放项目设置（这样团队成员拿到代码就有一致的配置）。

## T5.3 十二个高频快捷键

**只列真正每天用得上的**。Mac 上把 `Ctrl` 换成 `Cmd`（少数例外已标注）。

### 导航类（这四个能省最多时间）

| 快捷键 | 作用 | 什么时候用 |
|---|---|---|
| **`Ctrl+Shift+P`** | 命令面板 | **最重要的一个**：任何功能都能搜到，忘了快捷键就用它 |
| **`Ctrl+P`** | 按文件名快速打开 | 项目文件多了之后比在侧栏点快得多 |
| **`F12`** | 跳转到定义 | 看某个函数到底怎么实现的 |
| **`Shift+F12`** | 查找所有引用 | 改一个函数前先看谁在用它 |

### 编辑类

| 快捷键 | 作用 |
|---|---|
| **`F2`** | 重命名符号（**跨文件安全改名**，比查找替换可靠得多） |
| **`Ctrl+D`** | 选中下一个相同的词（连按可多选，然后一起改） |
| **`Alt+Click`** | 在多处放光标（多光标编辑） |
| **`Ctrl+/`** | 注释 / 取消注释当前行或选中块 |
| **`Alt+↑` / `Alt+↓`** | 整行上下移动 |

### 运行与调试

| 快捷键 | 作用 |
|---|---|
| **`Ctrl+` `** （反引号） | 打开 / 关闭集成终端 |
| **`F5`** | 启动调试；**`Ctrl+F5`** 不调试直接运行 |
| **`F9`** | 在当前行打断点 / 取消断点 |

配合第 20 章的调试：`F10` 步过（对应 pdb 的 `n`）、`F11` 步入（对应 `s`）、`Shift+F11` 步出（对应 `r`）。

### 三个"知道了能省很多时间"的操作

| 操作 | 怎么做 | 价值 |
|---|---|---|
| **在文件里跳到某个函数** | `Ctrl+Shift+O` 列出当前文件所有符号 | 长文件里找函数不用滚 |
| **全局搜索并替换** | `Ctrl+Shift+F` 搜索，侧栏里能直接批量替换 | 比逐文件改快 |
| **看两个文件的差异** | 侧栏选中一个文件 → 右键 `Select for Compare` → 选另一个 → `Compare with Selected` | 对比两版代码 |

> **不用背这张表。** 挑三个最有用的（`Ctrl+Shift+P`、`F12`、`F2`）先用起来，其余的等遇到"这个操作好麻烦"的时候回来查。
>
> **想看全部快捷键**：`Ctrl+K Ctrl+S` 打开快捷键列表，可以搜索、可以自定义。

## T5.4 `launch.json`：带参数运行与设置工作目录

学完第 24 章的 `argparse` 之后，你的程序需要参数才能跑。**直接按 `F5` 是不带参数的**，所以要配置一个"运行配置"。

### 怎么创建

`Ctrl+Shift+P` → `Debug: Add Configuration` → 选 `Python` → `Python File`。它会在项目根目录生成 `.vscode/launch.json`。

### 三个够用的配置

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      // ① 调试当前打开的文件（最常用）
      "name": "当前文件",
      "type": "debugpy",
      "request": "launch",
      "program": "${file}",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}"
    },
    {
      // ② 带命令行参数运行（配合第 24 章的 argparse）
      "name": "带参数：归档脚本",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/archive.py",
      "args": ["./downloads", "--by", "suffix", "--dry-run", "-v"],
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}"
    },
    {
      // ③ 以模块方式运行（配合第 18.14 节的 python -m，包内相对导入必须用这个）
      "name": "以模块运行 CLI",
      "type": "debugpy",
      "request": "launch",
      "module": "mypkg.cli",
      "console": "integratedTerminal",
      "cwd": "${workspaceFolder}"
    }
  ]
}
```

### 四个关键字段

| 字段 | 作用 | 注意 |
|---|---|---|
| `"type": "debugpy"` | 调试器类型 | **新版是 `debugpy`**；老教程里写 `"python"`，现在也还能用但已经不是推荐写法 |
| `"args"` | 命令行参数 | **一个参数一个字符串**：`["data.csv", "-v"]`，不要写成 `["data.csv -v"]` |
| **`"cwd"`** | **工作目录** | **这个字段解决第 16.15 节那个坑**：相对路径是相对于工作目录的，不设它可能找不到文件 |
| `"console": "integratedTerminal"` | 在集成终端里跑 | **必须设**，否则 `input()` 没法交互（回收第 6 章的"IDE 里 input 没反应"） |

### 配好之后怎么用

左侧调试面板顶部有个下拉框，选择配置名，按 `F5` 启动。**你可以配好几个配置**（不同参数组合），切换着用——比每次改代码里的常量方便得多。

> **一个实用技巧**：`args` 里可以放 `"${input:filename}"` 让它每次启动时弹窗问你要处理哪个文件。配置略复杂，需要时搜 `VS Code launch.json inputs`。

## T5.5 集成终端与虚拟环境

**集成终端**（`Ctrl+` `）就是一个嵌在编辑器里的命令行，工作目录默认是项目根目录。

### 虚拟环境的自动激活

设置了 T5.2 的第 ④ 项（`python.terminal.activateEnvironment`）之后，**新开的终端会自动激活项目的虚拟环境**——提示符前面出现 `(.venv)`。

**两个常见困惑**：

| 现象 | 原因 | 解法 |
|---|---|---|
| 改了设置但当前终端没激活 | **设置只对新开的终端生效** | 关掉当前终端（垃圾桶图标）重开一个 |
| 提示符没有 `(.venv)` 但其实激活了 | 某些终端主题会吃掉这个前缀 | 用第 19.5 节的可靠办法验证：`python -c "import sys; print(sys.executable)"` |

### 编辑器解释器 ≠ 终端解释器

这是个容易混淆的点，要分清两件事：

| | 影响什么 | 怎么设 |
|---|---|---|
| **编辑器选的解释器** | 智能提示、报红、按 F5 调试 | `Ctrl+Shift+P` → `Python: Select Interpreter` |
| **终端里的 python** | 你在终端手敲的命令 | 靠虚拟环境激活（自动或手动 `source`） |

**两者都要对**。第 1.6 节那个"pip 装了但 import 失败"的经典问题，就是这两者不一致造成的。

## T5.6 八个常见问题

| 现象 | 原因 | 解法 |
|---|---|---|
| **import 报红但代码能跑** | 编辑器选的解释器和实际运行的不是一个 | `Python: Select Interpreter` 选到 `.venv` 里的 |
| **import 自己写的模块报红** | Pylance 不知道你的项目根在哪 | 项目根目录建 `.vscode/settings.json`，加 `"python.analysis.extraPaths": ["."]` |
| **保存时格式化不生效** | ① 没装 Ruff 扩展 ② 没设 `defaultFormatter` ③ **文件有语法错误** | 按 T5.2 检查配置；先修语法错误（格式化器解析不了坏代码） |
| **格式化把我的代码改乱了** | 那是 Ruff 在按 PEP 8 规范化 | 这通常是对的（第 37 章讲规范）；确实不想让它管某一行，行尾加 `# fmt: skip` |
| **终端里 `python` 不是虚拟环境的** | 设置只对新终端生效 | 关掉终端重开；或手动激活（第 19.4 节） |
| **`input()` 在运行时没反应** | 输出面板不支持交互 | `launch.json` 里设 `"console": "integratedTerminal"` |
| **调试时报 `FileNotFoundError`** | 工作目录不对（第 16.15 节的坑） | `launch.json` 里设 `"cwd": "${workspaceFolder}"` |
| **Jupyter 用的不是虚拟环境的包** | Notebook 的内核和编辑器解释器是分开选的 | Notebook 右上角点内核名，选 `.venv` 那个 |

### 附：Windows 终端中文乱码

如果集成终端里中文显示成乱码，通常是终端编码不是 UTF-8。两个办法：

1. 临时：在终端里执行 `chcp 65001`
2. 长期：改用 Windows Terminal / PowerShell 7，它们默认 UTF-8

（这和第 16.10 节讲的文件编码是两件事——那个是文件内容的编码，这个是终端显示的编码。）

## T5.7 PyCharm 对应操作速查

用 PyCharm 的读者查这张表。**2025 年起 PyCharm 合并为单一产品**，核心功能（含 Jupyter）免费，所以下面的操作在免费版基本都有。

| 要做的事 | VS Code | PyCharm |
|---|---|---|
| 命令面板 / 搜任何功能 | `Ctrl+Shift+P` | `Shift` 连按两次（Search Everywhere） |
| 选解释器 | `Python: Select Interpreter` | Settings → Project → Python Interpreter |
| 跳转到定义 | `F12` | `Ctrl+B` 或 `Ctrl+Click` |
| 查找引用 | `Shift+F12` | `Alt+F7` |
| 重命名符号 | `F2` | `Shift+F6` |
| 格式化 | `Shift+Alt+F` | `Ctrl+Alt+L` |
| 注释切换 | `Ctrl+/` | `Ctrl+/` |
| 打断点 | `F9` | `Ctrl+F8` |
| 启动调试 | `F5` | `Shift+F9` |
| 步过 / 步入 | `F10` / `F11` | `F8` / `F7` |
| 打开终端 | `Ctrl+` ` | `Alt+F12` |
| 带参数运行 | `launch.json` 的 `args` | Run → Edit Configurations → Parameters |
| 设置工作目录 | `launch.json` 的 `cwd` | Run → Edit Configurations → Working directory |
| 配 Tab 转空格 | `editor.insertSpaces` | Settings → Editor → Code Style → Python |
| 用 Ruff | 装 Ruff 扩展 | 装 Ruff 插件，或配成 External Tool |

**PyCharm 的几个明显优势**（用它的话记得用上）：

- **重构更强**：提取函数、改签名、跨文件移动都比 VS Code 可靠
- **开箱即用**：不用装扩展配设置
- **数据库工具**：不过这个在 **Pro 订阅**里，免费版没有（VS Code 的 mssql 扩展是免费的）

| 要做的事 | 一句话 |
|---|---|
