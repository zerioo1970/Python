## 3.1 变量是标签，不是盒子

### 先说一个错误的比喻

几乎所有入门教材都这么说：**"变量是一个盒子，你把数据装进去。"**

这个比喻在 Python 里是**错的**，它会害你后面栽跟头。

Python 的真实模型是：**数据是独立存在的对象，变量是贴在对象上的标签。**

```text
错误的模型（盒子）：          正确的模型（标签）：

  a ┌─────┐                    a ──────┐
    │  10 │                            ├──→ 10
    └─────┘                    b ──────┘
```

`=` 这个符号做的事情不是"把数据装进盒子"，而是"**把标签贴到某个对象上**"。

### 用 id() 亲眼看一次

**示例 3-1　用 `id()` 看清"标签"这件事**

`id()` 这个内置函数能返回一个对象的**身份编号**（可以理解为它在内存里的门牌号）。

```python
a = [1, 2, 3]        # 这里先借用一下"列表"，它的完整用法第 9 章讲
b = a                # 关键：这不是"复制一份给 b"，而是"给同一个对象再贴一张标签"

print(id(a))         # => 140234567890123   （你运行时数字会不同，看的是两者是否相同）
print(id(b))         # => 140234567890123   和 a 完全一样
print(a is b)        # => True              is 判断的是"是不是同一个对象"
```

两个变量的 `id` 相同，说明它们贴在**同一个对象**上——不是两份数据，是一份数据、两张标签。

### 这个区别什么时候会害到你

对数字和字符串，你**感觉不到**区别：

```python
x = 10
y = x
y = 20               # 这不是"把那个 10 改成了 20"，而是把 y 撕下来贴到 20 上
print(x)             # => 10    x 毫发无损
```

但对列表这类**能被修改**的对象，区别是致命的：

```python
a = [1, 2, 3]
b = a
b.append(4)          # 通过 b 修改了那个对象本身（不是重新贴标签）
print(a)             # => [1, 2, 3, 4]     a 也变了！
```

**两段代码的区别在哪？**

| 操作 | 做了什么 | 影响 |
|---|---|---|
| `y = 20` | **重新贴标签**：把 y 撕下来贴到另一个对象上 | 只影响 y |
| `b.append(4)` | **修改对象本身**：那个列表变长了 | 所有贴在它上面的标签都看到变化 |

这就是为什么 `y = 20` 不影响 `x`，而 `b.append(4)` 会影响 `a`——**一个换了标签的位置，一个改了对象的内容。**

### 为什么 Python 要这样设计

**因为复制很贵。** 假设你有一个装了一百万条记录的列表，`b = a` 如果要复制一份，就得占用双倍内存、花时间搬数据。而实际情况是——**绝大多数时候你并不需要复制**，你只是想换个短点的名字来用它。

所以 Python 默认选了便宜的做法：只贴标签，不复制。**真需要复制的时候你可以明确要求**（第 13 章会讲怎么做）。

> **记住这条**：**`=` 是贴标签，不是复制。**
>
> **这条认知的回报会在这些地方陆续兑现**：
> - 第 9 章：`b = a` 之后改 `b`，`a` 也变了
> - 第 9 章：`[[0]*3]*3` 改一行，三行全变
> - 第 10 章：元组说是"不可变"，里面的列表却能改
> - 第 11 章：字典 `copy()` 之后，内层还是共享的
> - 第 13 章：把这些统一解释清楚，并给出解决办法
> - 第 14 章：把列表传进函数，函数改了它，外面也变
>
> **这六处怪现象，本质上是同一件事。** 现在只要记住"标签"这个模型就够了。

## 3.2 动态类型：变量不需要声明类型

**示例 3-2　同一个变量换成另一种类型**

```python
x = 1
print(x, type(x))        # => 1 <class 'int'>

x = "hello"              # 完全合法：同一个变量，现在贴到一个字符串上
print(x, type(x))        # => hello <class 'str'>

x = True
print(x, type(x))        # => True <class 'bool'>
```

**这叫动态类型**：变量本身没有类型，**类型属于它指向的那个对象**。你不需要（也不能）声明"这个变量是整数"。

**好处**：写起来快，不用为类型操心。

**代价**：错误从"编译时"推迟到了"运行时"。

```python
count = "10"             # 本来打算存数字，手一滑存成了字符串
total = count * 3        # 完全不报错！
print(total)             # => 101010    字符串重复了三次，不是 30
```

这段代码没有任何报错，但结果完全不是你想要的。C# / Java 的编译器会当场拦住你，Python 不会——**它会老老实实照字符串的规则执行**。

**这个代价怎么补救**：靠命名规范（`count_text` vs `count`）、靠类型注解（第 33 章）、靠测试（第 36 章）。这三样是 Python 用来换回一部分安全感的工具。

> **记住这条**：**变量没有类型，对象才有类型。** 灵活是有代价的，而这个代价要用规范和测试来补。

## 3.3 整数 int

### 任意精度：不会溢出

**示例 3-3　大得离谱的整数**

```python
print(2 ** 100)
```

```text
1267650600228229401496703205376
```

`2 ** 100` 是 2 的 100 次方，31 位数字。Python 算得出来，而且完全精确。

**这是 Python 一个很实在的优势**。C# 的 `int` 最大约 21 亿，超了会溢出（悄悄变成负数，或者抛异常）；Python 的整数**没有上限**，需要多少位就用多少位，只受内存限制。

**什么时候用得上**：算阶乘、算大数幂、处理超长的 ID 或订单号。在别的语言里这些都要专门找大数库，Python 里直接算。

### 三种写法上的便利

**示例 3-4　下划线分隔与进制表示**

```python
# 下划线分隔：只为了人好读，Python 完全忽略它
print(1_000_000)         # => 1000000
print(1_0_0)             # => 100      （分隔位置随意，但别这么写）

# 三种进制的字面量写法
print(0b1010)            # => 10       0b 开头是二进制
print(0o17)              # => 15       0o 开头是八进制
print(0xff)              # => 255      0x 开头是十六进制

# 反过来：把十进制转成各进制的字符串表示
print(bin(10))           # => 0b1010
print(hex(255))          # => 0xff
print(oct(15))           # => 0o17
```

**下划线的实际价值**：`1000000` 你得数零，`1_000_000` 一眼就知道是一百万。写大数字时用它，能减少数错位的错误。

**进制的实际用途**：读硬件寄存器、处理颜色值（`0xFF0000` 是红色）、看文件权限（`0o755`）。日常业务开发用得少，但**看到 `0x` 开头别慌，那就是十六进制**。

## 3.4 浮点数 float：本章最重要的一节

### 现象：0.1 + 0.2 不等于 0.3

**示例 3-5　浮点数的精度问题**

```python
print(0.1 + 0.2)              # => 0.30000000000000004
print(0.1 + 0.1 + 0.1)        # => 0.30000000000000004
print(1.1 + 2.2)              # => 3.3000000000000003
print(0.1 + 0.2 == 0.3)       # => False
```

最后一行尤其危险：**你写的判断条件，结果和你想的相反。**

### 为什么：一个不用数学的解释

先看一个你早就接受了的事实：

**示例 3-6　十进制也有写不出来的数**

```python
print(1 / 3)             # => 0.3333333333333333
print(2 / 3)             # => 0.6666666666666666
```

三分之一在十进制里写不完——`0.333...` 无限循环。你只能截断成有限位，于是 `1/3 + 1/3 + 1/3` 用截断后的值算，就不会精确等于 1。

**计算机用的是二进制，而在二进制里，`0.1` 恰好就是那个"写不完的数"。**

十进制写不出 1/3，二进制写不出 0.1——**同一类问题，只是换了个进制。**

想看看 `0.1` 在计算机里的真面目吗：

```python
print(format(0.1, ".20f"))    # 显示 20 位小数（format 的用法第 5 章讲，这里只为看真相）
```

```text
0.10000000000000000555
```

**计算机存的根本不是 `0.1`，而是一个非常接近 `0.1` 的数。** 你写 `0.1`，它存 `0.10000000000000000555`。两个这样的近似值相加，误差就露出来了。

**这不是 Python 的问题**。这是 IEEE 754 浮点标准，所有主流语言（C、C++、Java、C#、JavaScript、Go）都是这个行为。JavaScript 里 `0.1 + 0.2` 同样得 `0.30000000000000004`。

### 这件事什么时候会真的害到你

**示例 3-7　真实的坑：金额计算**

```python
# 场景一：单价 × 数量
price = 19.9
count = 3
print(price * count)              # => 59.699999999999996
```

> **回收第 1 章的一个细节**：第 1 章示例 1-6 我特意用的是 `19.9 * 2`（得 `39.8`，很干净）。当时如果写 `19.9 * 3`，你在第一天就会看到这串 `59.699999999999996` 而完全不知道发生了什么。现在你知道了。

```python
# 场景二：元转分（这是真实系统里出过事故的写法）
print(4.35 * 100)                 # => 434.99999999999994
print(19.99 * 100)                # => 1998.9999999999998
```

第二个场景是**真实事故**的来源。很多支付系统内部用"分"作单位，需要把元转成分。如果这么写：

```python
fen = int(4.35 * 100)             # int() 是截断，不是四舍五入！
print(fen)                        # => 434        少了 1 分钱
```

`4.35` 元应该是 `435` 分，结果算出 `434`。**一笔交易少一分钱，一百万笔就是一万块。** 这种 bug 极其隐蔽——大部分数字都是对的，只有某些特定数值才出错。

### 三个应对办法

**办法一：显示时用 `round` 截断（只解决显示问题）**

**示例 3-8　`round` 保留指定位数**

```python
print(round(3.14159, 2))          # => 3.14
print(round(0.1 + 0.2, 2))        # => 0.3        看起来正常了
print(round(19.9 * 3, 2))         # => 59.7
```

**注意**：这只是把显示结果修圆了，**底层的误差还在**。用来打印报表可以，用来做后续计算和比较不行。

**办法二：比较时不用 `==`（第 4 章会详讲）**

```python
a = 0.1 + 0.2
print(a == 0.3)                   # => False    不要这样比
print(round(a, 10) == 0.3)        # => True     先修圆再比
```

第 4 章会介绍更规范的做法 `math.isclose()`。

**办法三：算钱不用浮点数（正确做法）**

两个方案：

```python
# 方案 A：用整数存"分"，只在显示时除以 100
price_fen = 1990                  # 19.90 元存成 1990 分
count = 3
total_fen = price_fen * count     # 整数运算，绝对精确
print(total_fen)                  # => 5970
print(total_fen / 100)            # => 59.7      只在最后显示时转成元
```

方案 B 是用标准库的 `decimal` 模块，它专门为精确的十进制运算而生（详见**工具箱 T2**）。

> **记住这条**：**浮点数不适合算钱。** 涉及金额，要么用整数存最小单位（分），要么用 `decimal`。
>
> **判断标准**：这个数字**要不要和别人对账**？要对账就别用 `float`。科学计算、统计指标、图表坐标用 `float` 完全没问题（那些场景本来就允许微小误差）。

### round 的两个意外行为

**示例 3-9　`round` 不是你想的"四舍五入"**

```python
print(round(2.5))                 # => 2        不是 3！
print(round(3.5))                 # => 4
print(round(0.5))                 # => 0        不是 1！
print(round(1.5))                 # => 2
```

规律看出来了吗？**`.5` 的时候，它朝着"偶数"那边靠。**

这叫**银行家舍入**（round half to even）。为什么这么设计：如果 `.5` 一律进位，大量数据累加会**系统性偏高**；朝偶数靠能让偏差正负相抵。这在统计和金融领域是标准做法。

**第二个意外**：

```python
print(round(2.675, 2))            # => 2.67     不是 2.68！
```

这次不是银行家舍入的问题，而是 3.4 开头讲的精度问题——`2.675` 存进去的实际是 `2.67499999...`，比 `2.675` 略小，所以往下舍。

**需要"标准的四舍五入"怎么办**：用 `decimal` 模块（工具箱 T2），它可以指定舍入规则。

> **记住这条**：**`round()` 在 `.5` 时朝偶数靠，而且会受浮点精度影响。** 需要严格四舍五入的场合（尤其算钱），用 `decimal`。

### 科学计数法

```python
print(1e3)               # => 1000.0     e3 表示 ×10³
print(1.5e-3)            # => 0.0015     e-3 表示 ×10⁻³
```

注意 `1e3` 的结果是 `1000.0`（**浮点数**）而不是 `1000`——**只要写了 `e`，得到的就是 float。**

## 3.5 布尔值 bool

### 只有两个值，首字母必须大写

**示例 3-10　`True` 和 `true`**

```python
print(True, False)
print(type(True))
```

```text
True False
<class 'bool'>
```

写成小写会怎样：

```python
print(true)
```

```text
NameError: name 'true' is not defined. Did you mean: 'True'?
```

**从 JavaScript、Java、C# 转过来的人几乎必踩这个坑**，那些语言里是全小写的。Python 3.12 会直接提示你 `Did you mean: 'True'?`。

同理还有 `None`（不是 `null`、不是 `none`）。

### 布尔值其实是整数

**示例 3-11　`True` 就是 1**

```python
print(True + 1)                   # => 2
print(True * 3)                   # => 3
print(int(True), int(False))      # => 1 0
print(True == 1, False == 0)      # => True True
print(isinstance(True, int))      # => True     bool 是 int 的子类
```

`bool` 在 Python 里是 `int` 的**子类**，`True` 的数值就是 `1`，`False` 就是 `0`。

**这个特性有个实用价值**（第 8 章会用到）：统计"有多少个满足条件"时，可以直接把布尔值加起来——`True` 算 1，`False` 算 0。

**也有个坑**：`1 == True` 是 `True`，所以如果你需要严格区分"数字 1"和"布尔真"，`==` 判断不出来，得用 `isinstance` 或 `is`。这种情况少见，但读别人代码时可能遇到。

> **记住这条**：**`True` / `False` / `None` 三个词首字母大写**；`True` 的数值等于 1。

## 3.6 None：表示"没有值"

**示例 3-12　`None` 长什么样**

```python
print(None)
print(type(None))
```

```text
None
<class 'NoneType'>
```

`None` 表示"**这里没有值**"。它不是 0，不是空字符串，不是 `False`——它是一个独立的、专门表示"空"的对象。

**四个"看起来都是空"的东西，其实完全不同**：

| 值 | 含义 | 例子 |
|---|---|---|
| `0` | 数量是零 | 库存 0 件（**确实清点过了**） |
| `""` | 一段空文本 | 备注填了但内容为空 |
| `False` | 逻辑上的假 | 审核未通过 |
| `None` | **根本没有值** | 库存还没盘点（**不知道是多少**） |

**这个区分在真实业务里非常重要**。"库存 0 件"和"库存未知"是两回事：前者不能卖，后者要先去盘点。用 `0` 表示"未知"会导致严重的判断错误。

**`None` 最常见的三个来源**（现在只需知道，后面各章会遇到）：

1. **函数没有 `return`**，调用它就得到 `None`（第 14 章）
2. **字典取值取不到**，用 `.get()` 会返回 `None`（第 11 章）
3. **变量初始化**，先声明"还没有值"，后面再填

**它带来的最常见报错**（第 2 章提过，这里正式认识）：

```python
name = None
print(name.upper())
```

```text
AttributeError: 'NoneType' object has no attribute 'upper'
```

**看到 `'NoneType' object has no attribute ...`，就是同一个原因：你以为某个变量有值，实际它是 `None`。** 这个报错在真实项目里出现的频率极高，认识它能省很多时间。

> **记住这条**：**`None` 表示"没有值"，和 `0`、`""`、`False` 都不一样。** 判断它要用 `is None`（第 4 章讲为什么不用 `==`）。

## 3.7 查看类型：type 与 isinstance

**示例 3-13　两个查类型的工具**

```python
print(type(42))          # => <class 'int'>
print(type(3.14))        # => <class 'float'>
print(type("hi"))        # => <class 'str'>
print(type(True))        # => <class 'bool'>
print(type(None))        # => <class 'NoneType'>
```

`type()` 告诉你"它是什么"，`isinstance()` 回答"它是不是某个类型"：

```python
print(isinstance(42, int))        # => True
print(isinstance(42, float))      # => False    42 是整数，不是浮点数
print(isinstance(True, int))      # => True     因为 bool 是 int 的子类（见 3.5）
```

**日常用哪个**：**用 `isinstance`**。原因是它认子类关系——比如 `isinstance(True, int)` 是 `True`，而 `type(True) == int` 是 `False`。在需要判断类型的场合，通常你想要的是前者的行为。

**`type()` 最常见的用途其实是调试**：程序行为奇怪时，打印出来看看变量到底是什么类型。第 6 章你会用它抓一个非常典型的错误。

## 3.8 类型转换：显式

**示例 3-14　四种转换**

```python
print(int("42"))         # => 42        字符串 → 整数
print(float("3.5"))      # => 3.5       字符串 → 浮点数
print(str(42))           # => 42        数字 → 字符串（注意打印出来看不出区别）
print(bool(1))           # => True      任何东西 → 布尔值
```

`str(42)` 打印出来是 `42`，和数字 `42` 看着一样。用 `type()` 才能看出区别：

```python
print(type(str(42)))     # => <class 'str'>
```

### 转换失败的两种情况

**示例 3-15　`int()` 什么时候会失败**

```python
print(int("42"))         # => 42        纯数字字符串可以
```

```python
int("abc")
```

```text
ValueError: invalid literal for int() with base 10: 'abc'
```

这个符合预期。但下面这个很反直觉：

```python
int("3.5")
```

```text
ValueError: invalid literal for int() with base 10: '3.5'
```

**`"3.5"` 明明是个数字，为什么 `int()` 不认？** 因为 `int()` 只接受**整数形式**的字符串，它不处理小数点。

要转就分两步：

```python
print(int(float("3.5")))       # => 3     先转成浮点数 3.5，再截断成 3
print(round(float("3.5")))     # => 4     想四舍五入用 round
```

**这个坑在哪里最常遇到**：处理用户输入和读 Excel 导出的数据。Excel 里的整数导出成 CSV 常常带着 `.0`——`"5.0"`、`"100.0"`，直接 `int()` 全部报错。

> **记住这条**：**`int("3.5")` 会报错，要写 `int(float("3.5"))`。**
>
> 更根本的解决办法是用 `try` 把转换包起来（第 15 章）——那时候你会回来把这段重写一遍，代码会更短也更可靠。

### int() 是截断，不是四舍五入

**示例 3-16　`int()` 直接砍掉小数**

```python
print(int(3.9))          # => 3         不是 4
print(int(3.1))          # => 3
print(int(-3.9))         # => -3        朝 0 的方向砍，不是 -4
```

**三个"取整"函数的区别**（第 4 章还会遇到 `//`）：

| 写法 | 行为 | `3.9` | `-3.9` |
|---|---|---|---|
| `int(x)` | 直接砍掉小数（朝 0 方向） | `3` | `-3` |
| `round(x)` | 四舍五入（`.5` 朝偶数） | `4` | `-4` |
| `x // 1` | 向下取整（朝更小方向，第 4 章） | `3.0` | `-4.0` |

**要四舍五入就用 `round`，不要用 `int`。** 这是一个非常常见的错误来源。

### 什么会被当成"假"

**示例 3-17　`bool()` 的转换规则**

```python
print(bool(0))           # => False
print(bool(0.0))         # => False
print(bool(""))          # => False     空字符串
print(bool(None))        # => False
```

以上四个都是"假"。但下面两个是**真**：

```python
print(bool("0"))         # => True      ！这是字符串 "0"，不是数字 0
print(bool(" "))         # => True      ！一个空格也是内容
```

**`"0"` 和 `" "` 都是"假"的直觉是错的**——它们是**非空字符串**，而任何非空字符串都为真。

**这个坑的真实场景**：从文件或表单读到的数据都是字符串。用户填了 `0`，你拿到的是 `"0"`，判断"用户填没填"时如果直接用真假判断，就会把 `"0"` 当成"填了"（这是对的），但如果你想判断"数量是不是零"，就必须先转成数字。第 7 章会专门讲真假判断规则。

## 3.9 类型转换：隐式

**示例 3-18　数字和文字能不能相加**

整数和浮点数混算，Python 会**自动**把整数转成浮点数：

```python
print(1 + 2.0)                    # => 3.0
print(type(1 + 2.0))              # => <class 'float'>
```

结果是 `3.0` 而不是 `3`——**只要参与运算的有一个是浮点数，结果就是浮点数。**

但字符串和数字**不会**自动转换：

```python
print("1" + 1)
```

```text
TypeError: can only concatenate str (not "int") to str
```

报错信息很直白："字符串只能和字符串拼接"。必须显式转换：

```python
print("1" + str(1))               # => 11     两个字符串拼接
print(int("1") + 1)               # => 2      两个数字相加
```

**这个严格性是好事**。JavaScript 里 `"1" + 1` 得到 `"11"`、`"1" - 1` 得到 `0`，规则复杂且反直觉，是无数 bug 的来源。Python 直接拒绝猜测你的意图，让你自己说清楚。

> **记住这条**：**数字之间会自动转换，字符串和数字之间不会。** Python 不猜你的意图，这能避免大量隐蔽错误。

## 3.10 多变量赋值与 del

**示例 3-19　一行赋好几个变量**

```python
x, y = 1, 2              # 一次给两个变量赋值
print(x, y)              # => 1 2

m = n = 0                # 链式赋值：m 和 n 都指向 0
print(m, n)              # => 0 0
```

第一种写法（`x, y = 1, 2`）用得很多，第 10 章会讲清它的原理，还会看到它的一个妙用：**一行交换两个变量**。

第二种写法（`m = n = 0`）**对数字和字符串没问题，但对列表这类可变对象有坑**——两个名字会指向同一个对象，改一个另一个也变（原因就是 3.1 讲的标签模型）。第 13 章会详细说。

**示例 3-20　`del` 删掉变量**

```python
temp = 5
print(temp)              # => 5

del temp                 # 把这张标签撕掉
print(temp)              # ❌ NameError: name 'temp' is not defined
```

`del` 删的是**标签**，不是对象。如果那个对象还有别的标签贴着，它依然存在。

**`del` 用得不多**，主要在两个场合：明确释放一个占内存很大的对象、或者删掉字典里的某一项（第 11 章）。

## 3.11 复数 complex（★ 用到再查）

Python 内置支持复数，用 `j` 表示虚部：

**示例 3-21　复数一瞥**

```python
c = 3 + 4j
print(c)                 # => (3+4j)
print(type(c))           # => <class 'complex'>
print(c.real, c.imag)    # => 3.0 4.0      实部和虚部
print(abs(c))            # => 5.0          求模（勾三股四弦五）
```

**什么时候用**：信号处理、电路分析、某些科学计算。**日常开发几乎用不到**，知道 Python 有这个类型、看到 `j` 结尾的数字不惊讶就够了。

<details>
<summary><b>给有 C# / Java / SQL 经验的读者</b></summary>

| 你熟悉的 | Python |
|---|---|
| `int x = 5;` 声明类型 | `x = 5`，**不声明也不能声明**（注解不是声明，见第 33 章） |
| `var x = 5;`（仍是静态类型，编译期定死） | Python 的动态类型是**运行期**的，同一变量可以换类型 |
| `int` 有上下限，溢出会出问题 | **任意精度**，`2 ** 100` 直接算 |
| `decimal` 是语言内置类型 | 要 `from decimal import Decimal`（工具箱 T2） |
| `null` | **`None`**（首字母大写） |
| `true` / `false` | **`True`** / **`False`**（首字母大写） |
| `int.Parse(s)` / `Integer.parseInt(s)` | `int(s)` |
| `int.TryParse(s, out n)` | 没有对应物——用 `try` + `int()`（第 15 章） |
| `x is int`（C# 类型判断） | `isinstance(x, int)`；注意 Python 的 `is` 是**身份比较**，完全不同（第 4 章） |
| `(int)3.9` 强制转换 | `int(3.9)`，同样是截断 |
| `Math.Round(2.5)` 得 3（默认远离零） | `round(2.5)` 得 **2**（银行家舍入，见 3.4） |

**三个需要特别注意的**：

1. **`decimal` 不是内置的。** C# 里算钱用 `decimal` 是本能，Python 里 `float` 是默认的浮点类型，**你必须主动选择 `Decimal`**，否则就落进 3.4 那个坑。
2. **`is` 不是类型判断。** C# 的 `x is int` 判断类型，Python 的 `x is y` 判断"是不是同一个对象"。判断类型用 `isinstance`。
3. **SQL 背景的读者注意 `None` 的行为**：SQL 里 `NULL = NULL` 结果是 `NULL`（未知），而 Python 里 `None == None` 是 `True`。不过规范写法仍然是 `x is None`（理由见第 4.11 节）。

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| `true` / `false` / `none` | `NameError: Did you mean: 'True'?` | `True` / `False` / `None` | 首字母必须大写 |
| `int("3.5")` | `ValueError: invalid literal for int()` | `int(float("3.5"))` | `int()` 不认小数点 |
| `int(3.9)` 期望得 4 | 得到 `3` | 用 `round(3.9)` | `int()` 是截断 |
| `"1" + 1` | `TypeError: can only concatenate str` | `int("1") + 1` 或 `"1" + str(1)` | 字符串和数字不自动转换 |
| `0.1 + 0.2 == 0.3` | 结果是 `False` | 先 `round`，或用 `math.isclose`（第 4 章） | 二进制表示不了 0.1 |
| 用 `float` 算金额 | 账目差几分钱 | 用整数存"分"，或用 `decimal`（T2） | 浮点精度 |
| `int(4.35 * 100)` | 得 `434` 而不是 `435` | `round(4.35 * 100)` 或全程用整数 | 精度 + 截断双重问题 |
| 以为 `round(2.5)` 得 3 | 得 `2` | 需要严格四舍五入用 `decimal` | 银行家舍入 |
| 用 `0` 表示"未知" | 把"未盘点"当成"没库存" | 用 `None` 表示未知 | 语义不同 |
| 变量是 `None` 却调用方法 | `'NoneType' object has no attribute ...` | 检查那个变量为什么是 `None` | 函数忘了 return / 取值取空 |
| 以为 `bool("0")` 是 False | 它是 `True` | 先转成数字再判断 | 非空字符串恒为真 |
| `b = a` 以为复制了数据 | 改 `b` 影响 `a` | 见第 13 章拷贝方法 | `=` 是贴标签 |
| 变量没赋值就使用 | `NameError` | 先赋初值 | Python 不自动初始化 |
| `x = 1e3` 以为得整数 | 得 `1000.0` | 要整数写 `1000` 或 `int(1e3)` | 有 `e` 就是浮点数 |

## 本章小结

- **`=` 是贴标签，不是复制**——这是全书最重要的一个认知，后面六处"怪现象"都源于它
- 变量**没有类型**，类型属于对象；灵活的代价是错误推迟到运行时
- `int` **任意精度**，不会溢出；支持 `1_000_000` 和 `0b` / `0o` / `0x` 写法
- `float` **有精度问题**：`0.1 + 0.2 != 0.3`，原因和"十进制写不出 1/3"是同一类
- **算钱不用 `float`**：用整数存"分"，或用 `decimal`
- `round()` 在 `.5` 时**朝偶数靠**（银行家舍入），且受浮点精度影响
- `True` / `False` / `None` **首字母大写**；`True` 的数值就是 1
- **`None` 表示"没有值"**，和 `0`、`""`、`False` 语义完全不同
- `int("3.5")` 会报错；`int()` 是**截断**不是四舍五入
- 数字之间自动转换，**字符串和数字之间不会**

### API 速查

| 写法 | 作用 | 注意 |
|---|---|---|
| `id(x)` | 对象的身份编号 | 用来判断是否同一个对象 |
| `x is y` | 是不是同一个对象 | 与 `==`（值相等）不同，第 4 章详讲 |
| `type(x)` | 查看类型 | 主要用于调试 |
| `isinstance(x, int)` | 是不是某类型 | 日常判断用这个 |
| `int(x)` | 转整数 | **截断**；不认 `"3.5"` |
| `float(x)` | 转浮点数 | —— |
| `str(x)` | 转字符串 | —— |
| `bool(x)` | 转布尔 | `"0"` 和 `" "` 都是 `True` |
| `round(x, n)` | 保留 n 位小数 | `.5` 朝偶数靠 |
| `bin/hex/oct(x)` | 转进制字符串 | —— |
| `abs(x)` | 绝对值 | 对复数是求模 |
| `del x` | 删掉变量名 | 删标签，不删对象 |

### 四种基本类型

| 类型 | 例子 | 关键特点 |
|---|---|---|
| `int` | `42`、`0xff`、`1_000` | 任意精度，不溢出 |
| `float` | `3.14`、`1e3` | **有精度问题**，别用来算钱 |
| `bool` | `True`、`False` | 首字母大写；本质是 `int` |
| `NoneType` | `None` | 表示"没有值"，只有这一个值 |
