## 开篇：让程序有判断力

第 6 章结尾那个 BMI 程序有个明显的缺憾：它算出 `22.9`，然后就完了——**它不会告诉你这算正常还是超重**。

因为到目前为止，你的代码都是"一条道跑到黑"：从第一行执行到最后一行，不管数据是什么。这一章加上 `if`，程序才算真正有了判断力。

`if` 的语法只有三行就能讲完。**本章真正的难点在两个地方**：

1. **把中文规则准确翻译成条件表达式**——"满 100 包邮"里的"满"是 `>=` 还是 `>`？
2. **多个条件的先后顺序**——顺序错了，语法完全正确、程序不报错、结果全错

这两件事都是靠踩坑才能学会的，所以本章的示例会给出大量"边界值验证"。

顺便还会解决第 3 章留下的一个悬念：为什么 `0`、`""`、`None` 都被当成"假"，而 `"0"` 是"真"。

## 7.1 第一个 `if`

**示例 7-1　条件成立才执行**

```python
score = 75

if score >= 60:
    print("及格")
```

```text
及格
```

**语法三要素，一个都不能少**：

| 要素 | 说明 |
|---|---|
| **条件** | `score >= 60`，一个能算出真假的表达式（第 4 章的比较运算符） |
| **冒号** | 行尾的 `:`，表示"下面有一个代码块" |
| **缩进块** | 下一行缩进 4 个空格，这些语句属于这个 `if`（第 2.2 节） |

**关于冒号，有一条规律现在就可以记住**：**凡是以冒号结尾的行，下一行必须缩进。** 这条规律对 `if`、`for`、`while`、`def`、`class`、`try`、`with` 全都成立——冒号是"下面有一个块"的统一信号。你后面学到那些语句时，就不需要重新记了。

---

## 7.2 条件不成立时，整块被跳过

**示例 7-2　缩进决定了什么会被跳过**

```python
score = 45

if score >= 60:
    print("及格")               # 缩进在块内 → 条件不成立就不执行

print("这行在块外，总是执行")      # 没有缩进 → 不属于 if，总是执行
```

```text
这行在块外，总是执行
```

**"及格"没有输出，但后面那行输出了。**

这就是缩进的作用——它决定了"哪些语句受这个条件控制"。**缩进错一格，逻辑就完全变了**：

```python
# ❌ 这样写，第二行也变成了 if 的一部分，条件不成立时两行都不执行
if score >= 60:
    print("及格")
    print("这行本来应该总是执行")
```

第 2 章说过"缩进是语法不是排版"，这里你看到了具体后果。

## 7.3 `if` / `else`：二选一

**示例 7-3　条件不成立时做另一件事**

```python
score = 45

if score >= 60:
    print("及格")
else:
    print("不及格")
```

```text
不及格
```

**`else` 后面直接跟冒号，不带条件**——它的含义就是"上面那个条件不成立的所有情况"。

**一个常见误解**：以为 `else` 也能写条件（`else score < 60:`）。那是 `elif`，下一节讲。

---

## 7.4 `if` / `elif` / `else`：多分支

**示例 7-4　判成绩等级**

```python
score = 85

if score >= 90:
    print("优秀")
elif score >= 80:
    print("良好")
elif score >= 60:
    print("及格")
else:
    print("不及格")
```

```text
良好
```

**`elif` 是 `else if` 的缩写**，可以连续写任意多个。执行规则是：

> **从上往下逐个判断，第一个成立的执行完，整个结构就结束了**——后面的分支一律不再检查。

用四个代表值各跑一次，四个分支都能进到：

```text
95 优秀
85 良好
70 及格
30 不及格
```

**注意第二个条件只写了 `score >= 80`，没写 `80 <= score < 90`。** 为什么不用写 `< 90`？因为能走到这一行，就说明上面的 `score >= 90` 已经不成立了——`< 90` 是**自动保证**的。

**这是 `elif` 链最大的好处**：条件之间自带"排除前面所有情况"的语义，能省掉一大堆重复判断。

---

## 7.5 `elif` 的顺序就是逻辑本身

**示例 7-5　顺序写反的后果**（样板示例）

先看一段"看起来很对"的代码：

```python
score = 90

# ❌ 错误：把最宽松的条件放在了最前面
if score >= 60:
    print("及格")
elif score >= 80:
    print("良好")
elif score >= 90:
    print("优秀")
```

```text
及格
```

**90 分被判成了"及格"。**

原因就是 7.4 那条规则：`90 >= 60` 成立，所以打印"及格"，**下面两个 `elif` 根本不会被检查**。

正确写法是**从最严格到最宽松**排列：

```python
score = 90

# ✅ 正确：从高到低排，先被最严格的条件拦住
if score >= 90:
    print("优秀")
elif score >= 80:
    print("良好")
elif score >= 60:
    print("及格")
else:
    print("不及格")
```

```text
优秀
```

**这类 bug 是本章最危险的**，因为：

- 语法完全正确
- 程序不报错
- 大部分数据可能还是对的（`70` 分两种写法结果都是"及格"）
- 只有特定数据才暴露

> **记住这条**：写 `elif` 链之前先问自己一句——**我的条件是从严到宽排的吗？**
>
> **自查方法**：**给每个分支挑一个代表值，逐个试一遍。** 上面这段就该用 `95 / 85 / 70 / 30` 各跑一次，四个分支都进到了才算验证过。这个习惯能挡掉绝大多数多分支的错误。

## 7.6 条件里可以放什么

条件不一定是比较表达式，**任何能算出值的东西都可以**——Python 会把它当成真或假来用。

**示例 7-6　条件里放一个光秃秃的变量**

```python
name = "小明"

if name:                    # 没有比较运算符，直接放一个变量
    print(f"你好，{name}")
```

```text
你好，小明
```

`if name:` 的含义是"**如果 name 有内容**"。这个写法非常常见，因为它比 `if name != "":` 短而且更通用。

**但它到底是怎么判断真假的？** 下一节回答。

---

## 7.7 真假规则：什么算"假"

**示例 7-7　逐个测一遍**

```python
print(bool(0))          # => False
print(bool(0.0))        # => False
print(bool(""))         # => False
print(bool(None))       # => False
```

**这四个都是"假"。** 规律是：**零、空、无，都是假。**

（第 9 章起你还会遇到空列表 `[]`、空字典 `{}`，它们同样是假。）

**除此之外的一切都是真**：

```python
print(bool(-1))         # => True     负数也是真（不是 0 就行）
print(bool(0.1))        # => True
print(bool("abc"))      # => True
```

### 三个反直觉的"真"

**示例 7-8　这三个都是真**

```python
print(bool("0"))         # => True    字符串 "0"，不是数字 0
print(bool(" "))         # => True    一个空格
print(bool("False"))     # => True    字符串 "False"
```

**它们都是非空字符串，而任何非空字符串都是真。** 引号里装的是什么内容，Python 完全不管。

**这个坑的真实场景**：从文件、表单、命令行读到的数据**全都是字符串**（回收第 6.7 节）。用户输入了 `0`，你拿到的是 `"0"`，直接判断真假就会得到"真"。

> **记住这条**：**零、空、无为假，其余为真**；但要注意 **`"0"` 是字符串，它是真的**。

### 为什么 Python 要设计这套规则

因为它让"有没有内容"这个判断变得非常简洁：

```python
name = input("姓名：").strip()

if name:                        # ✅ 地道：如果用户填了名字
    print(f"你好，{name}")
```

对比啰嗦的写法：

```python
if name != "" and name is not None:      # 功能一样，但长得多
    print(f"你好，{name}")
```

**"判断有没有内容"用 `if x:`**，这是 Python 的惯用写法。

## 7.8 `if x:` 还是 `if x == 0:`

上一节的便利有个代价，**这是本章第二个必须讲透的坑**。

**示例 7-9　`if count:` 把 0 当成了"没有"**

场景：用户填写库存数量，你要判断"填没填"。

```python
count = 0                    # 用户明确填了 0（真的没库存）

# ❌ 错误：用真假判断"填没填"
if count:
    print("有库存")
else:
    print("没填库存")        # 走到了这里——但用户其实是填了的！
```

```text
没填库存
```

**程序把"填了 0"和"没填"混为一谈了。** 这两件事在业务上完全不同：

| 值 | 业务含义 | 该怎么处理 |
|---|---|---|
| `0` | **确实清点过了，一件都没有** | 不能卖，但数据是可靠的 |
| `None` | **还没盘点，不知道多少** | 要先去盘点（回收第 3.6 节） |

**正确做法是显式比较**：

```python
# ✅ 正确：明确区分三种情况
count = 0

if count is None:
    print("还没盘点")
elif count == 0:
    print("库存确实是 0")
else:
    print(f"有 {count} 件库存")
```

```text
库存确实是 0
```

> **记住这条**：**判断"有没有内容"用 `if x:`；但只要 `0` 或空字符串是"合法的有效值"，就必须用显式比较。**
>
> **判断标准很简单**：问自己一句——**"`0` 在我这个场景里是合法数据吗？"** 是（数量、余额、次数、分数）→ 用 `== 0` 或 `is None`；不是（名字、地址、备注）→ 用 `if x:` 就行。
>
> **这个坑还有个变体**，第 4.14 节见过：`count or 10` 这种取默认值的写法，也会把 `0` 当成"没有"。同一个原因。

## 7.9 三元表达式：一行搞定二选一

**示例 7-10　把简单的 if/else 压成一行**

```python
score = 75

result = "及格" if score >= 60 else "不及格"
print(result)                    # => 及格
```

**读法是从中间开始读**：先看 `if score >= 60`（条件），成立取前面的值，不成立取后面的值。

```text
"及格"     if    score >= 60     else    "不及格"
  ↑              ↑                          ↑
条件成立时取这个   ② 先读这里              条件不成立时取这个
```

**什么时候用**：**简单的二选一赋值**。像上面这样一行说清，比四行 `if/else` 更清爽。

### 什么时候别用

**示例 7-11　嵌套两层就该改回 if**

```python
score = 75

# ❌ 能跑，但已经很难读了
r = "优秀" if score >= 90 else ("良好" if score >= 80 else ("及格" if score >= 60 else "不及格"))
print(r)                         # => 及格
```

```python
# ✅ 改回 if/elif，行数多了但一眼看懂
if score >= 90:
    r = "优秀"
elif score >= 80:
    r = "良好"
elif score >= 60:
    r = "及格"
else:
    r = "不及格"
print(r)                         # => 及格
```

> **记住这条**：**三元表达式只用于"一层的二选一"。** 需要嵌套就说明分支多了，老实用 `if/elif`——**代码的目的是让人读懂，不是让行数变少。**

## 7.10 区间判断与边界值

### 链式比较

**示例 7-12　判断一个数在不在区间内**

回收第 4.7 节的链式比较，这次用在真实场景：

```python
score = 85

print(0 <= score <= 100)                    # => True     链式写法
print(score >= 0 and score <= 100)          # => True     等价但啰嗦
print(0 <= 150 <= 100)                      # => False
```

**判断区间一律用链式比较**，它更短、更接近数学写法。

### 边界值必须逐个确认

**示例 7-13　`>` 和 `>=` 差一个数**

```python
print(90 >= 90)          # => True     90 分算优秀
print(90 > 90)           # => False    90 分不算优秀
```

**就差一个等号，业务含义完全不同。** 这类错误有个名字叫 **off-by-one**（差一错误），是最常见的逻辑 bug。

**中文规则和运算符的对应关系，容易搞混的都在这里**：

| 中文说法 | 运算符 | 含 90 吗 |
|---|---|---|
| 90 分**以上**、**不低于** 90、**满** 90 | `>= 90` | ✅ 含 |
| **超过** 90、**高于** 90、**大于** 90 | `> 90` | ❌ 不含 |
| 90 分**以下**、**不超过** 90 | `<= 90` | ✅ 含 |
| **低于** 90、**不足** 90 | `< 90` | ❌ 不含 |

**"满 100 包邮"是 `>= 100`；"超过 30 公斤不接单"是 `> 30`。** 遇到规则不明确的（"90 分以上"到底含不含 90），**去问清楚，不要猜**——这是业务问题不是技术问题。

## 7.11 与 `None`、浮点数比较

这两个是前面章节埋的伏笔，这里给出实际写法。

**示例 7-14　判断 `None` 用 `is`**

```python
x = None

print(x is None)             # => True     ✅ 规范写法
print(x is not None)         # => False    ✅ 否定形式
```

**为什么用 `is` 而不是 `==`**（回收第 4.11 节）：`None` 在整个程序里只有一个对象，所以身份比较是 100% 可靠的，而且比 `==` 更快、更规范。

```python
# ❌ 能跑但不规范
if x == None:
    pass

# ✅ 规范
if x is None:
    pass
```

**示例 7-15　浮点数不能用 `==` 判断**

```python
import math                                    # 标准库；import 的完整机制见第 18 章

print(0.1 + 0.2 == 0.3)                        # => False    ❌ 结果和预期相反
print(math.isclose(0.1 + 0.2, 0.3))            # => True     ✅ 正确做法
```

回收第 3.4 节和第 4.12 节：浮点数有精度问题，判断"相等"要用 `math.isclose()`。

**放进 `if` 里就是这样**：

```python
total = 0.1 + 0.2

# ❌ 这个分支永远进不去
if total == 0.3:
    print("正好三毛")

# ✅ 这样才对
if math.isclose(total, 0.3):
    print("正好三毛")
```

> **提醒**：如果这是**金额**，正确做法不是 `isclose`，而是根本别用浮点数——用整数存"分"或者用 `decimal`（第 3.4 节、工具箱 T2）。

## 7.12 嵌套判断的扁平化

嵌套超过两层，代码就开始难读了。**三种扁平化手段**：

### 手段一：平级互斥的条件改用 `elif`

**示例 7-16　嵌套改 elif**

```python
score = 85

# ❌ 三层嵌套，缩进越来越深
if score >= 90:
    print("优秀")
else:
    if score >= 80:
        print("良好")
    else:
        if score >= 60:
            print("及格")
        else:
            print("不及格")
```

```python
# ✅ 用 elif 拉平，缩进始终只有一层
if score >= 90:
    print("优秀")
elif score >= 80:
    print("良好")
elif score >= 60:
    print("及格")
else:
    print("不及格")
```

**两段代码功能完全相同**，但第二段的每个分支都在同一层缩进，一眼能看出这是"四选一"。

### 手段二：层层递进的条件用 `and` 合并

**示例 7-17　嵌套改 and**

```python
name = "admin"
pwd = "python123"

# ❌ 两层嵌套只为了"两个条件都成立"
if name == "admin":
    if pwd == "python123":
        print("登录成功")
```

```python
# ✅ 用 and 合并
if name == "admin" and pwd == "python123":
    print("登录成功")
```

**什么时候不能合并**：如果两层各自都需要 `else`（比如要区分"用户名错"和"密码错"），那就不能简单合并——本章末的登录示例会展示正确的处理方式。

### 手段三：区间判断按边界单向排序

这就是 7.4 讲的——`elif` 链从严到宽排，每个条件只写一个边界。

> **记住这条**：**缩进超过三层就该考虑重构。** `elif` 拉平互斥分支、`and` 合并递进条件。
>
> 还有第四种手段叫"**提前返回**"，它需要函数，第 14.17 节会讲——那是最有效的一种。

## 7.13 `pass`：占个位置

**示例 7-18　空的 `if` 块会报错**

```python
if True:
```

```text
IndentationError: expected an indented block after 'if' statement on line 1
```

**`if` 块不能为空。** 想先把结构搭出来、逻辑以后再写，就用 `pass`：

```python
if True:
    pass                # 什么都不做，只为占位让语法合法

print("pass 让空块合法")
```

```text
pass 让空块合法
```

**`pass` 是一条真正的语句**（不是注释），它的作用就是"什么都不做"。

**两个使用场合**：搭框架时占位、以及"这种情况确实什么都不用做"（这时最好加注释说明为什么，否则读者会以为你忘写了）。

## 7.14 把 `==` 写成 `=` 会怎样

**示例 7-19　Python 从语法上禁止了这个错误**

```python
x = 1
if x = 5:
    print("a")
```

```text
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
```

**这是好事。** 在 C / C#/ Java 里，`if (x = 5)` 能编译通过——它会把 5 赋给 x，然后判断 5 是真值，于是条件恒成立。这种 bug 极其隐蔽。

Python 直接在语法层面禁止了在条件里赋值，**你不可能犯这个错**。而且 3.10+ 的报错还会提示你 `Maybe you meant '==' or ':=' instead of '='?`

（那个 `:=` 是"海象运算符"，是唯一能在表达式里赋值的写法，用途很窄，第 37 章会提一句。）

## 7.15 多条件的优先级

**示例 7-20　`and` 和 `or` 混用时加括号**

```python
a, b, c = True, False, False

print(a or b and c)              # => True
print((a or b) and c)            # => False
```

**两个结果不同。** 因为 `and` 的优先级高于 `or`（第 4.8 节），第一行实际是 `a or (b and c)`。

还有一个容易搞反的：

```python
print(not 3 == 3)                # => False
```

它不是 `(not 3) == 3`，而是 `not (3 == 3)`——因为比较运算符的优先级高于 `not`。

> **记住这条**：**`and` 和 `or` 混用时一律加括号。** 不是语法需要，而是让读代码的人（包括三个月后的你）不用回忆优先级表。**多余的括号不会让程序变慢，但会让意图变清楚。**

## 7.16 `match-case`（★ 认知即可）

Python 3.10 起有了 `match-case`，处理"一个值对多种取值"的情况：

**示例 7-21　`match-case` 长什么样**

```python
cmd = "list"

match cmd:
    case "add":
        print("添加记录")
    case "list":
        print("列出记录")
    case _:                      # _ 表示"其他所有情况"，相当于 else
        print("未知命令")
```

```text
列出记录
```

**注意版本要求**：这是 3.10+ 的语法。在 3.9 上运行会直接报 `SyntaxError`（我实测确认过）。

1. 日常用 `if/elif` 已经够
2. 处理"值 → 结果"的映射，**用字典比 `match` 更简洁**（第 11 章会讲，那是更常用的做法）
3. `match` 真正强大的地方是**匹配结构**（能拆解嵌套的数据），那需要先学容器和类

**示例 7-23　快递运费计算**（样板示例）

真实规则：首重 1 公斤 8 元，续重每公斤 3 元；满 100 元包邮；超过 30 公斤走货运不接单。

```python
weight = float(input("重量（公斤）：").strip())
amount = float(input("订单金额（元）：").strip())

# 边界值先想清楚：规则说"超过 30 不接"，所以 30 公斤是接的 → 用 > 而不是 >=
if weight > 30:
    print("超重，请走货运")
elif amount >= 100:                    # "满 100" 就是 >=，100 元本身算包邮
    print("满 100 包邮，运费 0 元")
elif weight <= 1:                      # 1 公斤以内只收首重
    print("运费 8.00 元")
else:
    # 走到这里说明 1 < weight <= 30
    extra = weight - 1                 # 超出首重的部分
    fee = 8 + extra * 3
    print(f"运费 {fee:.2f} 元")         # 金额一律保留两位小数
```

**七组边界值逐个验证**（我实际跑过，结果如下）：

| 输入 | 输出 | 这一组在检验什么 |
|---|---|---|
| 重 0.5，金额 50 | `运费 8.00 元` | 首重下限 |
| 重 **1**，金额 50 | `运费 8.00 元` | **1 公斤走首重还是续重**（`<= 1` 决定的） |
| 重 1.5，金额 50 | `运费 9.50 元` | 续重计算对不对（`8 + 0.5 × 3`） |
| 重 **30**，金额 50 | `运费 95.00 元` | **30 公斤仍然接单**（`> 30` 决定的） |
| 重 31，金额 50 | `超重，请走货运` | 拒单下限 |
| 重 40，金额 **200** | `超重，请走货运` | **超重优先于包邮** |
| 重 2，金额 **100** | `满 100 包邮，运费 0 元` | "满 100"含不含 100 |

**最后两行尤其要注意**：

- **第六组**说明了一件重要的事：**分支顺序表达的是业务优先级**。这段代码把"超重拒单"排在"包邮"前面，意味着超重比包邮优先。如果把包邮判断挪到最前面，40 公斤的大件就会被判包邮——**这不是技术错误，是业务错误**。
- **第七组**验证了"满"的含义。规则里的一个字（满/超过/不低于），决定了一个等号。

> **记住这条**：**多分支代码写完，先列一张边界值表逐个试。** 分支越多越要试——因为不进那个分支的时候，写错了也不会报错。

**示例 7-24　简易登录判断**

演示 7.12 提到的"两层各自需要 `else`"的情况：

```python
USER = "admin"                                  # 大写变量名表示"当成常量用"（第 2.5 节）
PASSWORD = "python123"

name = input("用户名：").strip().lower()          # 用户名不区分大小写（第 6.8 节的标准动作）
pwd = input("密码：").strip()                     # 密码区分大小写，所以不 lower()

if name == USER and pwd == PASSWORD:
    print("登录成功")
elif name == USER:                              # 走到这里说明用户名对、密码错
    print("密码错误")
else:
    print("用户名不存在")
```

三种情况各测一次：

```text
用户名：Admin
密码：python123
登录成功
```

```text
用户名：admin
密码：wrongpwd
密码错误
```

```text
用户名：someone
密码：python123
用户名不存在
```

**注意第一组输入的是 `Admin`（大写 A）也能登录成功**——因为 `.lower()` 把它规范化了。而密码没有 `.lower()`，所以密码是区分大小写的。**这个区别是有意设计的**，不是疏忽。

> **一个安全提醒**：真实系统**绝不会**像这样把密码明文写在代码里，也不会明文比较。正确做法是存储密码的哈希值（工具箱 T3 会提到 `hashlib`）。这里只为演示条件判断，**不要照抄到真实项目里**。

<details>
<summary><b>给有 C# / Java / SQL 经验的读者</b></summary>

| 你熟悉的 | Python |
|---|---|
| `if (cond) { ... }` | `if cond:` + 缩进块，**不要括号，但要冒号** |
| `else if` | **`elif`**（拼写不同） |
| `switch` / `case` | `if/elif` 链、字典分发（第 11 章）、或 `match-case`（3.10+） |
| `cond ? a : b` | `a if cond else b`（**顺序不同**，值在前、条件在中间） |
| `&&` / `\|\|` / `!` | `and` / `or` / `not` |
| `if (x != null)` | `if x is not None:` |
| `if (string.IsNullOrEmpty(s))` | `if not s:`（空字符串和 `None` 都是假） |
| `if (list.Count > 0)` | `if lst:`（第 9 章） |
| `if (x = 5)` **能编译**，是经典 bug 来源 | **语法禁止**，直接 `SyntaxError` |
| SQL 的 `CASE WHEN ... THEN` | `if/elif` |
| SQL 的 `BETWEEN 0 AND 100` | `0 <= x <= 100`（链式比较） |

**三个需要特别注意的**：

1. **没有括号但必须有冒号。** 写 `if (x > 5):` 也能跑（括号被当成分组），但不地道。写 `if x > 5` 忘了冒号会直接报错。
2. **`if x:` 的含义比 C# 宽得多。** C# 的 `if` 只接受 `bool`，而 Python 的 `if` 接受任何值并按真假规则判断。这带来便利（`if s:` 就能判断空字符串），也带来 7.8 那个坑（`0` 被当成"没有"）。
3. **三元表达式的顺序反了。** C# 是 `cond ? a : b`（条件在前），Python 是 `a if cond else b`（**值在前**）。刚转过来时很容易写错。

**SQL 背景的读者注意**：SQL 里 `NULL` 参与比较结果是 `NULL`（三值逻辑），所以要用 `IS NULL`。Python 里 `None == None` 是 `True`，**但规范写法仍然是 `is None`**——习惯上和 SQL 一致，理由不同（Python 是因为 `None` 是单例）。

</details>

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| `elif` 从宽到严排 | **语法正确、结果全错、不报错** | 从严到宽排，用代表值逐分支验证 | 第一个成立的分支就终止判断 |
| `if x = 5:` | `SyntaxError: Maybe you meant '=='` | `if x == 5:` | 一个等号是赋值 |
| `if` 后忘冒号 | `SyntaxError: expected ':'` | 补冒号 | 冒号是块的起始标记 |
| `if` 块内没有语句 | `IndentationError: expected an indented block` | 放一个 `pass` | 块不能为空 |
| 缩进多了一级 | 语句被归进上一个块，逻辑错乱 | 检查缩进对齐 | 缩进决定归属 |
| `if count:` 判断"填没填" | 用户填的 `0` 被当成没填 | `if count == 0:` / `is None` 区分 | `0` 是假值 |
| 用真假判断字符串 `"0"` | 恒为真，判断永远成立 | 显式比较内容 | 非空字符串恒为真 |
| `if x == None:` | 能跑但不规范 | `if x is None:` | `None` 是单例 |
| `if 0.1 + 0.2 == 0.3:` | 分支永远进不去 | `math.isclose(a, b)` | 浮点精度 |
| 用 `isclose` 判断金额 | 治标不治本 | 用整数存"分"或 `decimal` | 金额不该用浮点数 |
| `a or b and c` 以为从左往右 | 实际是 `a or (b and c)` | 加括号 | `and` 优先级高于 `or` |
| `not 3 == 3` 以为是 `(not 3) == 3` | 逻辑反了 | 实际是 `not (3 == 3)` | 比较优先级高于 `not` |
| 三元表达式嵌套两层以上 | 自己都读不懂 | 改回 `if/elif` | 可读性优先 |
| 区间判断漏边界 | 90 分不算优秀这类差一错误 | **列边界值表逐个试** | `>` 与 `>=` 差一个数 |
| 把"满 100"写成 `> 100` | 正好 100 元的订单不包邮 | `>= 100` | 中文规则要翻译准确 |
| 分支顺序不符合业务优先级 | 40 公斤大件被判包邮 | 想清楚哪个规则优先 | 顺序表达优先级 |
| 在 3.9 上用 `match-case` | `SyntaxError` | 用 `if/elif` | 3.10+ 才有 |

## 本章小结

- `if` 三要素：**条件、冒号、缩进块**；**凡是冒号结尾的行，下一行必须缩进**（这条规律后面处处适用）
- `elif` **从上往下逐个判断，第一个成立的执行完就结束**——所以**顺序必须从严到宽**
- **每个分支挑一个代表值逐个试**，这是多分支代码唯一可靠的自查方法
- 真假规则：**零、空、无为假，其余为真**；注意 **`"0"` 是非空字符串，它是真的**
- **判断"有没有内容"用 `if x:`；但 `0` 是合法数据时，必须用 `== 0` 或 `is None`**
- 三元表达式 `a if cond else b` 只用于一层的二选一
- 区间判断用**链式比较** `0 <= x <= 100`；**边界值要逐个确认**（`>` 和 `>=` 差一个数）
- `None` 用 `is None`；浮点数用 `math.isclose()`
- 扁平化三手段：`elif` 拉平互斥分支、`and` 合并递进条件、边界单向排序
- **`and` / `or` 混用一律加括号**

### 语法速查

| 写法 | 作用 |
|---|---|
| `if 条件:` | 单分支 |
| `if ... else:` | 二选一 |
| `if ... elif ... else:` | 多分支（**从严到宽排**） |
| `a if 条件 else b` | 三元表达式（值在前、条件在中） |
| `if x:` | 判断"有没有内容" |
| `if x == 0:` | 判断"是不是零"（`0` 是合法值时必须这样） |
| `if x is None:` | 判断"有没有值" |
| `if 0 <= x <= 100:` | 区间判断 |
| `if math.isclose(a, b):` | 浮点数相等判断 |
| `pass` | 占位，什么都不做 |
| `match x: case ...:` | 多值匹配（3.10+，★） |

### 真假规则速查

| 值 | 真假 |
|---|---|
| `0`、`0.0` | 假 |
| `""`（空字符串） | 假 |
| `None` | 假 |
| `[]`、`{}`（空容器，第 9 章） | 假 |
| **`"0"`、`" "`、`"False"`** | **真**（非空字符串） |
| `-1`、`0.1` | 真 |
