> **本章目标**：会创建元组（包括单元素元组）；理解不可变的**范围与边界**；会用解包；知道什么时候该用元组而不是列表。
> **前置章节**：第 9 章
> **预计用时**：2~3 小时
> **优先级**：★★

## 开篇：一个故意不让你改的列表

学完列表，你可能会想：**还需要别的序列吗？** 列表能装能改能排序，看起来什么都能干。

问题恰恰出在"能改"上。

想象你写了一个函数，把一份配置列表传给别人的代码去处理。你怎么保证对方不会偷偷改动它？**你保证不了**——列表是可变的，任何拿到它的代码都能改。

元组解决的就是这个问题：**它创建之后就锁死了，谁也改不了。**

听起来像是"功能变少了"，但这个限制换来了两样列表没有的东西：

1. **交出去放心**——对方不可能改坏你的数据
2. **能当字典的键**（第 11 章会用到）——这是元组**不可替代**的用途

本章还会揭穿一个常见误解：**元组的"不可变"，比你想的浅。**

## 10.1 创建元组

**示例 10-1　用圆括号**

```python
t = (1, 2, 3)
print(t)                 # => (1, 2, 3)
print(len(t))            # => 3
print(type(t))           # => <class 'tuple'>

print(())                # => ()            空元组
print(tuple([1, 2, 3]))  # => (1, 2, 3)     从列表转过来
```

---

## 10.2 逗号才是关键，括号不是

**示例 10-2　不加括号也是元组**

```python
t = 1, 2, 3              # 没有括号
print(t)                 # => (1, 2, 3)
print(type(t))           # => <class 'tuple'>
```

**创建元组靠的是逗号，不是括号。** 括号只是为了清楚（以及在有歧义的场合必须加）。

**为什么要知道这件事**：它解释了后面三个看起来无关的现象——

| 现象 | 其实是 |
|---|---|
| `a, b = b, a` 能交换变量（10.7 节） | 右边的 `b, a` 是一个元组 |
| `return a, b` 返回"两个值"（第 14 章） | 其实返回的是一个元组 |
| `divmod(17, 5)` 返回"商和余数" | 返回的是元组 `(3, 2)` |

**Python 里"多个值"的默认载体就是元组**，这个认知很重要。

---

## 10.3 单元素元组必须加逗号

**示例 10-3　`(1)` 不是元组**

```python
print(type((1)))         # => <class 'int'>      只是一个数字！
print((1))               # => 1

print(type((1,)))        # => <class 'tuple'>    加了逗号才是元组
print((1,))              # => (1,)
```

**为什么会这样**：括号在 Python 里还有"分组运算"的含义（`(2 + 3) * 4`）。`(1)` 就是"被括起来的 1"，还是个数字。**Python 只能靠那个逗号区分**。

**什么时候会踩到**：写只有一个元素的配置、或者给函数传一个单元素元组时。类型悄悄变了，后面用 `len()` 或遍历就报错。

> **记住这条**：**单元素元组一定要写成 `(1,)`**，那个逗号不是笔误。

---

## 10.4 索引与切片

**示例 10-4　和列表完全一致**

```python
t = (10, 20, 30, 40)

print(t[0])              # => 10
print(t[-1])             # => 40
print(t[1:3])            # => (20, 30)
print(type(t[1:3]))      # => <class 'tuple'>     切片结果还是元组
```

**规则和字符串、列表都一样**（左闭右开、负下标、越界不报错）——**第三次遇到同一套规则**了。这就是 Python"序列"概念带来的好处。

---

## 10.5 元组不能改

**示例 10-5　三种改动都不行**

```python
t = (1, 2)
t[0] = 9
```

```text
TypeError: 'tuple' object does not support item assignment
```

```python
t.append(3)
```

```text
AttributeError: 'tuple' object has no attribute 'append'
```

```python
t.remove(1)
```

```text
AttributeError: 'tuple' object has no attribute 'remove'
```

**注意后两个报的是 `AttributeError` 而不是 `TypeError`**。这个区别有意思：

- `t[0] = 9` → `TypeError`：**"这个操作不支持"**
- `t.append(3)` → `AttributeError`：**"根本没有这个方法"**

**元组不是"有 append 但不许用"，而是压根没这个方法。**

---

## 10.6 元组只有两个方法

**示例 10-6　对比一下方法数量**

```python
tuple_methods = [m for m in dir(tuple) if not m.startswith("_")]
list_methods = [m for m in dir(list) if not m.startswith("_")]

print("元组的方法:", tuple_methods, "共", len(tuple_methods), "个")
print("列表的方法:", list_methods, "共", len(list_methods), "个")
```

```text
元组的方法: ['count', 'index'] 共 2 个
列表的方法: ['append', 'clear', 'copy', 'count', 'extend', 'index', 'insert', 'pop', 'remove', 'reverse', 'sort'] 共 11 个
```

**元组只有 `count` 和 `index` 两个方法**——因为列表其余九个方法**全都是改数据的**。

**这是个好记忆点**：方法少不是缺陷，正是"不可变"的直接体现。

（`dir()` 列出一个类型有哪些成员，`startswith("_")` 过滤掉内部方法——这个技巧在探索陌生库时很有用，第 18.17 节会再提。）

## 10.7 不可变的边界（重要）

**这一节是本章最容易误解的地方。**

**示例 10-7　元组里的列表照样能改**（样板示例）

```python
t = (1, [2, 3])          # 元组里装了一个列表

t[0] = 99                # ❌ TypeError    改元素不行，符合预期
```

但是——

```python
t = (1, [2, 3])
print("改之前:", t)               # => 改之前: (1, [2, 3])

t[1].append(4)                    # 改的是元组里那个列表
print("改之后:", t)               # => 改之后: (1, [2, 3, 4])
```

**元组的内容"看起来"变了。这算不算违背了不可变？**

**不算。** 回到第 3.1 节的标签模型——

```python
t = (1, [2, 3])
print(id(t[1]))          # => 140486257789376    记住这个身份编号
t[1].append(4)
print(id(t[1]))          # => 140486257789376    没变，还是同一个列表
```

**元组里存的不是那个列表本身，而是一根"指向列表的线"。**

- 不可变保证的是：**这根线不能改接到别的对象上**
- 但线那头的对象自己变胖变瘦，元组管不着

```text
元组 t ──→ [ 1, ● ]
                 │
                 └──→ [2, 3]  ← 这个列表可以自己变成 [2, 3, 4]
                             元组只记得"我指向它"，不管它多长
```

**所以准确的说法是**：**元组保证"装的是哪几个对象"不变，不保证"这些对象的内容"不变。**

### 这个区别有实际后果

它决定了元组能不能当字典的键（下一节）：

```python
print(hash((1, 2)))              # 能算出一个整数
```

```python
print(hash((1, [2])))
```

```text
TypeError: unhashable type: 'list'
```

**装了列表的元组不能算哈希**，因为内容会变——算出来的"指纹"就不可靠了。

> **记住这条**：**元组的不可变是"浅"的。** 想真正锁死一份数据，元组里就只能装不可变的东西（数字、字符串、其他这样的元组）。

## 10.8 可哈希：元组能做而列表不能做的事

**示例 10-8　能不能算出"指纹"**

```python
print(hash((1, 2)))              # 成功，得到一个整数
print(hash("abc"))               # 字符串也可以
```

```python
print(hash([1, 2]))
```

```text
TypeError: unhashable type: 'list'
```

**什么叫"可哈希"**：能算出一个固定的整数"指纹"。前提是——**内容不会变**，否则指纹就不可靠了。

> **一个实测细节**：`hash((1, 2))` 每次运行结果相同，但 **`hash("abc")` 每次运行都不一样**——Python 对字符串启用了哈希随机化（防止恶意构造的哈希碰撞攻击）。所以**具体数值不重要，能不能算出来才是重点**。

**为什么这件事重要**：

| 用途 | 要求 |
|---|---|
| **当字典的键**（第 11 章） | 必须可哈希 |
| **放进集合**（第 12 章） | 必须可哈希 |

**列表不可哈希，所以列表不能当字典的键；元组可以。** 这是元组**不可替代**的用途。

**典型场景**：用"坐标"当键。

```python
# 想用 (行, 列) 作为键记录棋盘上的棋子——只有元组能做到
# 具体写法第 11 章讲，这里只说明为什么需要元组
print(hash((3, 5)))              # ✅ 坐标元组可哈希
```

## 10.9 解包

**示例 10-9　一次拆成几个变量**

```python
point = (3, 4)
x, y = point                     # 把两个元素分别赋给两个变量
print(x, y)                      # => 3 4
```

**这个操作叫"解包"（unpacking）**，是 Python 里非常常用的写法。

**解包对所有可迭代对象都有效**，不只是元组：

```python
a, b, c = "xyz"                  # 字符串也能解包
print(a, b, c)                   # => x y z
```

**示例 10-10　个数必须完全匹配**

```python
x, y = (1, 2, 3)
```

```text
ValueError: too many values to unpack (expected 2)
```

```python
x, y, z = (1, 2)
```

```text
ValueError: not enough values to unpack (expected 3, got 2)
```

**报错信息很直白**：多了说"too many"，少了说"not enough"还告诉你实际有几个。

## 10.10 交换变量

**示例 10-11　一行搞定，不需要临时变量**

```python
m, n = 1, 2
m, n = n, m
print(m, n)                      # => 2 1
```

**原理就是 10.2 节讲的**：

1. 右边的 `n, m` 先被打包成一个元组 `(2, 1)`
2. 然后整体解包给左边的 `m, n`

**所以不需要临时变量**——旧值在打包时就已经被"取出来"了。

**对比其他语言的写法**：

```text
C# / Java:  int temp = m; m = n; n = temp;
Python:     m, n = n, m
```

这是 Python 最讨喜的小特性之一。

---

## 10.11 星号解包

**示例 10-12　只要头尾，中间打包**

```python
first, *rest = (1, 2, 3, 4)
print(first)                     # => 1
print(rest)                      # => [2, 3, 4]
print(type(rest))                # => <class 'list'>     注意是列表！
```

**`*rest` 会把剩下的元素收集起来**——**收成的是列表，不是元组**（这一点容易记错）。

星号也可以放中间：

```python
a, *mid, z = (1, 2, 3, 4, 5)
print(a, mid, z)                 # => 1 [2, 3, 4] 5
```

**什么时候用**：只关心开头和结尾、中间部分不重要时。比如处理"第一行是表头、最后一行是合计、中间是数据"的情况。

## 10.12 "返回多个值"的真相

**示例 10-13　`divmod` 揭穿这件事**

`divmod` 是个内置函数，"同时返回商和余数"（第 4.4 节见过）：

```python
print(divmod(17, 5))             # => (3, 2)         其实返回的是一个元组

q, r = divmod(17, 5)             # 配合解包，看起来就像"返回了两个值"
print(q, r)                      # => 3 2
```

**Python 里没有"返回多个值"这回事**——函数永远只返回一个对象，只不过那个对象可以是元组，再配合解包，用起来就像返回了多个值。

**这个认知在第 14 章会正式用上**：

```python
# 第 14 章会写的代码
def divide(a, b):
    return a // b, a % b         # 逗号 → 打包成元组

q, r = divide(17, 5)             # 解包
```

## 10.13 解包遍历：处理一批记录

**这是元组在实战中最高频的用法**：用元组表示"一条记录"，用列表装"很多条记录"。

**示例 10-14　对比两种遍历方式**

```python
# 每个元组是一条记录，三个位置的含义固定：姓名、科目、分数
# 用列表装它们，因为记录条数是会变的
records = [
    ("小明", "数学", 92),
    ("小红", "语文", 88),
    ("小刚", "英语", 76),
]

# ❌ 不解包：三个月后你不记得 r[1] 是科目还是分数
for r in records:
    print(f"{r[0]:<6}{r[1]:<6}{r[2]:>4}")
```

```python
# ✅ 解包遍历：每个变量都有名字，代码自己说明了含义
for name, subject, score in records:
    print(f"{name:<6}{subject:<6}{score:>4}")
```

两段的输出完全一样：

```text
小明    数学      92
小红    语文      88
小刚    英语      76
```

**但可读性差别很大。** `r[2]` 需要你回头数第几个位置，`score` 一眼就懂。

**示例 10-15　给记录排序**

```python
records = [("小明", 92), ("小红", 88), ("小刚", 76)]

print("按分数降序:")
for name, score in sorted(records, key=lambda t: t[1], reverse=True):
    print(f"  {name:<6}{score:>4}")
```

```text
按分数降序:
  小明      92
  小红      88
  小刚      76
```

**`key=lambda t: t[1]` 的含义是"按每条记录的第 2 个元素排"**。`lambda` 是一种简写的小函数，完整讲解在第 25 章——**现在照这个形式用就行**。

**不指定 `key` 时会按元组的第一个元素排**：

```python
print("按姓名:")
for name, score in sorted(records):
    print(f"  {name:<6}{score:>4}")
```

```text
按姓名:
  小刚      76
  小明      92
  小红      88
```

**元组之间的比较是"逐个位置比"**——先比第一个元素，相同才比第二个。这个特性在第 25 章的多级排序里会大放异彩。

## 10.14 元组与列表互转

**示例 10-16　需要临时修改元组时**

```python
t = (3, 1, 2)

lst = list(t)                    # 转成列表
lst.sort()                       # 改
t2 = tuple(lst)                  # 再转回元组

print(t, "→", lst, "→", t2)      # => (3, 1, 2) → [1, 2, 3] → (1, 2, 3)
```

**"转成列表改完再转回去"是处理元组的标准套路**。注意原元组 `t` 始终没变——你得到的是一个新元组。

## 10.15 选型：元组还是列表

**示例 10-17　同一份数据两种表示**

```python
# 用元组：表示"一个点"，两个位置含义不同（x 和 y）
point = (3, 4)

# 用列表：表示"一批分数"，每个元素地位相同
scores = [88, 95, 70]
```

**判断标准**：

| 情况 | 用哪个 | 例子 |
|---|---|---|
| **元素个数固定，每个位置含义不同** | **元组** | 坐标 `(x, y)`、RGB 颜色 `(255, 0, 0)`、数据库的一行记录 |
| **元素个数会变，每个元素地位相同** | **列表** | 学生名单、购物车、日志行 |
| **需要当字典的键 / 放进集合** | **必须元组** | 用坐标当键（第 11 章） |
| **需要增删改** | **必须列表** | —— |

**一条实用经验**：

> **元组表达"结构"，列表表达"集合"。**

一条记录里每个位置的含义不同（姓名、科目、分数）→ 元组；一堆地位相同的东西 → 列表。

**这个区分不是语法要求**（用列表存坐标也能跑），但它能让代码的意图一眼看明白。而且用元组还有个附带好处：**万一你不小心写了 `point[0] = 5`，它会当场报错**，而不是悄悄改坏数据。

## 综合示例

**示例 10-18　坐标点计算**

```python
p1 = (0, 0)
p2 = (3, 4)

x1, y1 = p1                                          # 解包，比 p1[0] p1[1] 好读
x2, y2 = p2

distance = ((x2 - x1) ** 2 + (y2 - y1) ** 2) ** 0.5   # ** 0.5 就是开平方（第 4.4 节）

print(f"{p1} 到 {p2} 的距离是 {distance}")
print(f"保留两位: {distance:.2f}")
```

```text
(0, 0) 到 (3, 4) 的距离是 5.0
保留两位: 5.00
```

**为什么用元组表示点**：一个点就是"两个含义不同的数字"，个数固定为 2，不需要增删——**完全符合元组的适用场景**。而且传给别的函数时不怕被改。

**示例 10-19　学生成绩报表**

比第 9 章的纯列表版本清晰得多，因为**每条记录是一个结构**：

```python
records = [
    ("小明", 88, 92, 76),                            # 姓名、语文、数学、英语
    ("小红", 95, 85, 90),
    ("小刚", 62, 70, 58),
]

line = "-" * 40
print(line)
print(f"{'姓名':<8}{'语文':>7}{'数学':>7}{'英语':>7}{'总分':>8}")
print(line)

for name, chinese, math, english in records:         # 解包遍历，四个变量都有名字
    total = chinese + math + english
    print(f"{name:<8}{chinese:>7}{math:>7}{english:>7}{total:>8}")

print(line)
```

```text
----------------------------------------
姓名           语文     数学     英语      总分
----------------------------------------
小明           88     92     76     256
小红           95     85     90     270
小刚           62     70     58     190
----------------------------------------
```

**和第 9 章的对比**：如果用纯列表存这些数据，你得写 `r[1] + r[2] + r[3]`，还得记住哪个下标是哪科。**解包让代码自己说明了含义。**

（中文列还是有点歪，原因见第 5.29 节——f-string 按字符数算宽度，中文占两格。）

**示例 10-20　`namedtuple` 一瞥**（★ 认知即可）

元组的下标还是不够直观（`r[2]` 是什么？）。标准库提供了一个折中方案：

```python
from collections import namedtuple                   # 完整讲解在第 34 章

Point = namedtuple("Point", "x y")
p = Point(3, 4)

print(p)                         # => Point(x=3, y=4)     打印时带字段名
print(p.x, p.y)                  # => 3 4                 可以用名字访问
print(p[0], p[1])                # => 3 4                 也还能用下标
print(isinstance(p, tuple))      # => True                它仍然是元组
```

**`namedtuple` 让你用名字而不是下标访问元素**，同时保留了元组的全部特性（不可变、可哈希、能解包）。

**什么时候用**：一条记录有三四个字段、下标已经记不住的时候。

**为什么本章不细讲**：现代 Python 里更常用的是 `dataclass`（第 29 章），它更灵活。`namedtuple` 主要出现在老代码和"需要不可变记录"的场合。**认得出就行。**

<details>
<summary><b>给有 C# / Java / SQL 经验的读者</b></summary>

| 你熟悉的 | Python |
|---|---|
| C# 的 `(int, int)` 元组、`ValueTuple` | `tuple`——但 Python 的元组用得**广泛得多** |
| C# 的 `var (x, y) = point;` 解构 | `x, y = point`（解包） |
| C# 的 `readonly` / Java 的 `final` | 元组的不可变**只保护"指向谁"，不保护对象内容**（10.7 节） |
| Java 没有内置元组（要用 `Pair` 之类） | 内置，且是"多个值"的默认载体 |
| `out` 参数返回多个值 | `return a, b`（其实是返回一个元组，第 14 章） |
| `int temp = a; a = b; b = temp;` | `a, b = b, a` |
| `Dictionary<(int, int), string>` 用元组当键 | 同样可以——**因为元组可哈希，列表不行**（10.8 节） |
| SQL 的一行记录 | 元组正是表示"一行"的天然选择 |

**三个需要注意的**：

1. **单元素元组必须写 `(1,)`。** C# 的 `ValueTuple` 不存在这个问题，Python 里漏了逗号类型就变了。
2. **不可变是"浅"的。** C# 的 `readonly` 字段同样只保证引用不变（对象内容仍可改），这一点两个语言是一致的——但 Python 的 `hash()` 会因此拒绝含列表的元组，这个连带效果需要注意。
3. **元组在 Python 里的地位比在 C#/Java 里高得多。** 它不是"偶尔用一下的小工具"，而是函数返回多值、遍历记录、字典键的标准做法。**看到逗号就想到元组**。

**SQL 背景的读者**：`records = [("小明", 92), ...]` 这个结构，本质上就是**查询结果集**——每个元组是一行，列表是行的集合。用 `for name, score in records:` 遍历，相当于游标逐行取值并把列拆到变量里。这个对应关系在第 31 章（数据库）会真正用上：`cursor.fetchall()` 返回的就是元组的列表。

</details>

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| `(1)` 当元组用 | 它是整数，`len()` 会报错 | `(1,)` | 逗号才是关键 |
| `t[0] = 9` | `TypeError: does not support item assignment` | 转成列表改，或重建元组 | 元组不可变 |
| `t.append(x)` | `AttributeError: no attribute 'append'` | 用列表，或 `t + (x,)` | 元组根本没这个方法 |
| **以为放进元组数据就安全了** | 里面的列表被别处改掉 | 元组里只装不可变元素 | **不可变是"浅"的** |
| `hash((1, [2]))` | `TypeError: unhashable type: 'list'` | 元组里改用元组代替列表 | 含可变元素则不可哈希 |
| 用列表当字典的键 | `TypeError: unhashable type` | 改用元组 | 列表不可哈希 |
| 解包个数不匹配 | `ValueError: too many / not enough values` | 数清个数，或用 `*rest` 兜底 | 解包要求严格对应 |
| **`first, *rest` 以为 `rest` 是元组** | 后续按元组用会出错 | 记住 `rest` 是**列表** | 星号解包固定收成列表 |
| 以为 `t += (4,)` 是原地追加 | `id` 变了，别处引用的还是老元组 | 明确知道这是重新赋值 | 产生了新元组 |
| 用元组存"条数会变"的数据 | 每次增删都要重建，代码难看 | 改用列表 | 选型错误 |
| 用 `r[2]` 而不解包 | 三个月后看不懂哪个下标是什么 | `for name, subject, score in records` | 可读性 |

## 本章小结

- 创建元组靠的是**逗号**，括号只为清楚；**单元素元组必须写 `(1,)`**
- 索引和切片规则与字符串、列表**完全一致**（第三次遇到同一套规则）
- 元组**不能改**：改元素报 `TypeError`，调 `append` 报 `AttributeError`（**根本没这个方法**）
- **元组只有 `count` 和 `index` 两个方法**——方法少正是不可变的体现
- **不可变是"浅"的**：元组保证"装的是哪几个对象"不变，**不保证那些对象的内容不变**
- **可哈希是元组不可替代的用途**：能当字典的键、能放进集合，列表不行
- **解包**：`x, y = point`、`a, b = b, a` 交换、`first, *rest`（**`rest` 是列表**）
- Python 里"返回多个值"的真相就是**返回一个元组 + 解包**
- **解包遍历** `for name, score in records` 是处理一批记录的标准写法
- 选型：**元组表达"结构"，列表表达"集合"**

### 语法速查

| 写法 | 作用 |
|---|---|
| `(1, 2, 3)` / `1, 2, 3` | 创建元组（**逗号是关键**） |
| `(1,)` | 单元素元组 |
| `()` | 空元组 |
| `tuple(lst)` / `list(t)` | 互转 |
| `t[0]` / `t[1:3]` | 索引 / 切片（结果还是元组） |
| `t.count(x)` / `t.index(x)` | **元组仅有的两个方法** |
| `x, y = point` | 解包 |
| `a, b = b, a` | 交换变量 |
| `first, *rest = t` | 星号解包（`rest` 是**列表**） |
| `for name, score in records:` | 解包遍历 |
| `sorted(records, key=lambda t: t[1])` | 按第 2 个元素排序（第 25 章详讲） |
| `hash(t)` | 算哈希（判断可不可以当键） |
| `namedtuple("Point", "x y")` | 具名元组（★ 第 34 章） |
