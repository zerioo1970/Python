## 开篇：为什么第 2 章就讲读报错

正常的教程顺序应该是先讲变量、再讲运算，把报错留到后面。这本书把它提到第 2 章，理由很简单：

**你接下来要犯的错，比要写的代码多。**

第 1 章你已经见过两次报错了（拼错 `print`、找不到文件）。接下来的每一章，你都会遇到十几次。如果每次看到红字都要愣两分钟、然后把代码删掉重写，那学习速度会慢十倍。

而实际上——**报错已经把答案告诉你了**。它会说出：哪个文件、第几行、什么问题、有时甚至直接建议你怎么改。读懂它只需要十分钟的训练，这十分钟能在后面省掉你几十个小时。

所以这一章分两半：前半讲 Python 的语法规矩（这些规矩恰好是新手报错的主要来源），后半讲怎么读报错。

## 2.1 Hello World 逐行拆解

回到第 1 章那行代码，把它拆开看：

**示例 2-1　一行代码里的四个部分**

```python
print("Hello, Python!")
```

```text
Hello, Python!
```

| 部分 | 是什么 | 说明 |
|---|---|---|
| `print` | **函数名** | 一个内置的功能，作用是把东西显示出来 |
| `(` `)` | **调用** | 括号表示"执行这个函数"。没有括号就只是提到它的名字，不会执行 |
| `"` `"` | **字符串标记** | 引号里的内容是文本，Python 不会试图理解它的含义 |
| `Hello, Python!` | **数据** | 你要显示的具体内容 |

**引号的作用要特别说一下**。有引号和没引号是两件完全不同的事：

```python
print("name")     # => name        引号里的是文本，原样输出这四个字母
print(name)       # ❌ NameError   没引号，Python 会去找一个叫 name 的东西
```

第二行报错，因为 Python 认为你在指代某个叫 `name` 的变量，而它不存在。**引号是"这是一段文本"和"这是一个名字"的分界线。**

### Python 区分大小写

**示例 2-2　大小写敏感**

```python
Print("hi")
```

```text
Traceback (most recent call last):
  File "bug.py", line 1, in <module>
    Print("hi")
    ^^^^^
NameError: name 'Print' is not defined. Did you mean: 'print'?
```

`Print` 和 `print` 是两个完全不同的名字。Python 3.12 甚至直接问你"你是想写 print 吗"。

**这条规则对所有名字都成立**，包括后面会学到的：

| 正确 | 错误 | 说明 |
|---|---|---|
| `print` | `Print`、`PRINT` | 内置函数名全小写 |
| `True` / `False` | `true`、`TRUE` | 布尔值**首字母大写**（第 3 章） |
| `None` | `none`、`NONE` | 空值首字母大写（第 3 章） |
| `if` / `for` / `while` | `If`、`For` | 关键字全小写 |

**为什么这值得单独讲**：从 SQL 或 VB 转过来的人特别容易踩这个坑，那些语言里 `SELECT` 和 `select` 是一样的。Python 里不是。

> **记住这条**：**Python 严格区分大小写，内置函数和关键字都是小写，只有 `True` / `False` / `None` 首字母大写。**

## 2.2 缩进：Python 用缩进代替花括号

这是 Python 最有名的特点，也是新手报错最集中的地方。

在大多数语言里，代码块用花括号框起来，缩进只是为了好看：

```text
C# / Java / JavaScript 的写法：
if (score >= 60) {
    Console.WriteLine("及格");     ← 缩进可有可无，花括号才是关键
}
```

Python 里没有花括号，**缩进本身就是语法**：

```python
if score >= 60:
    print("及格")        ← 这个缩进是必须的，它表示"这行属于 if"
```

缩进错了不是排版难看，是**程序跑不起来**。

### 规矩一：统一用 4 个空格

Python 不强制要求 4 个，但**整个 Python 社区都用 4 个空格**，所有编辑器默认也是 4 个。照做就行，不要标新立异。

### 规矩二：同一个块里必须对齐

**示例 2-3　缩进多了**

```python
print("a")
    print("b")
```

```text
  File "bug.py", line 2
    print("b")
IndentationError: unexpected indent
```

`unexpected indent` = "这里不该有缩进"。因为第 1 行是一句普通语句，它后面不该跟一个"块"。

**示例 2-4　该缩进却没缩进**

```python
if True:
print("x")
```

```text
  File "bug.py", line 2
    print("x")
    ^^^^^
IndentationError: expected an indented block after 'if' statement on line 1
```

这个报错信息在 3.10 之后**非常友好**：`expected an indented block after 'if' statement on line 1`——"第 1 行的 if 语句后面应该有一个缩进块"。它连是哪个语句、在第几行都告诉你了。

**规律**：**凡是以冒号结尾的行，下一行必须缩进。** 这条规律对 `if`、`for`、`while`、`def`、`class`、`try`、`with` 全都适用——冒号是"下面有一个块"的信号。你现在还没学这些，但记住这条规律，后面就不会错。

### 规矩三：Tab 和空格绝对不能混用

**示例 2-5　Tab 和空格混用**

```python
if True:
    print("空格缩进")
	print("Tab缩进")
```

```text
  File "bug.py", line 3
    print("Tab缩进")
TabError: inconsistent use of tabs and spaces in indentation
```

**这是最让人抓狂的一种错**：两行在屏幕上看起来一模一样地对齐，Python 却说它们不一致。因为一个是 4 个空格字符，一个是 1 个 Tab 字符——**肉眼看不出区别，但它们是不同的字符**。

**一次性解决办法**（现在就去设置，别等踩坑）：

| 编辑器 | 设置 |
|---|---|
| VS Code | 右下角状态栏点 "Spaces: 4"，选 `Indent Using Spaces`；再勾选 `Convert Indentation to Spaces` |
| PyCharm | Settings → Editor → Code Style → Python，勾选 `Use tab character` **取消**掉 |

设置好之后，你按 Tab 键，编辑器会自动插入 4 个空格，从此不会再遇到 `TabError`。

> **记住这条**：**冒号结尾的下一行必须缩进；缩进统一用 4 个空格；现在就把编辑器设成"Tab 转空格"。**

## 2.3 注释

注释是写给人看的，Python 会完全忽略它。

**示例 2-6　三种写注释的方式**

```python
# 这是单行注释，从 # 到行尾都被忽略

print("hi")          # 这是行尾注释，习惯上 # 前面留两个空格

"""
三引号包起来的一段文字。不赋给任何变量时，常被当成注释块用。
但要知道：它其实是一个字符串，只是没人使用它而已，不是真正的注释。
"""
```

```text
hi
```

三种的区别和用法：

| 写法 | 本质 | 什么时候用 |
|---|---|---|
| `# 说明` | 真正的注释 | 绝大多数情况 |
| `代码  # 说明` | 真正的注释 | 解释这一行为什么这么写 |
| `"""说明"""` | **字符串**，只是没被使用 | 临时屏蔽一大段代码；正式用途是**文档字符串**（第 14 章） |

### 注释该写什么

新手常犯的错是把注释写成代码的翻译：

```python
# ❌ 没有价值的注释：代码本身就说明了这些
count = 0            # 把 count 设为 0
print(count)         # 打印 count

# ✅ 有价值的注释：解释"为什么"和"要注意什么"
count = 0            # 从 0 开始计数，因为第一条记录的编号也是 0
timeout = 30         # 30 秒是对方接口的响应上限，改小会误判超时
```

**判断标准**：注释要回答代码回答不了的问题——**为什么这么做、为什么是这个值、有什么陷阱**。如果注释只是把代码翻译成中文，那它就是噪音，以后代码改了注释还留着，反而误导人。

> **记住这条**：**注释解释"为什么"，不解释"是什么"。** 代码已经说清是什么了。

## 2.4 一行一句、换行、分号

### 不写分号

Python 一行一句，**行尾不写分号**。

**示例 2-7　分号：能用但不要用**

```python
print("a"); print("b")     # 语法上合法，但没人这么写
```

```text
a
b
```

分号确实能用（把两句挤在一行），但 Python 社区的共识是**一行只写一句**，可读性优先。**从 C# / Java 转过来的人要专门改掉手指的习惯**——不过忘了删分号也不会报错，只是不地道。

### 一行太长怎么换行

**示例 2-8　两种换行方式**

```python
# 方式一：行尾加反斜杠 \（注意：\ 后面不能有任何字符，连空格都不行）
total = 1 + 2 + \
        3 + 4
print(total)               # => 10

# 方式二（推荐）：括号内可以自由换行，不需要任何符号
names = [
    "小明",
    "小红",
]
print(names)               # => ['小明', '小红']
```

```text
10
['小明', '小红']
```

**为什么推荐第二种**：反斜杠很脆弱——它后面多一个看不见的空格就会失效，报一个莫名其妙的错。而括号（包括 `()`、`[]`、`{}`）里面的换行是 Python 天然支持的，写起来也更清楚。

**顺便注意 `"小红",` 后面那个多余的逗号**——Python 允许最后一项后面带逗号，这不是错误。它的好处是以后加一项时只需加一行，不用改动上一行（版本对比时能少一行改动）。

> **记住这条**：**一行一句、不写分号；要换行就用括号，别用反斜杠。**

## 2.5 命名规范与关键字

变量、函数的名字（专业说法叫**标识符**）有硬规则和软约定两层。

### 硬规则：违反就报错

**示例 2-9　三种非法命名**

```python
2name = 5
```

```text
  File "bug.py", line 1
    2name = 5
    ^
SyntaxError: invalid decimal literal
```

不能以数字开头。报错说 `invalid decimal literal`（无效的十进制数字）——因为 Python 看到 `2` 开头就以为你要写一个数字，结果后面跟了字母。

```python
user-age = 18
```

```text
  File "bug.py", line 1
    user-age = 18
    ^^^^^^^^
SyntaxError: cannot assign to expression here. Maybe you meant '==' instead of '='?
```

不能用减号。因为 `-` 是减法运算符，Python 把 `user-age` 理解成了"user 减 age"这个表达式，而表达式不能被赋值。

```python
class = 1
```

```text
  File "bug.py", line 1
    class = 1
          ^
SyntaxError: invalid syntax
```

`class` 是**关键字**，被语言本身占用了。

**硬规则总结**：

| 规则 | 合法 | 非法 |
|---|---|---|
| 只能用字母、数字、下划线 | `user_age`、`age2` | `user-age`、`user age`、`用户#1` |
| 不能以数字开头 | `age2` | `2age` |
| 不能是关键字 | `class_name`、`klass` | `class`、`for`、`import` |
| 区分大小写 | `age` 和 `Age` 是两个变量 | —— |

### 35 个关键字

**示例 2-10　查一查哪些词不能用**

```python
import keyword                    # 引入一个标准库；import 的完整用法见第 18 章

print(len(keyword.kwlist))        # => 35
print(keyword.kwlist)
```

```text
35
['False', 'None', 'True', 'and', 'as', 'assert', 'async', 'await', 'break', 'class', 'continue', 'def', 'del', 'elif', 'else', 'except', 'finally', 'for', 'from', 'global', 'if', 'import', 'in', 'is', 'lambda', 'nonlocal', 'not', 'or', 'pass', 'raise', 'return', 'try', 'while', 'with', 'yield']
```

**不用背这 35 个词**。它们大部分你后面都会学到，学到时自然就记住了。真正需要注意的是几个"看起来很适合当变量名"的：`class`、`from`、`import`、`is`、`in`、`lambda`、`global`、`pass`、`type`（注意 `type` 其实不是关键字，但它是内置函数，占用了也会出问题）。

**遇到冲突怎么办**：加下划线后缀，这是社区约定的做法：

```python
class_ = "三年二班"       # class 被占用，加下划线
type_ = "水果"            # type 是内置函数，同样避开
```

### 软约定：不违反不报错，但要遵守

| 约定 | 写法 | 反例 |
|---|---|---|
| 变量和函数用小写 + 下划线（**snake_case**） | `user_age`、`total_price` | `UserAge`、`totalprice` |
| 名字要能读懂 | `student_count` | `a1`、`n`、`data2`、`tmp` |
| 布尔值用 `is_` / `has_` 开头 | `is_valid`、`has_permission` | `flag`、`check` |
| 不要用中文 | `user_name` | `用户名`（**语法允许，但强烈不建议**） |

**中文变量名值得多说一句**：Python 3 确实允许 `用户名 = "小明"` 这样写，语法上完全合法。但不要这么做——输入法切换很痛苦、和别人的代码风格不一致、某些工具和终端处理会出问题。**注释和字符串里用中文没问题，标识符一律用英文。**

**关于"名字要能读懂"**，给一个具体对比：

```python
# ❌ 三个月后你自己都不知道这是什么
a = 88
b = 92
c = (a + b) / 2

# ✅ 代码自己说明了它在做什么
math_score = 88
chinese_score = 92
average = (math_score + chinese_score) / 2
```

写第二种多打了几十个字符，但省掉了以后读代码时的推理。**编程时间的大头花在读代码上，不是写代码上。**

> **记住这条**：**变量名用小写加下划线，取名要能读懂；和关键字冲突就加下划线后缀。**

## 2.6 读懂 Traceback

现在进入本章最重要的部分。

### 三行的 Traceback

**示例 2-11　读懂三行的 Traceback**

把下面代码存成 `bug.py`（注意第 3 行故意把 `name` 拼成了 `naem`）：

```python
name = "小明"
print("准备打招呼")
print(naem)
```

运行：

```text
准备打招呼
Traceback (most recent call last):
  File "bug.py", line 3, in <module>
    print(naem)
          ^^^^
NameError: name 'naem' is not defined
```

**从下往上读，一次读三样东西**：

**① 最后一行：是什么问题**

```text
NameError: name 'naem' is not defined
```

冒号前面是**异常类型**（`NameError`），后面是**具体原因**（有个叫 `naem` 的名字没定义过）。这一行永远是最重要的。

**② 倒数第二、三行：在哪里出的问题**

```text
  File "bug.py", line 3, in <module>
    print(naem)
          ^^^^
```

文件 `bug.py`、第 3 行。下面还把那一行代码原样打出来，并用 `^^^^` 精确指到了出问题的位置。

> `in <module>` 的意思是"在模块的最外层"，也就是不在任何函数里面。等你学了函数（第 14 章），这里会显示函数名。

**③ 第一行：固定套话**

```text
Traceback (most recent call last):
```

翻译是"回溯（最近一次调用在最后）"。**它是在提醒你：下面按调用顺序排列，最后一次调用在最下面。这就是为什么真正的错误信息永远在最下面。**

### 还有一个关键信息容易被忽略

注意输出的**第一行**是 `准备打招呼`——它被正常打印出来了。

这说明：**程序执行到第 3 行才崩，前两行已经正常跑完了。** 报错的位置就是程序停下的位置，之前的代码都生效了，之后的代码一行都没执行。

这个信息在排查复杂问题时非常有用——**看输出到哪儿断了，就知道程序走到哪一步。**

### 多层的 Traceback

上面的例子只有一层。实际用到标准库或第三方库时，Traceback 往往有好几层。

**示例 2-12　读懂多层的 Traceback**

```python
import json                       # 处理 JSON 数据的标准库，完整用法见第 17 章

print("开始解析")
json.loads("{bad}")               # 故意给一段格式错误的 JSON
```

```text
开始解析
Traceback (most recent call last):
  File "demo.py", line 4, in <module>
    json.loads("{bad}")
  File "/usr/lib/python3.12/json/__init__.py", line 346, in loads
    return _default_decoder.decode(s)
           ^^^^^^^^^^^^^^^^^^^^^^^^^^
  File "/usr/lib/python3.12/json/decoder.py", line 338, in decode
    obj, end = self.raw_decode(s, idx=_w(s, 0).end())
               ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  File "/usr/lib/python3.12/json/decoder.py", line 354, in raw_decode
    obj, end = self.scan_once(s, idx)
               ^^^^^^^^^^^^^^^^^^^^^^
json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
```

（`/usr/lib/python3.12/...` 这些路径在你的机器上会不一样，Windows 上大概是 `C:\Python312\Lib\json\...`。）

一下子四层，看着吓人。但处理方法很简单：

**只看属于你自己文件的那几行。**

```text
  File "demo.py", line 4, in <module>          ← 这是你的代码，看这行
    json.loads("{bad}")

  File ".../json/__init__.py", line 346        ← 这些是标准库内部，跳过
  File ".../json/decoder.py", line 338         ← 跳过
  File ".../json/decoder.py", line 354         ← 跳过

json.decoder.JSONDecodeError: Expecting ...    ← 最后一行，看这行
```

**为什么可以跳过库的部分**：标准库的代码是经过千万人验证的，出错概率极低。**99% 的情况是你传给它的数据或参数有问题**，而那个位置就在"属于你的那一行"。

所以读多层 Traceback 的套路是：

1. 看**最后一行**：什么错、什么原因
2. **从下往上**找第一个出现你自己文件名的行：错误的源头在这里
3. 中间那些库内部的行，**除非你在调试库本身，否则不用看**

本例的结论就很清楚了：`demo.py` 第 4 行传给 `json.loads` 的数据格式不对，而且错误信息还精确到了 `line 1 column 2`——第 2 个字符处应该有一个双引号包起来的属性名。

> **记住这条**：**Traceback 从下往上读。最后一行说"什么错"，往上找到你自己的文件名那行说"哪里错"，中间的库内部调用跳过不看。**

## 2.7 十个必认报错

**示例 2-13　十个报错速认**

下面每一行都会触发一种报错。**建议一个个真的敲一遍**，看到十次红字之后，你对报错的恐惧就没了。

```python
print(abc)                  # NameError: name 'abc' is not defined
print("年龄" + 18)           # TypeError: can only concatenate str (not "int") to str
int("abc")                  # ValueError: invalid literal for int() with base 10: 'abc'
print([1, 2, 3][5])         # IndexError: list index out of range
print({"a": 1}["b"])        # KeyError: 'b'
"hello".push("x")           # AttributeError: 'str' object has no attribute 'push'
print(10 / 0)               # ZeroDivisionError: division by zero
import nosuchmodule         # ModuleNotFoundError: No module named 'nosuchmodule'
```

加上前面见过的 `SyntaxError` 和 `IndentationError`，就是十个。**把它们的含义整理成一张表**：

| 报错 | 通常意味着 | 第一步该做什么 | 详见 |
|---|---|---|---|
| `SyntaxError` | 语法写错了（缺冒号、括号不配对、用了中文标点） | 看报错指的那一行和**它的上一行** | 本章 2.8 |
| `IndentationError` | 缩进不对 | 检查冒号后面有没有缩进、同块是否对齐 | 本章 2.2 |
| `TabError` | Tab 和空格混用 | 设置编辑器"Tab 转空格" | 本章 2.2 |
| `NameError` | 用了一个不存在的名字 | 检查拼写；检查是不是忘了赋值 | 第 3 章 |
| `TypeError` | 类型不匹配（拿字符串和数字相加之类） | 用 `type()` 看看它到底是什么类型 | 第 3 章 |
| `ValueError` | 类型对但值不合法（`int("abc")`） | 检查数据来源，用 `try` 处理 | 第 15 章 |
| `IndexError` | 下标超出范围 | 检查 `len()`，注意下标从 0 开始 | 第 9 章 |
| `KeyError` | 字典里没有这个键 | 改用 `.get()`，或先判断键在不在 | 第 11 章 |
| `AttributeError` | 这个对象没有这个方法/属性 | 检查拼写；检查对象类型对不对 | 第 26 章 |
| `ZeroDivisionError` | 除数是 0 | 除之前判断一下 | 第 4 章 |
| `ModuleNotFoundError` | 找不到这个库 | `pip install`；检查解释器选对了没（1.6） | 第 18 章 |

**注意其中三个的区别，它们最容易搞混**：

```python
int("abc")     # ValueError —— 类型对（都是字符串），但这个值转不成数字
int([1, 2])    # TypeError  —— 类型就不对，列表根本不能转成整数
```

```python
"hello".upper()    # ✅ 字符串有 upper 方法
"hello".push("x")  # AttributeError —— 字符串没有 push 这个方法（那是 JavaScript 的）
```

**`AttributeError` 有个非常常见的变体**，现在提前打个招呼：

```python
name = None
print(name.upper())    # AttributeError: 'NoneType' object has no attribute 'upper'
```

看到 `'NoneType' object has no attribute ...`，几乎总是同一个原因：**你以为某个变量有值，实际它是 `None`**。这个错误在真实项目里出现的频率极高（函数忘了 `return`、字典取值取到了 `None`），第 3 章和第 14 章都会再遇到。

### 两大类报错的根本区别

| | 语法错误 | 运行时异常 |
|---|---|---|
| 代表 | `SyntaxError`、`IndentationError`、`TabError` | 其余全部 |
| 什么时候发现 | Python **读**代码的时候 | 程序**跑到那一行**的时候 |
| 前面的代码执行了吗 | **一行都没执行** | 执行了 |
| 怎么区分 | 输出里**没有** `Traceback` 那行套话 | 输出以 `Traceback (most recent call last):` 开头 |

**这个区分很实用**：如果你的程序连第一行 `print` 都没输出就报错了，那必然是语法错误——**去找拼写和标点，不用怀疑逻辑**。

## 2.8 排错的基本套路

### 语法错误优先

**示例 2-14　修好一段有三处错误的代码**

下面这段代码有三处错误。存成 `calc.py`：

```python
Print("开始计算")
total = 19.9 * 2
  print("总价是", total)
print("结束"
```

**第一次运行**：

```text
  File "calc.py", line 3
    print("总价是", total)
IndentationError: unexpected indent
```

只报了缩进错误。注意——`开始计算` **没有被打印出来**，尽管第 1 行看起来能跑。这印证了 2.7 的结论：**语法错误会让整个文件解析不过，一行都不执行。**

**改第一处**（去掉第 3 行多余的缩进），重新运行：

```text
  File "calc.py", line 4
    print("结束"
         ^
SyntaxError: '(' was never closed
```

新的错误暴露出来了：第 4 行的括号没闭合。**Python 一次只报第一个语法错误**，所以要一个一个修。

**改第二处**（补上右括号），重新运行：

```text
Traceback (most recent call last):
  File "calc.py", line 1, in <module>
    Print("开始计算")
    ^^^^^
NameError: name 'Print' is not defined. Did you mean: 'print'?
```

变化很关键：**这次开头有 `Traceback` 了**，说明语法问题全解决了，现在是运行时异常。而且 Python 直接建议了 `Did you mean: 'print'?`。

**改第三处**（`Print` 改小写），运行：

```text
开始计算
总价是 39.8
结束
```

三步修完。**整个过程的节奏是本节的重点**：

| 步骤 | 报错 | 类型 | 得到的信息 |
|---|---|---|---|
| 1 | `IndentationError` line 3 | 语法 | 一行都没执行 |
| 2 | `SyntaxError` line 4 | 语法 | 上一个修好了，露出下一个 |
| 3 | `NameError` line 1 | 运行时 | 语法全对了，开始真正执行 |
| 4 | 无 | —— | 完成 |

### 四条排错纪律

**① 一次只改一处，改完立刻重跑。**
不要盯着报错一次改五个地方。你以为的另外四个"错"可能根本不是错，改了反而引入新问题。而且改一处跑一次，你能确切知道每个报错对应哪个原因。

**② 语法错误从报错行和它的上一行找。**
语法错误的报错位置有时会偏——因为 Python 是读到"不合语法"的地方才发现问题，而根源可能在上一行（比如上一行括号没闭合）。**先看报错行，没问题就看上一行。**

**③ 报错文字读完整，尤其最后一行。**
不要只看到红色就慌。`NameError: name 'naem' is not defined` 这一行已经把答案写出来了。

**④ 删到最小可复现。**
如果一段代码怎么都看不出问题，**把它删到只剩能复现错误的那几行**。一半的情况下，删的过程中你就发现原因了。

### 顺便说：升级 Python 能少踩坑

**示例 2-15　同一个错误，新旧版本的报错差别**

还是那段括号没闭合的代码：

```python
print("a"
print("b")
```

**Python 3.9 的报错**：

```text
  File "paren.py", line 2
    print("b")
    ^
SyntaxError: invalid syntax
```

它指着**第 2 行**说"语法错误"——可第 2 行明明是完全正确的一行代码！真正的问题在第 1 行。这就是老版本让人抓狂的地方，也是"语法错误要看上一行"这条经验的来源。

**Python 3.12 的报错**：

```text
  File "paren.py", line 1
    print("a"
         ^
SyntaxError: '(' was never closed
```

直接指着**第 1 行**说"这个括号从来没有闭合过"。位置准确、原因明确。

**这就是为什么本教程建议用 3.10 以上版本**：3.10、3.11、3.12 这几个版本在报错信息上做了大量改进——更准确的位置、`^^^^` 精确标记、`Did you mean` 建议。**对新手来说，这些改进的价值比任何新语法都大。**

> **记住这条**：**一次只改一处、改完就跑；语法错误看报错行和上一行；报错文字读到最后一行。**

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| `Print("hi")` | `NameError: name 'Print' is not defined` | 全小写 `print` | Python 区分大小写 |
| `true` / `false` / `none` | `NameError` | `True` / `False` / `None` | 首字母必须大写 |
| 冒号后面没缩进 | `IndentationError: expected an indented block` | 下一行缩进 4 空格 | 冒号表示"下面有一个块" |
| 同块缩进不一致 | `IndentationError: unexpected indent` | 统一 4 空格 | 缩进决定归属 |
| Tab 和空格混用 | `TabError: inconsistent use of tabs` | 编辑器设"Tab 转空格" | 两者是不同字符 |
| 用了中文全角引号 `“”` | `SyntaxError: invalid character '“' (U+201C)` | 切英文半角输入法 | 中文输入法自动转全角 |
| `if True` 忘了冒号 | `SyntaxError: expected ':'` | 补冒号 | —— |
| `2name = 5` | `SyntaxError: invalid decimal literal` | 改成 `name2` | 不能数字开头 |
| `user-age = 18` | `SyntaxError: cannot assign to expression here` | 改成 `user_age` | `-` 是减号 |
| `class = 1` | `SyntaxError: invalid syntax` | 改成 `class_` | 是关键字 |
| 反斜杠续行后面多了空格 | `SyntaxError` 且看不出原因 | 改用括号换行 | `\` 后不能有任何字符 |
| 只看报错第一行 | 抓不到真正原因 | **从最后一行往上读** | 关键信息在末尾 |
| 看到红字就整段重写 | 浪费时间，同样的错还会犯 | 读报错，一次改一处 | 报错已给出答案 |
| 一次改五个地方 | 引入新问题，分不清因果 | 改一处跑一次 | —— |

## 本章小结

- `print` 是函数、括号表示调用、引号区分"文本"和"名字"；**Python 严格区分大小写**
- **缩进是语法**，不是排版：冒号结尾的下一行必须缩进，统一 4 个空格，**Tab 和空格绝不混用**
- 注释用 `#`，**解释"为什么"而不是"是什么"**；三引号其实是字符串
- 一行一句、不写分号；换行**用括号不用反斜杠**
- 命名用 `snake_case`，不能数字开头、不能用关键字、**取名要能读懂**
- **Traceback 从下往上读**：最后一行说什么错，往上找自己的文件名说哪里错，中间的库内部跳过
- 语法错误让**整个文件一行都不执行**；有 `Traceback` 开头的才是运行时异常
- 排错纪律：**一次只改一处、改完就跑**、语法错误看报错行和上一行

| 报错 | 一句话原因 |
|---|---|
| `SyntaxError` | 语法写错（标点、括号、缺冒号） |
| `IndentationError` / `TabError` | 缩进问题 |
| `NameError` | 名字不存在（拼错、没赋值） |
| `TypeError` | 类型不匹配 |
| `ValueError` | 类型对、值不合法 |
| `IndexError` | 下标越界 |
| `KeyError` | 字典没这个键 |
| `AttributeError` | 对象没这个方法（`'NoneType' object has no attribute` = 变量其实是 None） |
| `ZeroDivisionError` | 除数为 0 |
