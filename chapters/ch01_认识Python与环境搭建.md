## 开篇：为什么这一章不能跳过

很多人学编程失败，不是败在语法上，是败在**第一天**。

装完 Python，命令行敲 `python` 说"不是内部或外部命令"；文件明明存进去了，运行却说"找不到文件"；照着教程装了个库，代码里 `import` 还是报红。这些问题都跟编程本身毫无关系，但它们能耗掉一个新手整个周末，然后让人得出结论"我可能不适合编程"。

## 1.1 Python 是什么

**一句话**：Python 是一门**解释型**编程语言，同时也指一个叫 `python` 的程序。

这两件事要分清楚，很多混乱都来自把它们混为一谈：

| 说"Python"时可能指 | 具体是什么 |
|---|---|
| 语言 | 一套语法规则，比如"缩进表示代码块" |
| **解释器** | 你电脑上一个真实存在的程序（Windows 上是 `python.exe`），负责读你的代码并执行 |
| 生态 | 几十万个能装来用的第三方库 |

**"解释型"是什么意思**：你写完代码，直接交给解释器运行，**不需要先编译**。

```text
C# / Java 的流程：  写代码 → 编译成 exe/class → 运行
Python 的流程：     写代码 → 直接运行
```

**为什么这件事对你有好处**：改一行代码，立刻就能看结果。学习阶段这一点极其重要——你可以疯狂试错，每次试错的成本只有一次回车。

**代价也要说清楚**：少了编译这一步，很多错误就不会提前被发现，只有真正跑到那一行才暴露。比如你把变量名拼错了，C# 编译时就会拦住你，Python 要等程序跑到那里才报错（第 2 章会专门教怎么读这种报错）。

**`.py` 文件就是纯文本**。用记事本能打开，用记事本也能写。它没有任何魔法，就是一个文本文件，只不过里面的内容符合 Python 的语法规则。

> **记住这条**：**你安装的是"解释器"这个程序，你写的是"文本文件"，解释器读文本文件然后执行。** 想清楚这个关系，后面"为什么找不到 python 命令""为什么装了库还是不能用"这些问题就都有了答案。

## 1.2 为什么只学 Python 3

Python 有两个大版本，**Python 2 已经在 2020 年 1 月 1 日正式停止维护**。它不再有任何更新，包括安全更新。

**你唯一需要关心 Python 2 的场合**：在网上抄代码的时候。搜索"python 教程"仍然会搜到大量 2010 年前后的内容，照抄会直接报错。

**一眼识别 Python 2 代码的三个信号**：

| 信号 | Python 2 写法 | Python 3 写法 |
|---|---|---|
| `print` 没有括号 | `print "hello"` | `print("hello")` |
| 输入函数名 | `raw_input()` | `input()` |
| 整数除法 | `3 / 2` 得 `1` | `3 / 2` 得 `1.5` |

看到 `print "hello"` 这种写法，直接换一篇教程看，别试图修。

> **记住这条**：**`print` 后面没括号的代码，是十年前的，别抄。**

## 1.3 Python 能做什么，不适合做什么

新手容易走两个极端：以为 Python 什么都能干，或者以为它只能写点小脚本。都不对。

**它擅长的**：

| 方向 | 典型任务 | 本教程覆盖 |
|---|---|---|
| 自动化脚本 | 批量重命名文件、定时抓数据、整理 Excel | 阶段一、二（验收项目 B） |
| 数据处理与分析 | 清洗数据、算统计指标、出报表 | 阶段二、三 + 工具箱 T4 |
| Web 后端 | 提供接口给前端/App 调用 | 专项 D |
| 人工智能 | 几乎所有 AI 框架的首选语言 | 只做导览（T4） |
| 胶水层 | 把几个现成的系统/工具串起来 | 阶段三 |

**它不擅长的**：

| 方向 | 为什么不适合 | 通常用什么 |
|---|---|---|
| 手机 App | 生态不成熟，打包体积大 | Swift / Kotlin / Flutter |
| 高性能游戏、3D 引擎 | 运算速度不够 | C++ / C# |
| 对启动速度敏感的小工具 | 解释器启动本身要几十毫秒 | Go / Rust |
| 浏览器里跑的前端 | 浏览器只认 JavaScript | JavaScript / TypeScript |

**一句实话**：**Python 确实慢**，比 C++ 慢一到两个数量级。但对绝大多数任务来说，瓶颈根本不在语言上——你的脚本花 3 秒读文件、0.01 秒计算，换成 C++ 也还是要花 3 秒读文件。**先把事情做对，需要时再谈快**（第 40 章会讲怎么判断"需要时"）。

## 1.4 安装 Python

### 下载

去 **python.org** 官网下载，选最新的稳定版（本教程按 **3.10 及以上**编写，推荐装 3.12 或 3.13）。

**不要**从应用商店、软件管家、第三方下载站装——这些渠道装的版本可能很老，或者路径很奇怪，后面装库会出问题。

### Windows：一个必须勾的选项

安装界面第一屏最下面有一个复选框：

```text
☑ Add python.exe to PATH        ← 必须勾上！
```

**这个框默认是不勾的，而它是新手第一大坑的来源。**

**为什么必须勾**：勾了它，你在任何目录下敲 `python` 都能找到解释器；不勾，命令行会告诉你"不是内部或外部命令"。

**如果已经装完才发现没勾**：不用手工改环境变量（容易改错），最省事的办法是重新运行安装包，选 Modify 或者直接卸载重装，把框勾上。

### macOS / Linux：别用系统自带的

系统自带的 Python 版本通常很旧（有些 macOS 版本自带的还是 2.x），而且改动它可能影响系统工具。

- **macOS**：官网下载安装包，或者用 Homebrew：`brew install python`
- **Linux**：多数发行版自带 3.x，但版本可能偏旧；确认版本后按需用包管理器升级

### 验证安装

**示例 1-1　确认自己装的是哪个版本**

打开命令行（Windows 是 PowerShell 或 cmd，macOS 是终端），输入：

```bash
python --version
```

看到版本号就说明装好了：

```text
Python 3.12.4
```

> 我写这一章时用的环境显示 `Python 3.9.25`，你装的应该是 3.12 或 3.13，**版本号不一样是正常的**。本章内容在 3.9~3.13 上表现完全一致。

**如果报错**，按下面这张表对号入座：

| 症状 | 原因 | 解法 |
|---|---|---|
| `'python' 不是内部或外部命令` | 装的时候没勾 PATH | 重装并勾选，或改用 `py --version` |
| 显示 `Python 2.7.x` | 系统里有多个版本，`python` 指向了旧的 | Windows 用 `py -3 --version`；macOS/Linux 用 `python3 --version` |
| 命令行里什么都没显示就换行了 | 极少见，通常是 PATH 里有残留的坏路径 | 重启命令行窗口再试 |

**Windows 用户额外知道一件事**：装 Python 时还会附带一个 `py` 命令（叫 Python Launcher）。它比 `python` 更可靠——即使 PATH 有问题，`py` 通常也能用，而且能指定版本：

```bash
py --version          # 用默认版本
py -3.12 --version    # 明确用 3.12
```

> **记住这条**：**装完第一件事就是 `python --version`。** 这一步没通过，后面全部白搭，不要往下走。

## 1.5 三种运行方式

代码写好了要怎么跑？有三种方式，各有各的场合。**这三种你都要会**，之后每一章都会用到。

### 方式一：REPL（交互式解释器）

在命令行直接输入 `python` 并回车，你会进入这样一个界面：

**示例 1-2　把 REPL 当计算器用**

```text
Python 3.9.25 (main, Jul  6 2026, 00:00:00)
[GCC 11.5.0] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>> 2 + 3
5
>>> 19.9 * 2
39.8
>>> print("hi")
hi
>>> exit()
```

`>>>` 是提示符，表示"等着你输入"。输入一个表达式回车，**它立刻把结果显示出来**。

**REPL 是干什么用的**：验证一个想法。"字符串能不能直接相乘？""这个函数返回什么？"——不用建文件、不用保存，敲一行就知道答案。**本教程里所有 A 段的短示例，都建议你在 REPL 里敲一遍。**

**退出方式**：输入 `exit()` 回车，或者按 `Ctrl+D`（Windows 上是 `Ctrl+Z` 再回车）。

**REPL 的局限**：代码不保存，关了就没了；写超过几行的代码很难受（改一行要重敲整段）。

### 方式二：运行脚本文件（最常用）

**示例 1-3　第一个脚本**

用编辑器新建一个文件，命名为 `hello.py`，内容一行：

```python
print("Hello, Python!")
```

保存。然后在命令行**先切换到文件所在的目录**，再运行它：

```bash
cd C:\code           # Windows：切换到文件所在目录（换成你自己的路径）
python hello.py
```

```text
Hello, Python!
```

**这里有两个新手必踩的坑**：

**坑一：文件名变成了 `hello.py.txt`**

如果你用记事本保存，Windows 会悄悄在后面加 `.txt`。症状是运行时报：

```text
python: can't open file 'hello.py': [Errno 2] No such file or directory
```

**解法**：在文件资源管理器里打开"查看 → 显示 → 文件扩展名"，就能看到真实文件名；另存时"文件类型"选"所有文件"。**更好的解法是别用记事本**，见 1.6。

**坑二：忘了 `cd` 到文件所在目录**

`python hello.py` 里的 `hello.py` 是**相对路径**，意思是"当前目录下的 hello.py"。如果你的命令行当前在 `C:\Users\你`，而文件在 `C:\code`，就找不到。报错和上面一样。

**解法**：`cd` 到正确目录再运行。或者写完整路径：`python C:\code\hello.py`。

### 三种方式的关键区别

**示例 1-4　REPL 和脚本的关键区别**（样板示例）

这是本章最重要的一个认知，很多人卡在这里而不知道自己卡住了。

在 REPL 里输入 `2 + 3`，立刻看到结果：

```text
>>> 2 + 3
5
```

把**完全相同的一行**写进 `test.py` 文件：

```python
2 + 3
```

运行它，**屏幕上什么都没有**：

```bash
python test.py
```

```text
```

（是的，就是空的，一个字符都没输出。）

**为什么？** 因为这是两种不同的工作模式：

| | REPL | 脚本 |
|---|---|---|
| 每个表达式的结果 | **自动显示**（这叫"回显"） | **不显示**，除非你明确要求 |
| 设计目的 | 让你随手做实验 | 老老实实执行你写的指令 |

REPL 会自动把结果显示出来，是为了方便你做实验。脚本不会——它只做你**明确要求**的事。想看到结果，必须用 `print` 说出来：

```python
print(2 + 3)      # => 5
```

> **记住这条**：**以后你写脚本发现"程序跑完了却什么都没输出"，第一个要检查的就是——忘了 `print`。**
>
> 这个坑在学习阶段会反复出现。你在 REPL 里试得好好的代码，复制到脚本里就"没反应"了，原因几乎总是这个。

### 方式三：Jupyter Notebook（适合学习和实验）

**示例 1-5　在 Jupyter 里分段执行**

先安装（需要联网）：

```bash
pip install notebook
```

启动：

```bash
jupyter notebook
```

它会自动打开浏览器。新建一个 Notebook，你会看到一个个的输入框，叫 **Cell**。在第一个 Cell 里写：

```python
name = "小明"
age = 18
```

按 **Shift+Enter** 执行。然后在第二个 Cell 里写：

```python
print(name, age)
```

再按 Shift+Enter：

```text
小明 18
```

**关键点：第一个 Cell 定义的变量，在第二个 Cell 里还活着。** 这就是 Jupyter 最大的价值——你可以把一个长过程拆成好几段，**每段执行完，中间结果都留在内存里**，随时可以查看、可以只重跑其中一段。

**为什么这对学习特别有用**：读到第 9 章列表的时候，你可以第一个 Cell 造一份数据，然后在后面的 Cell 里一个个试各种方法，数据不用反复重建。改错了只重跑那一个 Cell 就行。

**Jupyter 的局限**：Cell 的执行顺序可以乱来（你可以先跑第 3 个再跑第 1 个），容易产生"在我这儿能跑，重启就崩"的混乱状态。**所以它适合探索和学习，不适合交付程序**——真正的程序要写成 `.py` 文件。

### 三种方式怎么选

| 场景 | 用什么 |
|---|---|
| 验证一行代码、查一个函数返回什么 | **REPL** |
| 学习新章节、一步步试验、需要保留中间数据 | **Jupyter** |
| 写真正要用的程序、要交给别人的东西 | **脚本 `.py`** |

**本教程的建议**：阶段一（第 1~15 章）跟着例子学时用 Jupyter 或 REPL，做验收项目时用脚本。到了阶段二，全部用脚本。

### 走一遍完整流程

**示例 1-6　让 print 算一笔账**

`print` 里面可以直接放算式：

```python
print(19.9 * 2)      # => 39.8
```

**示例 1-7　连续多个 print 输出一张名片**

```python
print("姓名：小明")
print("职位：工程师")
print()                    # 空的 print() 打一个空行
print("电话：13800138000")
```

```text
姓名：小明
职位：工程师

电话：13800138000
```

代码**从上往下依次执行**，`print` 一个接一个输出。空的 `print()` 输出一个空行——它其实是"零个参数 + 默认换行"。

**示例 1-8　打印一张购物小票**

现在把上面这些拼成一个完整的小程序，走一遍"编辑 → 保存 → 运行"的全流程。新建 `receipt.py`：

```python
# 这一章还没讲变量和格式化，所以先用最笨的方式：内容直接写进 print
# 第 3 章学了变量、第 5 章学了 f-string 之后，这段代码会被大幅简化

print("=" * 28)                          # "=" * 28 表示把等号重复 28 次，用来画分隔线
print("        小明便利店")
print("=" * 28)
print("矿泉水   2.5 x 3 =", 2.5 * 3)      # print 里逗号分隔的多项，输出时会用空格连起来
print("面包     6.0 x 2 =", 6.0 * 2)
print("鸡蛋    12.8 x 1 =", 12.8 * 1)
print("-" * 28)
print("合计：", 2.5 * 3 + 6.0 * 2 + 12.8 * 1)
print("=" * 28)
print("谢谢光临，欢迎再来")
```

运行 `python receipt.py`：

```text
============================
        小明便利店
============================
矿泉水   2.5 x 3 = 7.5
面包     6.0 x 2 = 12.0
鸡蛋    12.8 x 1 = 12.8
----------------------------
合计： 32.3
============================
谢谢光临，欢迎再来
```

**跑通这个，说明你的环境完全正常。**

顺便注意两个细节，它们是后面章节的伏笔：

1. **`"=" * 28`**——字符串居然能乘数字，结果是重复 28 遍。这不是笔误，第 5 章会讲。
2. **`12.8 * 1` 输出的是 `12.8`，而 `6.0 * 2` 输出的是 `12.0`** 而不是 `12`。小数点后的 `.0` 没有消失——Python 里"整数"和"小数"是两种不同的东西，第 3 章会讲清楚。

### 报错第一课

**示例 1-9　故意打错字看报错**

新手看到红色报错就慌，这没必要。报错是**Python 在告诉你哪里出了问题**，读它比重写代码快得多。

故意把 `print` 拼错，存成 `bug.py`：

```python
pirnt("hi")
```

运行：

```text
Traceback (most recent call last):
  File "bug.py", line 1, in <module>
    pirnt("hi")
NameError: name 'pirnt' is not defined
```

三行信息，**最后一行最重要**：`name 'pirnt' is not defined`——有个叫 `pirnt` 的名字没定义过。中间那行告诉你位置：`bug.py` 第 1 行。

> 如果你装的是 **Python 3.12 或更新版本**，报错还会多一行贴心的提示：`Did you mean: 'print'?`（你是想写 print 吗？）。老版本没有这个提示，但错误信息是一样的。

**报错不可怕，可怕的是不读它。** 第 2 章会专门教你怎么读报错，那是整本书里最先用得上、最省时间的技能。

## 1.6 选一个编辑器

理论上记事本就能写 Python。实际上**别用记事本**，两个原因：它会偷偷给文件加 `.txt`，而且它不显示缩进——而 Python 靠缩进决定代码结构（第 2 章会讲），缩进错了程序就跑不了，用记事本你连错在哪都看不见。

两个推荐选择：

| 编辑器 | 特点 | 适合 |
|---|---|---|
| **VS Code** | 轻量、免费、装个 Python 扩展就够用 | 大多数人，本教程推荐 |
| **PyCharm 社区版** | 功能强大、开箱即用、免费 | 喜欢"什么都配好了"的人 |

### VS Code 的最小配置

1. 装 VS Code
2. 左侧扩展面板搜 `Python`，装微软官方那个（作者显示 Microsoft）
3. **选择解释器**：按 `Ctrl+Shift+P`，输入 `Python: Select Interpreter`，从列表里选你刚装的那个版本

### 新手第一大坑：解释器选错了

**症状**：命令行里 `pip install requests` 明明成功了，VS Code 里 `import requests` 却报 `ModuleNotFoundError: No module named 'requests'`。

**原因**：你的电脑里可能有多个 Python（系统自带的、你装的、Anaconda 带的……）。`pip` 把库装到了 A 里，而 VS Code 用的是 B。**B 里当然没有这个库。**

**怎么确认**：在代码里加两行，看它到底用的是哪个解释器：

```python
import sys
print(sys.executable)     # 打印出当前正在运行的 python 程序的完整路径
```

把这个路径和 VS Code 右下角显示的解释器路径对比一下，就知道对不对得上了。

**解法**：重新执行 `Python: Select Interpreter`，选到你 `pip install` 用的那个环境。到了第 19 章学了虚拟环境，这个问题会有更彻底的解决办法——**每个项目一个独立环境，就不会搞混了**。

> **记住这条**：**`ModuleNotFoundError` 但你确信装过这个库时，99% 是"装库的 Python"和"跑代码的 Python"不是同一个。**

## 1.7 用 pip 安装第三方库

### 标准库和第三方库

| 类型 | 说明 | 例子 |
|---|---|---|
| **标准库** | 装 Python 就自带，直接 `import` 就能用 | `os`、`json`、`datetime`、`re` |
| **第三方库** | 别人写的，要先装 | `requests`、`pandas`、`numpy` |

判断办法：`import` 一下，报 `ModuleNotFoundError` 的就是没装的第三方库。

### 装一个库，立刻获得新能力

**示例 1-10　三行代码访问一个网站**

先装 `requests`（Python 最流行的网络请求库）：

```bash
pip install requests
```

```text
Successfully installed requests-2.32.5
```

然后新建 `net.py`：

```python
import requests                                      # 把刚装的库拿进来用

r = requests.get("https://www.python.org", timeout=10)   # 访问网站；timeout 防止一直卡着
print(r.status_code)                                  # 打印 HTTP 状态码，200 表示正常
```

```text
200
```

**三行代码就访问了一个网站。** 这就是"装库 = 扩展能力"的直观体验——你不需要懂 HTTP 协议怎么实现，别人已经写好了。

> **看到 200 说明成功。** 如果看到别的数字或者报错，通常是网络问题（公司网络、代理、防火墙），不是代码问题。这个例子只为体验一下，跑不通不影响后面学习。

### 看看自己装了什么

**示例 1-11　pip 的三个常用命令**

```bash
pip list                  # 列出所有已安装的库
pip show requests         # 看某个库的详细信息
pip uninstall requests    # 卸载
```

`pip show` 的输出长这样：

```text
Name: requests
Version: 2.32.5
Summary: Python HTTP for Humans.
Home-page: https://requests.readthedocs.io
Location: /usr/lib/python3.9/site-packages
```

**`Location` 那一行很有用**——它告诉你库被装到了哪个目录。1.6 节那个"装了库还是 import 失败"的问题，就是靠对比这个路径来诊断的。

### 国内网络慢的解决办法

`pip install` 默认从国外服务器下载，国内可能很慢或超时。临时换源：

```bash
pip install requests -i https://pypi.tuna.tsinghua.edu.cn/simple
```

永久换源（只需执行一次）：

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

> **记住这条**：**装库用 `pip install`，慢就加 `-i` 换源，装完用 `pip show` 确认装到哪了。**

## 1.8 怎么用这本教程

### 三条硬规矩

**① 所有代码自己敲一遍，不要复制粘贴。**
手指记住的语法比眼睛记住的牢十倍。而且抄的过程中你会打错字，打错字就会看到报错，看报错就是在练最重要的技能。

**② 每章的"易错点"要故意错一次。**
本教程每章末尾都有一张易错点表。**照着它把错误写出来，亲眼看到那个报错。** 下次真遇到时，你会认出它。只读不试，等于没看。

**③ 阶段验收项目必须做完。**
三个阶段各有一个项目。做不出来说明前面没真会，回头补，不要往下推进。**看懂了和写得出来是两件事。**

### 卡住了怎么办

按这个顺序做，别乱：

1. **把报错完整读一遍**——尤其最后一行（第 2 章教怎么读）
2. **打印中间结果**——`print` 出可疑的变量，看它到底是什么值
3. **查本章的易错点表**——大概率你踩的是已知的坑
4. **把代码删到最小**——只留能复现问题的那几行。一半情况下删的过程中就找到原因了

<details>
<summary><b>给有 C# / Java / SQL 经验的读者</b></summary>

几个会让你不适应的地方，提前打个招呼：

| 你习惯的 | Python 的做法 |
|---|---|
| 编译期就能发现变量名拼错 | 运行到那一行才报错（`NameError`） |
| `{}` 表示代码块 | **缩进**表示代码块，缩进错了就是语法错误 |
| 变量要声明类型 | 不用声明，`x = 1` 直接就用（第 3 章） |
| 每行结尾加分号 | 不加，一行一句（第 2 章） |
| `Console.WriteLine()` / `System.out.println()` | `print()` |
| 项目要有 `Main` 方法作为入口 | 脚本从第一行开始往下执行（第 18 章会讲 `if __name__ == "__main__"`） |
| 装包用 NuGet / Maven | 用 `pip`（第 19 章讲虚拟环境隔离） |

**一个心理准备**：Python 会让你觉得"这么随便真的没问题吗"。很多编译器帮你挡住的错误，Python 要靠你自己写测试（第 36 章）和类型注解（第 33 章）来挡。这是它换取灵活性的代价。

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| Windows 装完找不到 python | `'python' 不是内部或外部命令` | 重装勾选 Add to PATH，或改用 `py` | PATH 没配置 |
| 用记事本存成 `hello.py.txt` | `can't open file 'hello.py'` | 打开"显示文件扩展名"，另存选"所有文件" | 记事本默认追加 `.txt` |
| 在错误的目录运行脚本 | `No such file or directory` | 先 `cd` 到脚本所在目录 | 用的是相对路径 |
| 脚本里写 `2 + 3` 期待看到结果 | 什么都不输出 | 用 `print(2 + 3)` | 脚本不回显表达式结果 |
| 代码里用了中文全角引号 `“”` | `SyntaxError: invalid character` | 切换到英文半角输入法 | 中文输入法自动转全角 |
| VS Code 里 `import` 装好的库失败 | `ModuleNotFoundError` | 重新选解释器，选到 pip 装库的那个 | 装库和跑代码的不是同一个 Python |
| 在 REPL 里粘贴多行代码 | `IndentationError` 或只执行了一部分 | 多行代码写进 `.py` 文件或 Jupyter | REPL 对空行和缩进敏感 |
| 看到报错就整段删掉重写 | 浪费时间，同样的错还会再犯 | 先读最后一行错误信息 | 报错已经告诉你原因了 |

## 本章小结

- Python 是**解释型**语言，写完直接运行，不用编译；你装的 `python` 是**解释器程序**，`.py` 是**纯文本文件**
- **只学 Python 3**；看到 `print "hello"`（没括号）就知道是过时代码
- Windows 安装时**必须勾选 Add python.exe to PATH**，装完第一件事是 `python --version`
- 三种运行方式：**REPL** 验证单行、**Jupyter** 学习实验、**脚本** 写真正的程序
- **脚本不会自动显示表达式结果，必须用 `print`**——这是新手最常见的"程序没反应"
- 编辑器用 VS Code + Python 扩展，**注意选对解释器**，否则装了库也用不了
- 第三方库用 `pip install` 装，`pip show` 能看装到哪了

### 命令速查

| 命令 | 作用 |
|---|---|
| `python --version` | 查看版本（Windows 备用：`py --version`） |
| `python` | 进入 REPL；`exit()` 退出 |
| `python hello.py` | 运行脚本（需先 `cd` 到文件目录） |
| `pip install 库名` | 安装第三方库 |
| `pip install 库名 -i 镜像地址` | 从镜像源安装（国内更快） |
| `pip list` | 列出已安装的库 |
| `pip show 库名` | 查看库的版本和安装位置 |
| `jupyter notebook` | 启动 Jupyter |

### 代码速查

| 写法 | 作用 |
|---|---|
| `print("文字")` | 输出一行文字 |
| `print()` | 输出一个空行 |
| `print(2 + 3)` | 输出算式结果 |
| `print("a", "b")` | 输出多项，自动用空格连接 |
| `"=" * 28` | 把字符串重复 28 次 |
| `import 库名` | 引入一个库 |
