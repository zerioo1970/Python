## 开篇：代码开始重复了

到第 13 章为止，你能写出几十行干实事的脚本了。但如果回头看那些代码，会闻到一股味道不对的气息。

比如第 9 章算成绩，如果要算三个班的，很多人会这么干：

```python
# ❌ 一班
scores1 = [92, 85, 78]
total1 = sum(scores1)
print(f"总分 {total1}，平均 {total1 / len(scores1):.1f}")

# ❌ 二班——复制粘贴，改了变量名
scores2 = [88, 90, 76]
total2 = sum(scores2)
print(f"总分 {total2}，平均 {total2 / len(scores2):.1f}")

# ❌ 三班——再来一遍
scores3 = [65, 70, 82]
total3 = sum(scores3)
print(f"总分 {total3}，平均 {total3 / len(scores3):.1f}")
```

**问题不在于"多打了几个字"**，在于：

1. 要把"平均"改成保留两位小数 → **要改三处**，漏一处就出现两种格式
2. 要加一个"最高分" → **要加三处**
3. 三处里有一处手抖写成了 `len(scores1)` → **不报错，结果悄悄错了**

**函数就是解决这个的。** 但函数的价值远不止"少打字"，按重要性排是这三条：

| 价值 | 说明 |
|---|---|
| **① 给一段逻辑起个名字** | `calc_bmi(65, 1.75)` 比五行公式好读得多。**这是最重要的一条**——代码是给人看的 |
| ② 消除重复 | 改一处，所有调用点都受益 |
| ③ 能单独测试和替换 | 可以只测 `calc_bmi` 对不对，不必把整个程序跑一遍（第 29 章） |

**第 ① 条值得多说一句。** 很多人以为函数是"为了复用"，所以"只用一次的逻辑不值得写成函数"。这是错的——**哪怕只调用一次，把五行逻辑收成一个有名字的函数，也让代码好读得多**。名字本身就是文档。

本章是全书最重的章节之一。它有三处需要你格外用心：

- **14.8 可变默认值陷阱**——Python 最著名的坑，现象诡异原因简单
- **14.13 `UnboundLocalError`**——新手最困惑的报错之一
- **14.16 函数存进字典**——你会第一次感到"原来代码可以这样组织"

另外，第 13 章那个"传引用"的问题会以**第三种面貌**再出现一次（14.9）。到时候你应该能一眼看穿。

## 14.1 定义与调用

**示例 14-1　第一个函数**

```python
def greet():                # def = define（定义）；名字后面的括号不能省
    print("你好")            # 缩进的部分是【函数体】

greet()                     # 调用它：名字 + 括号
greet()                     # 想调用几次调用几次
# => 你好
# => 你好
```

**两个部分要分清**：

- `def greet():` 这一行执行时，**只是创建了这个函数**，函数体里的代码一行都不会跑
- `greet()` 这一行才**真正执行函数体**

**示例 14-7　调用必须写在定义后面**

```python
later()
# => NameError: name 'later' is not defined

def later():
    print("我在后面定义")
```

**为什么？** 因为 Python 是**从上往下执行**的。跑到 `later()` 那一行时，`def later` 还没被执行过，这个名字根本不存在。

这和 C# / Java **不一样**——那些语言的编译器会先扫一遍全文件，方法定义在哪都行。**Python 没有这一步**，`def` 就是一条普普通通的语句，执行到了才生效。

> **记住这条**：**先定义，后调用。** 习惯上把所有 `def` 放在文件上半部分，主流程放在下面。

**示例 14-2　带参数的函数**

```python
def greet(name):            # name 是【形参】：函数内部用的名字
    print(f"你好，{name}")

greet("小明")                # "小明" 是【实参】：调用时真正传进去的值
# => 你好，小明
```

**术语记一下就好**：括号里定义的叫**形参**（parameter），调用时传的叫**实参**（argument）。日常大家混着叫"参数"，不影响交流。

## 14.2 `return`：把结果交出来

**示例 14-3　用 return 交出结果**

```python
def add(a, b):
    return a + b            # 把结果交给【调用方】

print(add(2, 3))            # => 5
print(add(2, 3) * 10)       # => 50        返回值能直接参与运算
r = add(1, 1)               # 也能存进变量
print(r)                    # => 2
```

**`return` 和 `print` 完全是两回事**，这是本节的重点。

**示例 14-4　只 `print` 不 `return` 的坑**

```python
# ❌ 函数里只打印，没有 return
def bad_add(a, b):
    print(a + b)            # 只是把结果显示在屏幕上

r = bad_add(2, 3)           # => 5          屏幕上确实出现了 5
print(r)                    # => None       但 r 里什么都没有！
print(type(r))              # => <class 'NoneType'>
```

屏幕上看到了 5，很容易误以为"函数返回了 5"。但那 5 是**函数自己打印的**，调用方拿到的是 `None`。一旦你想用这个结果，立刻崩：

```python
def bad_add(a, b):
    print(a + b)

bad_add(2, 3) * 10
# => TypeError: unsupported operand type(s) for *: 'NoneType' and 'int'
```

`NoneType and int` 这个报错，**十有八九就是"函数忘了写 `return`"**。见到它先去检查函数末尾。

**没有 `return` 的函数返回 `None`**——这是规则，不是意外：

```python
def show():
    pass                    # pass 表示"这里什么都不做"，占位用

print(show())               # => None
```

这也解释了第 9.14 节那个现象：`lst.sort()` 返回 `None`，因为它的工作是"原地排序"，没有结果要交出来。

**判断标准很简单**：

| 函数的职责 | 该写什么 |
|---|---|
| **算出一个结果**给别人用 | `return 结果` |
| 显示给用户看 | `print(...)` |
| 修改传进来的数据 / 写文件 | 都不用，靠副作用 |

**最好不要一个函数既算又打印**——那样它只能用来打印，没法被别的代码复用（14.18 会细说）。

**示例 14-5　`return` 之后的代码不执行**

```python
def f():
    print("第一行")
    return "结果"
    print("这一行永远不会执行")      # 死代码，编辑器通常会灰显提醒

print(f())
# => 第一行
# => 结果
```

**`return` 不只是"交出结果"，它同时【立即结束整个函数】。** 这个性质非常有用——可以用它提前退出：

```python
def check(n):
    if n < 0:
        return "负数"           # 是负数就到此为止，下面不会执行
    return "非负数"

print(check(-1), check(1))      # => 负数 非负数
```

注意这里**不需要 `else`**，因为 `return` 已经把函数结束了。这个写法叫"提前返回"，14.17 节会讲它怎么消灭嵌套。

**示例 14-6　一次返回多个值**

```python
def divide(a, b):
    return a // b, a % b        # 用逗号隔开就行

print(divide(17, 5))            # => (3, 2)
print(type(divide(17, 5)))      # => <class 'tuple'>       其实是个元组！
```

**"返回多个值"这个说法不准确**——它返回的是**一个元组**，只是写法上省了括号（第 10.2 节讲过，元组的本质是逗号）。

配合解包（第 10.12 节）用起来很自然：

```python
def divide(a, b):
    return a // b, a % b

q, r = divide(17, 5)            # 解包成两个变量
print(q, r)                     # => 3 2
```

这正是第 10.13 节 `divmod` 的做法：

```python
print(divmod(17, 5))            # => (3, 2)      内置函数，和上面那个 divide 一样
```

> **经验规则**：返回值超过 **3 个**就别用元组了——调用方要数着顺序解包，很容易错。改成返回**字典**（键有名字，不怕顺序），或者到第 27 章用 `dataclass`。

## 14.3 位置参数与关键字参数

**示例 14-8　两种传参方式**

```python
def power(base, exp):
    return base ** exp

print(power(2, 3))              # => 8      ① 按位置传：谁在前谁是 base
print(power(base=2, exp=3))     # => 8      ② 按名字传：顺序无关
print(power(exp=3, base=2))     # => 8      ③ 按名字传，顺序颠倒也对
print(power(2, exp=3))          # => 8      ④ 混用：位置参数必须在前
```

**混用有个硬规定：位置参数必须写在关键字参数前面。**

```python
power(base=2, 3)
# => SyntaxError: positional argument follows keyword argument
```

报错文字直译就是"位置参数跟在了关键字参数后面"。**原因**：一旦开始按名字传，Python 就无法判断后面的 `3` 该对应谁了。

**示例 14-9　关键字参数真正的价值是可读性**

这一节讲的不是语法，是**怎么写出别人看得懂的调用**。

```python
def create_user(name, is_admin, send_email, retry):
    print(f"{name} 管理员={is_admin} 发邮件={send_email} 重试={retry}")

# ❌ 按位置传：三个月后你自己也看不懂这四个值是什么
create_user("小明", True, False, 3)
# => 小明 管理员=True 发邮件=False 重试=3
```

`True, False, 3` 这一串**完全无法阅读**。读代码的人（包括三个月后的你）必须跳到函数定义处数参数顺序。而且**一旦手抖把两个布尔值写颠倒，不会报错，行为却完全变了**。

```python
def create_user(name, is_admin, send_email, retry):
    print(f"{name} 管理员={is_admin} 发邮件={send_email} 重试={retry}")

# ✅ 按名字传：调用这一行本身就是文档
create_user("小明", is_admin=True, send_email=False, retry=3)
# => 小明 管理员=True 发邮件=False 重试=3
```

> **经验规则**（很实用，值得当习惯）：
>
> | 情况 | 建议 |
> |---|---|
> | 参数只有一两个，含义一目了然（`add(2, 3)`） | 按位置传就行 |
> | **参数超过两三个** | 从第三个起用关键字 |
> | **有布尔参数** | **一律用关键字**——光看 `True` 谁知道是什么意思 |
> | 参数是数字但含义不明（`sleep(3)` 还行，`resize(3)` 不行） | 用关键字 |
>
> **反过来对写函数的人也是个信号**：如果你的函数有四个参数、其中两个是布尔值，那它很可能干了太多事，该拆了（14.18）。

## 14.4 默认参数

**示例 14-10　默认参数**

```python
def power(base, exp=2):         # exp 有默认值，不传就用 2
    return base ** exp

print(power(5))                 # => 25       只传一个，exp 用默认值 2
print(power(5, 3))              # => 125      传了就用传的
```

默认参数让函数**既简单又灵活**：常见情况直接调用，特殊情况再指定。标准库里到处是这个套路（`round(x)` 和 `round(x, 2)`、`sorted(x)` 和 `sorted(x, reverse=True)`）。

**示例 14-11　有默认值的参数必须放后面**

```python
def bad(a=1, b):
    pass
# => SyntaxError: parameter without a default follows parameter with a default
```

**原因**：如果允许这样写，调用 `bad(5)` 时 Python 无法判断这个 5 是给 `a` 还是给 `b` 的。

**记法**：**必填的在前，可选的在后**——和现实中填表一样。

## 14.5 默认值只在定义时计算一次

**这一节是理解下一个陷阱的钥匙，请务必看懂。**

**示例 14-12　默认值只算一次**

```python
import time

def stamp(t=time.time()):       # 注意：time.time() 写在了默认值的位置
    return t

a = stamp()
time.sleep(0.05)                # 等 0.05 秒
b = stamp()

print(a == b)                   # => True      两次调用拿到的是【同一个】时间！
```

按直觉，两次调用间隔了 0.05 秒，时间戳该不一样。但结果是**完全相同**。

**原因只有一句话**：

> **默认值是在 `def` 那一行执行时算出来的，只算一次；之后每次调用都用那个算好的值。**

`def stamp(t=time.time())` 执行时，`time.time()` 就被调用了一次，结果**挂在函数身上**。之后一万次调用，用的都是那一个值。

这个"挂在函数身上"不是比喻，能直接看到：

```python
import time

def stamp(t=time.time()):
    return t

print(stamp.__defaults__ == (stamp(),))     # => True      默认值确实存在函数对象上
```

**一个真实事故**，很多人踩过：

```python
from datetime import datetime
import time

def log(msg, ts=datetime.now()):            # ❌ 时间戳永远是程序【启动】的时刻
    return f"[{ts}] {msg}"

x = log("第一条")
time.sleep(0.05)
y = log("第二条")

print(x.split("]")[0] == y.split("]")[0])   # => True      两条日志时间完全一样
```

程序跑一小时，所有日志的时间戳都停在启动那一刻。**正确写法**是默认 `None`，函数体里再取时间：

```python
from datetime import datetime

def log(msg, ts=None):
    if ts is None:
        ts = datetime.now()     # 这一行【每次调用都执行】，所以每次都是当前时间
    return f"[{ts}] {msg}"
```

**关键区别**：`def` 那一行只执行一次，**函数体每次调用都执行**。要"每次都重新算"，就得把代码放进函数体。

## 14.6 可变默认值陷阱

**这是 Python 最著名的坑。** 上一节讲清了原理，这一节看它造成的实际破坏。

**示例 14-13　可变默认值陷阱**

```python
# ❌ 错误：默认参数用了可变对象（列表）
def add_item(item, box=[]):
    box.append(item)
    return box

print(add_item("苹果"))          # => ['苹果']                    看着正常
print(add_item("香蕉"))          # => ['苹果', '香蕉']             ！上次的苹果还在
print(add_item("橘子"))          # => ['苹果', '香蕉', '橘子']      ！越攒越多
```

每次调用都应该得到一个只装一样东西的新列表，结果它把历史全记住了。

**原因就是 14.5 那一句**：`[]` 只在 `def` 执行时创建了一次，之后每次调用不传 `box`，用的都是**同一个列表**。而列表是可变的，`append` 直接改了它。

亲眼看看默认值被改的过程：

```python
def add_item(item, box=[]):
    box.append(item)
    return box

print(add_item.__defaults__)     # => ([],)                    一开始是空的
add_item("苹果")
print(add_item.__defaults__)     # => (['苹果'],)               默认值本身被改了！
add_item("香蕉")
print(add_item.__defaults__)     # => (['苹果', '香蕉'],)        继续攒
```

画出来是这样：

```text
def 执行时（只发生一次）：
    add_item ──→ 默认值 box ──→ [ ]        ← 只创建这一个列表

第 1 次调用（不传 box）：
    box 指向那个列表 → append("苹果") → ['苹果']

第 2 次调用（不传 box）：
    box 还是指向【同一个】列表 → append("香蕉") → ['苹果', '香蕉']
```

**这就是第 13 章的老问题**：`box` 只是贴在那个列表上的又一张标签。

**正确写法**：默认值写 `None`，在函数体里创建——因为函数体每次调用都执行：

```python
# ✅ 正确：默认值用 None
def add_item(item, box=None):
    if box is None:             # 用 is None 判断，不要用 if not box（下面解释）
        box = []                # 这一行每次调用都执行，所以每次都是新列表
    box.append(item)
    return box

print(add_item("苹果"))          # => ['苹果']
print(add_item("香蕉"))          # => ['香蕉']       ✅ 干净的新列表
print(add_item("橘子"))          # => ['橘子']

my_box = ["已有的"]              # 传自己的列表也照样能用
print(add_item("新的", my_box))  # => ['已有的', '新的']
```

**为什么必须用 `is None` 而不是 `if not box`？** 因为空列表也是 Falsy（第 7 章），会被误判：

```python
# ❌ 用 if not box 判断，传进来的空列表会被"没收"
def bad(item, box=None):
    if not box:                 # 空列表 [] 也满足这个条件！
        box = []                # 于是把调用者的列表换成了一个新的
    box.append(item)
    return box

empty = []                      # 调用者有一个空列表，想往里加东西
result = bad("x", empty)
print(result)                   # => ['x']       函数返回的有内容
print(empty)                    # => []          但调用者的列表【还是空的】！
```

调用者传了列表进来，指望它被填上，结果什么都没发生——**而且不报错**。

**哪些默认值有问题？判断标准还是"它可变吗"**：

| 默认值 | 安全吗 | 原因 |
|---|---|---|
| `0`、`""`、`None`、`True`、`(1, 2)` | ✅ 安全 | 不可变，改不了 |
| `[]`、`{}`、`set()` | ❌ 危险 | 可变，会跨调用累积 |
| `time.time()`、`datetime.now()` | ❌ 危险 | 只在定义时算一次 |

> **记住这条**：**默认参数只能用不可变的值。** 需要可变默认值时，写 `None`，在函数体里用 `if x is None:` 创建。
>
> 这条规则没有例外，照做就行。Ruff（第 37 章）里有专门的规则（`B006`）会自动揪出这种写法。

## 14.7 参数传的是引用

**这是第 13 章那件事的第三次现身**（3.3 标签 → 13.5 拷贝 → 现在的函数参数）。

**示例 14-14　传数字进函数：外面不受影响**

```python
def change_num(n):
    n = n + 100                 # 重新赋值：把 n 这张标签贴到新数字上
    return n

x = 5
print(change_num(x), x)         # => 105 5        x 完好无损
```

字符串也一样：

```python
def change_str(s):
    s = s.upper()               # upper() 返回新字符串
    return s

t = "abc"
print(change_str(t), t)         # => ABC abc      t 完好无损
```

**示例 14-15　传列表进函数：外面跟着变**

```python
def add_999(items):
    items.append(999)           # 改的是【那个列表本身】

lst = [1, 2, 3]
add_999(lst)
print(lst)                      # => [1, 2, 3, 999]      外面的列表被改了！
```

**函数悄悄改了调用者的数据。** 没有任何提示，`lst` 就变了。

但注意——**如果函数里是重新赋值，外面就不受影响**：

```python
def rebind(items):
    items = [0, 0]              # 重新赋值：把 items 撕下来贴到新列表上
    return items

lst = [1, 2, 3]
print(rebind(lst), lst)         # => [0, 0] [1, 2, 3]     外面的没变
```

**这正是 13.7 节那张表，一模一样**：

| 函数里的写法 | 影响调用者吗 |
|---|---|
| `items.append(x)` / `items[0] = x` / `d["k"] = v` | ✅ **会**——改的是那个对象 |
| `items = 新东西` | ❌ 不会——只是把形参这张标签挪走了 |

字典同理：

```python
def change_dict(d):
    d["new"] = 1

dd = {}
change_dict(dd)
print(dd)                       # => {'new': 1}
```

> **记住这条**：**Python 的参数传递没有"值传递 / 引用传递"之分，永远是"把实参那个对象再贴一张标签"。** 之后会不会影响外面，取决于你是**改那个对象**还是**给标签换个对象**。

## 14.8 怎么保护调用者的数据

知道了函数能改调用者的数据，接下来的问题是：**该不该改，以及怎么防**。

**示例 14-16　三种做法**

```python
# ① 原地改，但【名字说清楚】
def sort_in_place(items):
    """把 items 原地排序。注意：会修改传入的列表。"""
    items.sort()

# ② 函数内先拷贝再改
def sorted_copy(items):
    """返回排好序的新列表，不动传入的列表。"""
    items = items[:]            # 先拷一份（第 13.8 节）
    items.sort()
    return items

# ③ 不改，直接返回新对象（推荐）
def sorted_new(items):
    """返回排好序的新列表。"""
    return sorted(items)        # sorted 本身就返回新列表

a = [3, 1, 2]
sort_in_place(a)
print(a)                        # => [1, 2, 3]        原件被改了（这是它的本意）

b = [3, 1, 2]
print(sorted_copy(b), b)        # => [1, 2, 3] [3, 1, 2]     原件保留

c = [3, 1, 2]
print(sorted_new(c), c)         # => [1, 2, 3] [3, 1, 2]     原件保留
```

**三种都是正当做法，关键是"说清楚"**：

| 策略 | 什么时候用 | 代价 |
|---|---|---|
| ① 原地改 + 名字说清 | 数据很大，拷贝不起；或"修改"本身就是函数的职责 | 调用者必须知道数据会变 |
| ② 内部拷贝 | 想接受任意输入又不想影响它 | 有拷贝开销 |
| ③ **返回新对象（推荐）** | 绝大多数情况 | 有拷贝开销 |

**Python 标准库自己就用命名来区分这两类**，值得模仿：

| 原地改（返回 `None`） | 返回新对象 |
|---|---|
| `lst.sort()` | `sorted(lst)` |
| `lst.reverse()` | `reversed(lst)` |
| `random.shuffle(lst)` | `random.sample(lst, k)` |

**规律**：**动词原形（`sort`）= 原地改；过去分词 / 形容词（`sorted`）= 返回新的。** 你自己命名时也照这个来。

**嵌套数据要拷就得深拷贝**（第 13.15 节的结论）：

```python
import copy

def deep_guard(records):
    records = copy.deepcopy(records)    # 列表套字典，必须 deepcopy
    records[0]["name"] = "改了"
    return records

recs = [{"name": "小明"}]
print(deep_guard(recs), recs)   # => [{'name': '改了'}] [{'name': '小明'}]     ✅
```

> **记住这条**：**默认选"不改传入的数据，返回新对象"。** 只有在数据很大、拷贝代价明显时才原地改——**而且必须在函数名和 docstring 里说清楚**。

## 14.9 作用域基础

**示例 14-17　局部变量出了函数就不存在**

```python
def f():
    inner = 1               # 在函数里定义的变量是【局部的】
    return inner

print(f())                  # => 1

print(inner)
# => NameError: name 'inner' is not defined
```

函数里的变量**函数一结束就消失了**。这是好事——否则每个函数都往全局塞变量，几百行以后满地都是不知道谁定义的名字。

**示例 14-18　函数里能读全局变量**

```python
TAX_RATE = 0.1              # 全局变量，惯例用【全大写】表示"常量，别改"

def price_with_tax(p):
    return round(p * (1 + TAX_RATE), 2)     # 直接读，不用任何声明

print(price_with_tax(100))  # => 110.0
print(price_with_tax(19.9)) # => 21.89
```

**查找顺序是：局部 → 全局 → 内置。**

```text
① 局部：函数体里定义的（含参数）
② 全局：模块层面定义的
③ 内置：print / len / sum 这些
```

找到就停。完整规则叫 LEGB（还有一层"闭包"），到第 31 章讲闭包时再补。

**示例 14-22　别拿 `list`、`sum` 当变量名**

上面那个查找顺序有个直接后果——**你的变量会遮蔽内置函数**：

```python
list = [1, 2, 3]            # ❌ 把内置的 list 覆盖了

list("abc")
# => TypeError: 'list' object is not callable
```

报错说"list 对象不能被调用"——因为现在 `list` 是个列表，不是函数了。

```python
sum = 0                     # ❌ 同样的问题

sum([1, 2])
# => TypeError: 'int' object is not callable
```

**这个坑很隐蔽**：出错的地方往往离赋值那一行很远，你会盯着 `sum([1, 2])` 想"这明明是对的"。

**常被误用的内置名字**，避开它们：

| 别用 | 改用 |
|---|---|
| `list` | `items`、`rows`、`names` |
| `dict` | `mapping`、`config`、`d` |
| `sum` | `total` |
| `str` | `text`、`s` |
| `type` | `kind`、`category` |
| `id` | `user_id`、`item_id` |
| `input` | `raw`、`user_input` |
| `max` / `min` | `highest` / `lowest` |
| `file` | `path`、`f` |

**局部变量也会遮蔽同名的全局变量**：

```python
name = "全局"

def show():
    name = "局部"                    # 这是一个【新的局部变量】，和全局那个无关
    print("函数里看到:", name)

show()                               # => 函数里看到: 局部
print("函数外看到:", name)            # => 函数外看到: 全局      全局的没被动
```

## 14.10 `UnboundLocalError`

**这个报错是新手最困惑的之一**，值得单独一节。

**示例 14-19　`UnboundLocalError`**

上一节说"函数里能读全局变量"，那为什么这样会报错？

```python
count = 0                   # 全局变量

def bad_incr():
    count = count + 1       # 想给全局的 count 加 1

bad_incr()
# => UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

报错说"**无法访问局部变量 `count`，它还没有值**"。可 `count` 明明在外面定义过了？

**原因是一条你必须记住的规则**：

> ### 函数里只要对某个名字**赋过值**，Python 就在**整个函数内**把它当局部变量。

Python 在编译函数时会先扫一遍函数体，看到 `count = ...`，就判定"`count` 是这个函数的局部变量"。于是执行 `count = count + 1` 时：

1. 先算等号右边的 `count + 1`
2. 这个 `count` 是**局部**的（已被判定）
3. 但局部的 `count` 还没赋值 → **报错**

**注意它和 `NameError` 的区别**：

| 报错 | 含义 |
|---|---|
| `NameError` | 这个名字**根本不存在** |
| `UnboundLocalError` | 这个名字**是局部变量，但还没赋值** |

只读不写就完全没问题（这也印证了上面那条规则——没赋值就不会被判定为局部）：

```python
count = 0

def only_read():
    print("只读没问题:", count)      # 没有赋值，所以 count 还是全局的

only_read()                          # => 只读没问题: 0
```

**赋值语句写在后面也一样会报错**，因为判定是在编译期做的，跟位置无关：

```python
def bad2():
    print(v)                # 这里就已经报错了
    v = 1                   # 就因为下面这一行，v 被判定成了局部变量

bad2()
# => UnboundLocalError: cannot access local variable 'v' where it is not associated with a value
```

**这个例子最能说明问题**——`print(v)` 在赋值之前，却因为**后面**有个赋值而报错。

### 两种解法

**示例 14-20　`global`：能用，但不推荐**

```python
total = 0

def add_global(n):
    global total            # 声明：我要用的是全局那个 total
    total = total + n

add_global(5)
add_global(3)
print(total)                # => 8
```

`global` 确实解决了问题，但**它带来的麻烦通常比解决的多**：

- 任何函数都能改这个变量 → 出错时**你不知道是谁改的**，得把整个文件读一遍
- 函数不再"自给自足"，**没法单独测试**（它依赖外部状态）
- 多处调用顺序一变，结果就变

**示例 14-21　用返回值代替 `global`（推荐）**

```python
def incr(c, n=1):
    """返回 c + n。不碰任何外部状态。"""
    return c + n

count = 0
count = incr(count, 5)      # 状态用参数传进去，结果用返回值传出来
count = incr(count, 3)
print(count)                # => 8
```

**结果完全一样，但这个版本**：

- `incr` 只依赖参数，**给什么就算什么**，可以单独测试
- "谁改了 count"一目了然——只有写着 `count = ...` 的那几行
- 函数可以放心复用到别处

> **记住这条**：**看到自己想写 `global`，先想想能不能改成"参数传入、返回值传出"。** 九成情况可以，而且更好。
>
> `nonlocal` 是它的近亲（用于嵌套函数），第 31 章讲闭包时再说。
>
> **什么时候 `global` 算合理？** 极少数情况：程序级的配置开关、缓存。而且到了那种规模，用类（第 26 章）或模块级配置对象会更清楚。

## 14.11 docstring：给函数写说明书

**示例 14-23　docstring**

函数体的**第一行**如果是字符串，它就是这个函数的说明书：

```python
def calc_bmi(weight, height):
    """计算体质指数 BMI。

    参数：
        weight: 体重，单位公斤
        height: 身高，单位米
    返回：
        BMI 值（float），保留一位小数
    """
    return round(weight / height ** 2, 1)

print(calc_bmi(65, 1.75))                   # => 21.2
print(calc_bmi.__doc__.split("\n")[0])      # => 计算体质指数 BMI。
```

用 `help()` 能读到完整的说明——**和你查标准库函数用的是同一个机制**：

```python
def calc_bmi(weight, height):
    """计算体质指数 BMI。

    参数：
        weight: 体重，单位公斤
        height: 身高，单位米
    返回：
        BMI 值（float），保留一位小数
    """
    return round(weight / height ** 2, 1)

help(calc_bmi)
```

```text
Help on function calc_bmi in module __main__:

calc_bmi(weight, height)
    计算体质指数 BMI。

    参数：
        weight: 体重，单位公斤
        height: 身高，单位米
    返回：
        BMI 值（float），保留一位小数
```

**该写什么**：

| 写 | 不写 |
|---|---|
| 一句话说明**做什么** | **怎么实现的**（那是注释的事，写在函数体里） |
| 每个参数的**含义和单位** | 参数的类型（用类型注解表达，14.14） |
| **返回什么** | 显而易见的废话（`def get_name(): """获取名字"""`） |
| 什么情况会**报错** / 有什么**副作用** | |

**"单位"这一项特别值得写**——`height` 是米还是厘米？`timeout` 是秒还是毫秒？这类信息不写清楚，调用的人只能去读实现。

**什么时候可以不写 docstring？** 函数短、名字已经说清一切（`def is_empty(lst): return len(lst) == 0`）。**别为了凑格式写废话**。

## 14.12 函数是对象

**这一节会改变你对代码组织的认识。**

在 Python 里，函数和数字、字符串、列表一样，**就是个普通对象**。它能被赋值、能当参数传、能放进列表和字典。

**示例 14-24　函数可以赋值给变量**

```python
def greet():
    print("你好")

f = greet                   # 注意：【没有括号】，存的是函数本身
f()                         # => 你好          用新名字调用
print(type(greet))          # => <class 'function'>
```

**加不加括号是关键区别，这是本节最高频的错误**：

```python
def greet():
    print("你好")

g = greet()                 # 加了括号：先调用它，再把【返回值】存进 g
# => 你好                     （调用发生在这一行，所以立刻打印了）
print(g)                    # => None         greet 没有 return，所以 g 是 None
```

| 写法 | 含义 |
|---|---|
| `greet` | **这个函数**（一个对象） |
| `greet()` | **调用它，得到返回值** |

**示例 14-25　把函数传给另一个函数**

你其实早就用过了——第 10.18、11.17 节的 `key=`：

```python
records = [("小明", 92), ("小红", 88), ("小刚", 95)]

def get_score(r):
    """从一条记录里取出分数，供排序用。"""
    return r[1]

print(sorted(records, key=get_score))                   # => [('小红', 88), ('小明', 92), ('小刚', 95)]
print(sorted(records, key=get_score, reverse=True))     # => [('小刚', 95), ('小明', 92), ('小红', 88)]
print(max(records, key=get_score))                      # => ('小刚', 95)
```

`sorted` 收到 `get_score` 这个函数，**自己去决定什么时候调用它、对谁调用**。这叫"高阶函数"——接受函数作为参数的函数。

**示例 14-26　函数存进字典：命令分发器**

第 11.18 节我们用字典替掉了一串 `elif`，但那时字典的值只能是字符串，**只能"查出说明"，不能"执行动作"**。现在函数能当值了：

```python
def do_add():
    print("执行：添加一条记录")

def do_list():
    print("执行：列出全部记录")

def do_help():
    print("可用命令：" + ", ".join(actions))     # 直接从字典读出所有命令名

def do_unknown():
    print("未知命令，输入 help 查看帮助")

# 命令 → 函数 的映射表。注意值【不加括号】
actions = {
    "add": do_add,
    "list": do_list,
    "help": do_help,
}

cmd = input("请输入命令：").strip().lower()

# get 取出对应的函数（取不到就用兜底的），再加括号调用
actions.get(cmd, do_unknown)()
#                            ↑ 这一对括号才是真正的调用
```

三次运行的实际画面：

```text
请输入命令：list
执行：列出全部记录
```

```text
请输入命令：xyz
未知命令，输入 help 查看帮助
```

```text
请输入命令：help
可用命令：add, list, help
```

**最容易错的地方就是那对括号**：

```python
def do_add():
    print("执行：添加")

# ❌ 加了括号：构造字典时函数就被调用了，存进去的是返回值 None
actions = {"add": do_add()}
# => 执行：添加                    这一行在【建字典时】就打印了
print(actions)                    # => {'add': None}

actions["add"]()
# => TypeError: 'NoneType' object is not callable
```

```python
def do_add():
    print("执行：添加")

# ✅ 不加括号：存的是函数本身
actions = {"add": do_add}
print(callable(actions["add"]))   # => True          它是个能调用的东西
actions["add"]()                  # => 执行：添加      现在才调用
```

**这个模式比 11.18 的查找表更强**：

| 需求 | `if/elif` 版 | 分发器版 |
|---|---|---|
| 加一个命令 | 插一段 `elif` | 写个函数 + 字典加一行 |
| 列出所有命令 | 手工再维护一份清单（**容易和实际不一致**） | `", ".join(actions)` |
| 某个命令逻辑变复杂 | `elif` 块越来越长 | 各自在自己的函数里，互不干扰 |
| 单独测试某个命令 | 做不到，逻辑埋在分支里 | 直接调 `do_add()` |

> **记住这条**：**"根据某个值决定执行哪段逻辑"——用字典存函数，不要写一长串 `elif`。**
>
> **这就是验收项目 A2（命令行计算器）的核心结构**，下面的综合示例会用到。
>
> **这个模式还能走更远**：把函数放进字典是"用数据描述行为"的开始。第 31 章的装饰器、第 34 章的 `functools.partial`，都建立在"函数是普通对象"这个事实上。

## 14.13 怎么把函数写好

语法讲完了，这一节讲**判断**——同样能跑的代码，写法差别很大。

### 提前返回，消灭嵌套

**示例 14-27　提前返回**

```python
# ❌ 层层嵌套：主逻辑被埋在最里面第四层缩进
def check_nested(user):
    if user:
        if user.get("active"):
            if user.get("age", 0) >= 18:
                return "通过"
            else:
                return "未成年"
        else:
            return "账号未激活"
    else:
        return "没有用户"
```

问题：**真正想干的事（"通过"）在最深处**，而且每个 `if` 都要配一个远在天边的 `else`，读的时候要在脑子里维护一个栈。

```python
# ✅ 提前返回：不合格就立刻走人，主流程永远在最外层缩进
def check_flat(user):
    if not user:
        return "没有用户"
    if not user.get("active"):
        return "账号未激活"
    if user.get("age", 0) < 18:
        return "未成年"
    return "通过"                # 一路过关，才走到这里
```

两个版本行为完全一致：

```python
cases = [None, {"active": False}, {"active": True, "age": 15}, {"active": True, "age": 20}]
for c in cases:
    print(check_flat(c))
# => 没有用户
# => 账号未激活
# => 未成年
# => 通过
```

**第二个版本的好处**：

- 缩进只有一层，**主流程一眼看到底**
- 每条检查独立，加/删/调顺序都只改一行
- 不需要 `else`——`return` 已经结束函数了
- 读到 `return "通过"` 时你确定"前面所有检查都过了"

这个写法叫"**卫语句**"（guard clause）。它是我知道的**性价比最高的代码整理技巧**：改动极小，可读性提升极大。

> **记住这条**：**先把不合格的挡在门外（`return` 掉），主流程留在最外层。** 看到三层以上的 `if` 嵌套，先想想能不能改成提前返回。

### 一个函数只做一件事

**示例 14-28　一个函数只做一件事**

```python
# ❌ 一个函数又造数据、又算、又打印
def do_everything():
    scores = [92, 88, 76]
    total = sum(scores)
    print(f"总分 {total}，平均 {total / len(scores):.1f}")

do_everything()             # => 总分 256，平均 85.3
```

它能跑，但**什么都干不了**：

- 想拿总分去做别的事？**拿不到**，它只打印
- 想换成从文件读数据？**得改这个函数**
- 想测"平均分算得对不对"？**没法测**，一调用就打印
- 想改成写进文件而不是打印？**又得改它**

拆开：

```python
def load_scores():
    """取数据。以后换成读文件（第 16 章）只改这一个函数。"""
    return [92, 88, 76]

def calc_stats(scores):
    """算总分和平均分，返回一个元组。不打印任何东西。"""
    return sum(scores), sum(scores) / len(scores)

def report(total, avg):
    """把结果显示出来。"""
    print(f"总分 {total}，平均 {avg:.1f}")

total, avg = calc_stats(load_scores())
report(total, avg)          # => 总分 256，平均 85.3

print(calc_stats([100, 100]))       # => (200, 100.0)     现在能单独测了
```

**注意这个分工**：`load` 负责取数据、`calc` 负责算、`report` 负责显示。**算的那个函数不打印，打印的那个不算**——这样每一块都能单独换掉、单独测试。

**三条可操作的判断标准**：

| 标准 | 说明 |
|---|---|
| ① 函数名能否用**一个动词短语**说清 | 名字里出现"和"（`load_and_print`）就是干了两件事 |
| ② 参数是否超过 4 个 | 超了通常说明它管得太多 |
| ③ 能否脱离上下文**单独测试** | 一调用就打印 / 就读文件，就难测 |

**经验值**：函数体超过一屏（约 30 行）就该考虑拆。**但不要为拆而拆**——把一个连贯的 40 行逻辑硬切成四个互相调用的小函数，反而更难读。

### 命名约定

**示例 14-19 的补充：怎么起名字**

| 前缀 | 用于 | 例子 |
|---|---|---|
| `get_` / `load_` / `read_` | 取数据 | `get_user`、`load_config` |
| `calc_` / `compute_` | 计算 | `calc_bmi`、`calc_total` |
| **`is_` / `has_` / `can_`** | **返回布尔值** | `is_valid`、`has_permission` |
| `save_` / `write_` | 输出 | `save_report` |
| `parse_` / `format_` | 转换 | `parse_date`、`format_money` |
| `validate_` / `check_` | 校验 | `validate_input` |

**两条原则**：

1. **动词开头。** `data()` 看不出它会做事，`load_data()` 一目了然。
2. **说清"做什么"，不说"怎么做"。** `save_report()` 好，`write_report_to_csv_with_utf8()` 不好——实现方式会变，名字不该跟着变。

## 14.14 三个"一瞥即可"

这三样你会在别人代码里见到，本章只要**认得出**，不必现在掌握。

### 递归

**示例 14-29　递归算阶乘**

函数可以调用自己。两个要素缺一不可：**终止条件** + **向终止条件靠近的调用**。

```python
def factorial(n):
    if n <= 1:              # ① 终止条件：不能再往下了
        return 1
    return n * factorial(n - 1)     # ② 调用自己，但参数在【变小】

print(factorial(5))         # => 120        5*4*3*2*1
print(factorial(20))        # => 2432902008176640000
```

同一件事用循环写：

```python
def factorial_loop(n):
    result = 1
    for i in range(2, n + 1):
        result = result * i
    return result

print(factorial_loop(5), factorial_loop(20))    # => 120 2432902008176640000
```

**示例 14-30　递归太深会报错**

```python
import sys
print(sys.getrecursionlimit())       # => 1000       默认最多嵌套约 1000 层

def countdown(n):
    if n == 0:
        return 0
    return countdown(n - 1)

countdown(5000)
# => RecursionError: maximum recursion depth exceeded
```

忘了写终止条件，也是同一个报错（因为它永远递归下去）。

> **说句实话**：**日常业务代码里 95% 的递归都能用循环写得更清楚**，而且不用担心层数限制。
>
> 递归真正好用的场景是**树形结构**——遍历目录（第 16 章）、解析嵌套 JSON（第 17 章）。那些结构本身就是"一层套一层，深度未知"，用循环写反而绕。见到递归先问一句："这个数据是树形的吗？"不是的话，循环更好。

### `lambda`

**示例 14-31　`lambda` 长什么样**

一行写完的匿名函数。你在第 10.18、11.17 节已经见过：

```python
records = [("小明", 92), ("小红", 88)]

print(sorted(records, key=lambda r: r[1]))      # => [('小红', 88), ('小明', 92)]
#                          ↑ 相当于一个"接收 r，返回 r[1]"的函数，但不用起名字
```

**只在这种"临时用一次、逻辑只有一行"的场合用它**。逻辑稍复杂就该写成正常的 `def`（有名字、能写 docstring、能单独测试）。完整讨论见第 25 章。

### 类型注解

**示例 14-32　类型注解不影响运行**

```python
def add(a: int, b: int) -> int:      # 说明：两个 int 进，一个 int 出
    return a + b

print(add(1, 2))                     # => 3
print(add("你", "好"))                # => 你好        传字符串照样能跑！
print(add([1], [2]))                 # => [1, 2]     传列表也能跑
```

**注解完全不影响运行**——Python 不检查它。它是给**人**和**工具**看的：

```python
def add(a: int, b: int) -> int:
    return a + b

print(add.__annotations__)
# => {'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}
```

工具（mypy、VS Code）会读它来提示错误。**这是它真正的价值**：把"参数该传什么"从注释里的口头约定，变成工具能检查的东西。完整讨论见第 33 章。

从 C# / Java 过来的人要特别注意：**这不是类型声明，是"类型提示"。** 写了 `: int` 传字符串进去，Python 不会拦你。

### 示例 14-33　把成绩统计重构成函数

回收第 9 章。同一份需求，这次用函数组织。

```python
def load_records():
    """取成绩数据。以后换成读文件（第 16 章）只改这一个函数。"""
    return [
        {"name": "小明", "scores": {"数学": 92, "语文": 85}},
        {"name": "小红", "scores": {"数学": 78, "语文": 95}},
        {"name": "小刚", "scores": {"数学": 65, "语文": 70}},
    ]

def calc_total(record):
    """算一个学生的总分。"""
    return sum(record["scores"].values())

def calc_average(record):
    """算一个学生的平均分，保留一位小数。"""
    return round(calc_total(record) / len(record["scores"]), 1)

def calc_subject_average(records, subject):
    """算某一科的全班平均分。"""
    values = [r["scores"][subject] for r in records]
    return round(sum(values) / len(values), 1)

def is_passing(record, line=60):
    """判断这个学生是否每科都及格。line 可以调整及格线。"""
    return all([s >= line for s in record["scores"].values()])

def report(records):
    """打印成绩报表。"""
    # 中文是双宽字符，和数字混排时按字符数对齐会歪（第 6 章讲过），
    # 这里用竖线分隔，就不必纠结每列宽度了
    print("姓名 | 总分 | 平均 | 全科及格")
    print("-" * 30)
    for r in sorted(records, key=calc_total, reverse=True):     # 函数当 key 用
        flag = "是" if is_passing(r) else "否"
        print(f"{r['name']} | {calc_total(r):>4} | {calc_average(r):>5} | {flag}")
    print("-" * 30)
    for subject in ["数学", "语文"]:
        print(f"{subject}全班平均：{calc_subject_average(records, subject)}")

records = load_records()
report(records)
```

```text
姓名 | 总分 | 平均 | 全科及格
------------------------------
小明 |  177 |  88.5 | 是
小红 |  173 |  86.5 | 是
小刚 |  135 |  67.5 | 是
------------------------------
数学全班平均：78.3
语文全班平均：83.3
```

**比第 9 章那个版本强在哪？** 不是"短了"（其实更长），而是：

```python
records = load_records()

print(calc_total(records[0]))               # => 177        每个函数都能单独调用
print(calc_average(records[0]))             # => 88.5
print(is_passing(records[0]))               # => True
print(is_passing(records[2], line=70))      # => False      及格线提到 70，小刚就不合格了
print(calc_subject_average(records, "数学")) # => 78.3
```

- **每块逻辑都能单独验证**——不用把整个报表跑一遍
- **及格线能调**（`line=70`），因为它是参数而不是写死的数字
- 要改数据来源只改 `load_records`，要改报表格式只改 `report`，**互不影响**
- `sorted(records, key=calc_total)` 直接把函数当排序依据用（14.12）

### 示例 14-34　命令行计算器

**验收项目 A2 的核心。** 用字典分发器（14.12）组织四个运算。

```python
def add(a, b):
    return a + b

def sub(a, b):
    return a - b

def mul(a, b):
    return a * b

def div(a, b):
    if b == 0:                      # 提前返回，挡住除零
        return "错误：除数不能为 0"
    return a / b

# 运算符 → 函数。加新运算符只需在这里加一行 + 写个函数
OPS = {"+": add, "-": sub, "*": mul, "/": div}

while True:
    raw = input("请输入算式（如 3 + 4），输入 q 退出：").strip()
    if raw == "q":
        print("再见")
        break

    parts = raw.split()             # 按空格拆成三段
    if len(parts) != 3:
        print("格式不对，要用空格隔开，例如：3 + 4")
        continue

    left, op, right = parts         # 元组解包（第 10.12 节）
    if op not in OPS:
        print(f"不支持的运算符 {op}，只支持 {' '.join(OPS)}")
        continue
    # lstrip("-") 是为了让负数也能通过 isdigit 检查
    if not (left.lstrip("-").isdigit() and right.lstrip("-").isdigit()):
        print("两边必须是整数（第 15 章会用异常处理支持小数）")
        continue

    result = OPS[op](int(left), int(right))      # 取出函数，直接调用
    print(f"{left} {op} {right} = {result}")
```

实际运行（每一行都实测过）：

```text
请输入算式（如 3 + 4），输入 q 退出：3 + 4
3 + 4 = 7
请输入算式（如 3 + 4），输入 q 退出：10 / 3
10 / 3 = 3.3333333333333335
请输入算式（如 3 + 4），输入 q 退出：8 / 0
8 / 0 = 错误：除数不能为 0
请输入算式（如 3 + 4），输入 q 退出：2 ^ 5
不支持的运算符 ^，只支持 + - * /
请输入算式（如 3 + 4），输入 q 退出：3+4
格式不对，要用空格隔开，例如：3 + 4
请输入算式（如 3 + 4），输入 q 退出：-7 * 3
-7 * 3 = -21
请输入算式（如 3 + 4），输入 q 退出：q
再见
```

**注意这段代码的几个设计**：

| 做法 | 好处 |
|---|---|
| `OPS` 字典存函数 | 加一个 `%` 运算只要写个函数 + 加一行，**主循环一个字都不用改** |
| `' '.join(OPS)` 生成提示 | 支持的运算符列表**自动和字典保持一致**，不会说漏 |
| 每种错误都 `continue` | 提前返回的思路，主流程不嵌套 |
| `div` 内部处理除零 | 每个运算自己管自己的边界 |

**它还有两个缺陷**，第 15 章会修：

1. **只支持整数**——`3.5 + 1` 会被拒。用 `isdigit` 打补丁支持小数会越写越长（第 12 章那个 `rstrip` 的教训）
2. **只支持"数 运算符 数"三段式**——`3+4`（没空格）就不认

第 15 章用 `try` 重写之后，第 1 个问题会**自然消失**，代码还更短。

### 示例 14-35　可复用的输入校验函数

把校验逻辑收成一个函数，全程序复用。

```python
def parse_int(text, min_value=None, max_value=None):
    """把文本解析成整数并检查范围。

    参数：
        text: 待解析的文本
        min_value: 允许的最小值，None 表示不检查
        max_value: 允许的最大值，None 表示不检查
    返回：
        (成功?, 值或错误提示) 这个二元组
    """
    text = text.strip()
    # lstrip("-") 让负数也能通过 isdigit
    if not text.lstrip("-").isdigit():
        return False, "请输入一个整数"
    value = int(text)
    # 用 is not None 判断，因为 min_value=0 是合法的（0 是 Falsy！）
    if min_value is not None and value < min_value:
        return False, f"不能小于 {min_value}"
    if max_value is not None and value > max_value:
        return False, f"不能大于 {max_value}"
    return True, value

for s in ["35", "-5", "3.5", "abc", "", "150", "0"]:
    ok, result = parse_int(s, min_value=0, max_value=120)
    print(f"{s!r:8} -> {ok}, {result}")
```

```text
'35'     -> True, 35
'-5'     -> False, 不能小于 0
'3.5'    -> False, 请输入一个整数
'abc'    -> False, 请输入一个整数
''       -> False, 请输入一个整数
'150'    -> False, 不能大于 120
'0'      -> True, 0
```

**注意两个细节**：

1. **`min_value is not None` 不能写成 `if min_value:`**——因为 `min_value=0` 时 `0` 是 Falsy，检查会被跳过。这是 14.6 那个 `is None` 教训的另一面。
2. **返回 `(成功?, 结果)` 二元组**，让调用方决定怎么处理失败。

**但这个函数有个根本缺陷**：它靠 `isdigit` 判断，所以

- 支持不了小数（`3.5` 被拒）
- 支持不了 `1e5`、`+5`、`1_000` 这些**合法的 Python 数字写法**
- 想支持就得不断打补丁，而且**永远有漏的**

第 15 章会用 `try` 把它重写成三行，**这三个问题一次性全部消失**。

### 语法对照

| 你熟悉的 | Python |
|---|---|
| `int Add(int a, int b) { return a + b; }` | `def add(a, b): return a + b` |
| 方法定义在类里 | **函数可以定义在模块层面**，不需要类 |
| `void` 方法 | 没有 `return` 的函数（**实际返回 `None`**） |
| `out` / `ref` 参数 | 用 `return a, b` 返回元组 |
| 方法重载（同名不同签名） | **不支持**！后定义的会覆盖前面的 |
| 可选参数 `int n = 2` | `def f(n=2)`——**但默认值只算一次，见 14.5** |
| 命名参数 `Foo(name: "x")` | `foo(name="x")` |
| `params int[] args` | `*args`（第 25 章） |
| `Func<int,int>` / `delegate` | **函数本身就是对象**，不需要委托类型 |
| `Dictionary<string, Action>` | `{"add": do_add}`——**一样的模式，语法更短** |
| XML 文档注释 `/// <summary>` | docstring（`"""..."""`） |
| 编译期类型检查 | **没有**；类型注解只是提示（14.14） |

### 五个必须注意的差异

**① 没有方法重载。** 这是最容易踩的：

```python
def area(r):
    return 3.14 * r * r

def area(w, h):          # ❌ 不是重载，是【覆盖】——上面那个没了
    return w * h

area(5)
# => TypeError: area() missing 1 required positional argument: 'h'
```

Python 里同一个名字只能有一个函数。要"多种调用方式"，用**默认参数**：

```python
def area(w, h=None):
    if h is None:            # 只给一个参数 → 当正方形
        return w * w
    return w * h

print(area(5), area(3, 4))   # => 25 12
```

**② 必须先定义后调用。** C# 编译器会先扫全文件，Python 不会——`def` 是一条执行到才生效的语句。

**③ 默认值只算一次，而且是可变的。** C# 的可选参数必须是编译期常量，所以**根本不可能有 14.6 那个陷阱**。Python 允许任意表达式当默认值，于是就有了这个坑。**这是从 C# 转过来最容易中招的一条。**

**④ `global` 的语义和你想的不同。** C# 里给静态字段赋值不需要任何声明；Python 里**不加 `global` 就是创建局部变量**，于是有了 `UnboundLocalError`（14.10）。这个报错在 C# 里没有对应物。

**⑤ 参数传递：Python 没有"值传递 / 引用传递"这个区分。** C# 里 `int` 按值传、`List<T>` 按引用传，你靠类型判断。Python **永远是"给实参对象再贴一张标签"**——之后影不影响外面，取决于你是改对象还是给标签换对象（14.7）。

### 命名风格

| C# | Python |
|---|---|
| `CalcBmi`（PascalCase） | `calc_bmi`（**snake_case**） |
| `IsValid` | `is_valid` |
| 常量 `MaxRetry` | `MAX_RETRY`（**全大写**） |
| 私有 `_field` | `_name`（**只是约定**，不强制） |

Python 的函数名一律**小写加下划线**。用 PascalCase 会被 Ruff 提醒，而且读 Python 代码的人会以为那是个类。

### 一个观念差异：不要什么都包成类

C# 里所有方法都必须在类里，所以你习惯了"先建个 `Helper` 类"。**Python 里模块本身就是命名空间**——一堆相关的函数放在一个 `.py` 文件里就够了，不需要包一层类。

```python
# ❌ 从 C# 带来的习惯：只为了装函数而建类
class MathHelper:
    @staticmethod
    def add(a, b):
        return a + b
```

```python
# ✅ Python 的做法：直接是模块级函数（放在 math_utils.py 里，第 18 章讲）
def add(a, b):
    return a + b
```

**什么时候才该用类？** 当你需要**捆绑状态和行为**时（第 26 章）。只有函数没有状态，就别建类。

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| 函数里只 `print` 不 `return` | 调用方拿到 `None`，`TypeError: ... 'NoneType' and 'int'` | 用 `return` 交出结果 | 没有 `return` 就返回 `None` |
| **`def f(x=[])`** | 多次调用间数据累积 | 默认值用 `None`，体内 `if x is None:` 创建 | **默认值只在定义时创建一次** |
| `def f(t=datetime.now())` | 时间戳永远是程序启动时刻 | 同上 | 同上 |
| `if not box:` 判断默认值 | 传进来的空列表被"没收"，不报错 | `if box is None:` | 空列表也是 Falsy |
| `if min_value:` 判断可选参数 | `min_value=0` 时检查被跳过 | `if min_value is not None:` | `0` 是 Falsy |
| `def f(n=2, x)` | `SyntaxError: parameter without a default follows...` | 有默认值的放后面 | 位置无法对应 |
| `f(a=1, 2)` | `SyntaxError: positional argument follows keyword argument` | 位置参数写在前面 | 无法判断 `2` 给谁 |
| 函数里改了传入的列表 | 调用者的数据被悄悄改了 | 返回新对象，或在名字/docstring 里说清 | 参数传的是引用 |
| **`count = count + 1`**（count 是全局的） | `UnboundLocalError` | 用参数+返回值，或 `global` | **函数里赋过值就是局部变量** |
| 变量取名 `list` / `sum` / `str` | 之后调用 `list()` 报 `not callable` | 换名字 | 遮蔽了内置函数 |
| **字典里存 `do_add()`** | 存进去的是 `None`，调用时 `TypeError` | 存 `do_add`（**不加括号**） | 括号表示"立即调用" |
| `f = greet()` 想存函数 | 存的是返回值 | `f = greet` | 同上 |
| 调用写在 `def` 前面 | `NameError` | 先定义后调用 | 自上而下执行 |
| 定义两个同名函数当重载 | 后面的覆盖前面的 | 用默认参数区分 | **Python 不支持重载** |
| 递归忘了终止条件 | `RecursionError` | 补上终止条件 | 无限递归 |
| 拿递归处理非树形数据 | 有层数限制、更难读 | 用循环 | 递归只在树形结构上划算 |
| 一个函数干五件事 | 没法复用、没法测试、名字取不出来 | 按 14.13 三条标准拆 | 单一职责 |
| 三层以上 `if` 嵌套 | 主逻辑埋在最深处 | 提前返回（卫语句） | —— |
| 函数名用名词（`data()`） | 看不出它会做事 | 动词开头（`load_data()`） | 命名约定 |
| 以为类型注解会检查 | 传错类型照样跑 | 用 mypy 检查（第 33 章） | 注解只是提示 |
| 只为装函数而建类 | 多一层没用的包装 | 直接写模块级函数 | 模块本身就是命名空间 |

## 本章小结

### 定义与返回

- **函数最大的价值是"给一段逻辑起个名字"**，其次才是消除重复——**哪怕只调用一次也值得写**
- `def` 那一行只是**创建**函数；**必须先定义后调用**（Python 自上而下执行）
- **`return` 交出结果并立即结束函数**；没有 `return` 就返回 `None`
- 看到 `TypeError: ... 'NoneType' and ...`，**先查函数是不是忘了 `return`**
- `return a, b` 返回的其实是**元组**；超过 3 个值改用字典

### 参数

- 位置传 / 关键字传；**位置参数必须写在关键字参数前面**
- **有布尔参数就一律用关键字传**——`f("小明", True, False, 3)` 没人看得懂
- 有默认值的参数**必须放后面**
- **默认值只在 `def` 执行时算一次**——这是下一条的根源
- **可变默认值陷阱**：`def f(x=[])` 会跨调用累积。默认值只能用不可变的值，需要可变的就写 `None` + `if x is None:`
- 判断可选参数是否传了，**一律用 `is None` / `is not None`**，不要用真假判断（`0` 和 `[]` 都是 Falsy）

### 参数传递（第 13 章的第三次现身）

- **Python 没有"值传递 / 引用传递"之分**，永远是"给实参对象再贴一张标签"
- **改对象**（`items.append(x)`）→ 影响外面；**给标签换对象**（`items = 新的`）→ 不影响
- 保护调用者数据三策略：① 原地改但名字说清 ② 内部拷贝 ③ **返回新对象（推荐）**
- 标准库的命名规律可以模仿：**`sort()` 原地改，`sorted()` 返回新的**

### 作用域

- 查找顺序：**局部 → 全局 → 内置**（完整的 LEGB 见第 31 章）
- 函数里**能读**全局变量，不用声明
- **`UnboundLocalError`：函数里只要对某个名字赋过值，它在整个函数内都是局部变量**
  - 与 `NameError` 的区别：前者"是局部变量但没赋值"，后者"名字根本不存在"
  - **解法优先用"参数传入、返回值传出"，而不是 `global`**
- **别用 `list` / `sum` / `str` / `id` / `input` 当变量名**——会遮蔽内置函数

### 函数是对象

- 函数能赋值、能当参数传、能进列表和字典
- **`greet` 是函数本身，`greet()` 是调用结果**——存函数时**千万别加括号**
- **命令分发器**：`actions = {"add": do_add}` 然后 `actions.get(cmd, 兜底)()`
- 比 `if/elif` 强在：加命令只改一行、命令清单自动一致、每个命令能单独测试

### 怎么写好

- **提前返回（卫语句）**：不合格的挡在门外，主流程留在最外层缩进——**性价比最高的整理技巧**
- **一个函数只做一件事**，三条判断标准：① 名字能否用一个动词短语说清 ② 参数是否超过 4 个 ③ 能否单独测试
- **算的函数不打印，打印的函数不算**
- 命名：**动词开头**，布尔用 `is_` / `has_`，说清"做什么"不说"怎么做"
- docstring 写"做什么 / 参数含义和**单位** / 返回什么"，不写"怎么实现"
