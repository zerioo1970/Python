## 16.1 什么时候用文件，什么时候该用数据库

先把定位说清楚，免得以后用错工具。

| 情况 | 用什么 |
|---|---|
| 单机、数据量小（几千行以内）、结构简单 | **文件**（本章 + 第 17 章） |
| 要按条件查询、要排序分页 | 数据库 |
| 多人同时读写 | 数据库 |
| 数据关系复杂（多张表互相关联） | 数据库 |
| 只是存个配置、存个运行记录 | **文件** |

**给有 SQL 背景的读者**：你会本能地想到数据库，但**别小看文件**。配置、日志、导入导出、缓存中间结果，这些在真实项目里全是文件。数据库的完整讨论在专项 C。

**一句话判断**：**需要"查"就用数据库，只需要"存和取"就用文件。**

## 16.2 写与读：最短的完整例子

**示例 16-1　写下第一个文件**

```python
with open("note.txt", "w", encoding="utf-8") as f:
    n = f.write("你好，文件")

print(n)                    # => 5        write 返回写入的字符数
```

这一行 `with open(...)` 里有四样东西，逐个说明：

| 部分 | 含义 |
|---|---|
| `"note.txt"` | 文件名（相对于**工作目录**，见 16.11） |
| `"w"` | 模式：写。**⚠️ 文件已存在会被清空**（16.3） |
| `encoding="utf-8"` | 字符编码。**永远显式写**（16.7） |
| `as f` | 把打开的文件对象叫做 `f` |
| `with` | 块结束时**自动关闭文件**（16.4） |

**示例 16-2　把它读回来**

```python
with open("note.txt", "r", encoding="utf-8") as f:
    content = f.read()

print(repr(content))        # => '你好，文件'
```

`"r"` 是默认模式，可以省略：`open("note.txt", encoding="utf-8")`。

> **为什么用 `repr()` 打印？** 因为它会把 `\n`、`\t` 这些看不见的字符显示出来。**读文件时经常要看清有没有多余的换行符**，`repr` 是最方便的手段（第 3 章介绍过）。

**示例 16-3　`write` 不会自动换行**

这一点和 `print` 完全不同，是新手第一个意外：

```python
# ❌ 三次 write，全挤在一行
with open("a.txt", "w", encoding="utf-8") as f:
    f.write("第一行")
    f.write("第二行")
    f.write("第三行")

print(repr(open("a.txt", encoding="utf-8").read()))
# => '第一行第二行第三行'
```

```python
# ✅ 自己加 \n
with open("b.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
    f.write("第二行\n")

print(repr(open("b.txt", encoding="utf-8").read()))
# => '第一行\n第二行\n'
```

**记法**：`print` 是"给人看的"，默认帮你换行；`write` 是"写字节的"，一个字符都不多给。

（上面为了简短，读的时候直接用了 `open(...).read()` 没有配 `with`——**正式代码里不要这么写**，理由见 16.4。）

## 16.3 ⚠️ `w` 模式会清空文件

> # ⚠️ 本章最危险的一节
>
> **`open(路径, "w")` 这一行执行完，原文件的内容就没了——即使你之后一个字都不写。**

**示例 16-4　`w` 模式清空了我的文件**

```python
# 先造一个"很重要"的文件
with open("data.txt", "w", encoding="utf-8") as f:
    f.write("很重要的数据")

print(repr(open("data.txt", encoding="utf-8").read()))
# => '很重要的数据'
```

```python
# ❌ 只是以 w 打开，什么都没写
with open("data.txt", "w", encoding="utf-8") as f:
    pass                    # 真的什么都没做

print(repr(open("data.txt", encoding="utf-8").read()))
# => ''            原来的内容全没了
```

**没有确认提示，没有警告，没有回收站。** 这个操作是不可撤销的。

**为什么会这样？** 因为 `w` 的语义是"**从头开始写**"——它一打开就把文件截断（truncate）成 0 字节，等你往里写。你不写，它就是空的。

### 三种安全做法

```python
# ✅ 做法一：要在末尾添加，用 a（追加）
with open("data.txt", "a", encoding="utf-8") as f:
    f.write("新增一行\n")
```

```python
# ✅ 做法二：绝不允许覆盖，用 x（独占创建）
with open("brand_new.txt", "x", encoding="utf-8") as f:
    f.write("只有文件不存在时才会成功")
```

```python
from pathlib import Path

# ✅ 做法三：不确定就先判断
p = Path("data.txt")
if p.exists():
    print("文件已存在，请确认是否覆盖")
else:
    with open(p, "w", encoding="utf-8") as f:
        f.write("内容")
```

> **记住这条**：**看到 `"w"`，先想一秒"这个文件里有东西吗"。**
>
> **真实事故的样子**：写个脚本处理数据，调试时反复运行。某次你把输入文件名和输出文件名写成了同一个——`open(源文件, "w")`。**源数据在那一瞬间就没了**，而你还在纳闷为什么处理结果是空的。
>
> **所以本章开头建议你新建一个空目录练手**，就是这个原因。

## 16.4 `with` 语句：不是好习惯，是必须

**示例 16-8　不用 `with` 会怎样**

先看现象。下面这段代码写了内容，但**在 `close()` 之前，文件其实是空的**：

```python
from pathlib import Path

f = open("noclose.txt", "w", encoding="utf-8")
f.write("还在缓冲区里")

# 此刻从另一处去读这个文件
print(repr(Path("noclose.txt").read_text(encoding="utf-8")))
# => ''                    什么都没有！

f.close()
print(repr(Path("noclose.txt").read_text(encoding="utf-8")))
# => '还在缓冲区里'          close 之后才落盘
```

**为什么？** 因为写文件是**带缓冲的**——数据先攒在内存里，攒够一批或者关闭时才真正写进磁盘。这是为了性能（每写一个字都去碰磁盘会慢得无法忍受）。

**不关文件的三个后果**：

| 后果 | 说明 |
|---|---|
| **数据可能没落盘** | 程序崩了、断电了，缓冲区里的内容就丢了 |
| **文件被占用** | Windows 上尤其明显——别的程序打不开，你自己也删不掉 |
| **句柄耗尽** | 循环里打开几千个文件不关，会报 `OSError: Too many open files` |

**示例 16-9　`with` 等价于 `try/finally`**

`f.close()` 看着简单，但**它不可靠**——中间抛异常就执行不到了。第 15.8 节学过的 `finally` 正是为此而生：

```python
# 手写版：这才是可靠的
f = open("exc.txt", "w", encoding="utf-8")
try:
    f.write("写了一半")
    raise ValueError("中间出错了")
except ValueError as e:
    print("捕获:", e)                   # => 捕获: 中间出错了
finally:
    f.close()                           # 无论如何都关
    print("closed =", f.closed)         # => closed = True
```

**`with` 就是上面这一整套的语法糖**：

```python
with open("x.txt", "w", encoding="utf-8") as f:
    f.write("内容")
# 到这里，f 已经自动关好了
```

**示例 16-10　出异常时 `with` 照样关文件**

```python
from pathlib import Path

try:
    with open("exc2.txt", "w", encoding="utf-8") as f:
        f.write("写了一半")
        raise ValueError("块内抛异常")
except ValueError:
    pass

print(f.closed)                                             # => True
print(repr(Path("exc2.txt").read_text(encoding="utf-8")))    # => '写了一半'
```

**块内抛了异常，文件依然被正确关闭，已写的内容依然落盘。** 这就是 `with` 的全部价值。

> **记住这条**：**打开文件一律用 `with`，没有例外。**
>
> 你在别人代码里看到裸的 `open(...)` 后面跟 `close()`，那是老写法或者疏忽。
>
> `with` 的完整原理（上下文管理器协议、怎么写自己的 `with`）在第 32 章。**现在只要照着用。**

## 16.5 六种模式

**示例 16-7　六种模式对照**

选模式的真正依据是**这两列**：

| 模式 | 作用 | 文件**不存在**时 | 文件**已存在**时 |
|---|---|---|---|
| `r` | 读（默认） | ❌ `FileNotFoundError` | 从头读 |
| **`w`** | 写 | 创建 | **⚠️ 清空！** |
| `a` | 追加 | 创建 | 从末尾接着写 |
| `x` | 独占创建 | 创建 | ❌ `FileExistsError` |
| `r+` | 读写 | ❌ `FileNotFoundError` | 从头，不清空 |
| `w+` | 读写 | 创建 | **⚠️ 清空！** |

加 `b` 变二进制（`rb` / `wb`），见 16.8。

实测几个边界：

```python
open("不存在.txt", encoding="utf-8")
# => FileNotFoundError: [Errno 2] No such file or directory: '不存在.txt'
```

**示例 16-5　追加模式**

```python
from pathlib import Path

with open("log.txt", "w", encoding="utf-8") as f:
    f.write("第一条\n")
with open("log.txt", "a", encoding="utf-8") as f:      # a 不会清空
    f.write("第二条\n")
with open("log.txt", "a", encoding="utf-8") as f:
    f.write("第三条\n")

print(repr(Path("log.txt").read_text(encoding="utf-8")))
# => '第一条\n第二条\n第三条\n'
```

**示例 16-6　`x` 模式：绝不覆盖**

```python
with open("new.txt", "x", encoding="utf-8") as f:
    f.write("第一次创建成功")

print(open("new.txt", encoding="utf-8").read())     # => 第一次创建成功
```

```python
# 同一个文件再来一次
with open("new.txt", "x", encoding="utf-8") as f:
    f.write("覆盖")
# => FileExistsError: [Errno 17] File exists: 'new.txt'
```

**`x` 的价值就是"宁可报错也别覆盖"**。生成报表、导出文件时用它，能挡住"手一滑覆盖了昨天的结果"。

**日常九成场景只用三个**：`r` 读、`a` 追加、`w` 写（**确认可以覆盖时**）。

## 16.6 读的四种方式

**示例 16-11　读的四种方式**

假设 `poem.txt` 的内容是三行：`第一行\n第二行\n第三行\n`。

```python
with open("poem.txt", encoding="utf-8") as f:
    print(repr(f.read()))           # => '第一行\n第二行\n第三行\n'      一次读全部
```

```python
with open("poem.txt", encoding="utf-8") as f:
    print(repr(f.read(3)))          # => '第一行'                      只读 3 个字符
```

```python
with open("poem.txt", encoding="utf-8") as f:
    print(repr(f.readline()))       # => '第一行\n'                    读一行
    print(repr(f.readline()))       # => '第二行\n'                    再读下一行
```

```python
with open("poem.txt", encoding="utf-8") as f:
    print(f.readlines())            # => ['第一行\n', '第二行\n', '第三行\n']    读成列表
```

```python
with open("poem.txt", encoding="utf-8") as f:
    for i, line in enumerate(f, 1):     # ✅ 逐行迭代：首选
        print(i, repr(line))
# => 1 '第一行\n'
# => 2 '第二行\n'
# => 3 '第三行\n'
```

**五种写法怎么选**：

| 写法 | 得到 | 什么时候用 |
|---|---|---|
| `f.read()` | 一个大字符串 | **确定文件小**，且要整体处理（比如做替换） |
| `f.read(n)` | n 个字符 | 很少用（分块处理超大文件） |
| `f.readline()` | 一行字符串 | 很少用（需要精细控制读到第几行时） |
| `f.readlines()` | 列表 | 需要索引、需要 `len()`、需要多次遍历时 |
| **`for line in f`** | 一行一行 | **默认就用它** |

**示例 16-12　大文件必须逐行读**

```python
# ❌ read() 把整个文件塞进内存
with open("huge.log", encoding="utf-8") as f:
    content = f.read()          # 文件 2GB，内存就要吃掉 2GB 以上
```

```python
# ✅ 逐行读：一次只占一行的内存，文件多大都无所谓
with open("huge.log", encoding="utf-8") as f:
    for line in f:
        if "ERROR" in line:
            print(line.rstrip("\n"))
```

**为什么 `for line in f` 不占内存？** 因为文件对象是**可迭代对象**（第 13.2 节讲过），它一次只从磁盘取一行交给你，不预先读全部。

> **判断标准**：**文件可能超过几十 MB，就必须逐行读。** 日志、导出数据、CSV 这类"行数不确定"的文件，一律逐行。
>
> `readlines()` 和 `read()` 有同样的内存问题——它把所有行都装进列表了。

**示例 16-13　每行都带着 `\n`**

**这是读文件最高频的坑**：

```python
with open("poem.txt", encoding="utf-8") as f:
    line = f.readline()

print(repr(line))                       # => '第一行\n'        末尾有换行符！
print(line == "第一行")                  # => False            所以比较失败
print(line.strip() == "第一行")          # => True             去掉才相等
print(repr(line.rstrip("\n")))          # => '第一行'
```

**`line == "第一行"` 永远是 `False`**，而你盯着屏幕上打印出来的"第一行"想不通哪里不对——因为换行符看不见。

**两种去法，各有适用场景**：

| 写法 | 去掉什么 | 什么时候用 |
|---|---|---|
| `line.strip()` | 两端**所有**空白（空格、制表符、换行） | 大多数情况，输入不干净时 |
| `line.rstrip("\n")` | 只去右边的换行符 | **要保留行首缩进**时（比如读代码、读有缩进格式的文件） |

**还有一个边界**：最后一行**可能没有换行符**（取决于文件是怎么保存的）：

```python
from pathlib import Path

Path("noend.txt").write_text("甲\n乙", encoding="utf-8")     # 乙 后面没有 \n
with open("noend.txt", encoding="utf-8") as f:
    print(f.readlines())        # => ['甲\n', '乙']           最后一项没有 \n
```

**所以不要靠"每行都有 `\n`"来写逻辑**，统一 `strip()` 最省事。

**示例 16-14　读第二次是空的**

```python
with open("poem.txt", encoding="utf-8") as f:
    first = f.read()
    print(len(first))           # => 12
    second = f.read()
    print(repr(second))         # => ''            第二次什么都没有！

    f.seek(0)                   # 把指针挪回开头
    print(len(f.read()))        # => 12            又能读到了
```

**原因**：文件对象内部有一个**指针**，记着"读到哪儿了"。第一次 `read()` 把它推到了末尾，第二次自然读不到东西。

| 方法 | 作用 |
|---|---|
| `f.seek(0)` | 回到文件开头 |
| `f.tell()` | 当前位置（**文本模式下这个数字是字节数，不是字符数**，别当字符位置用） |

**同一个道理也适用于逐行迭代**：`for line in f` 走完一遍之后，再来一次就什么都没有了。要遍历两遍就 `seek(0)`，或者干脆读进列表。

**示例 16-15　写多行的两种方式**

```python
from pathlib import Path

lines = ["甲\n", "乙\n", "丙\n"]        # 注意元素自带 \n

# 方式一：循环 write
with open("m1.txt", "w", encoding="utf-8") as f:
    for s in lines:
        f.write(s)
print(repr(Path("m1.txt").read_text(encoding="utf-8")))     # => '甲\n乙\n丙\n'

# 方式二：writelines（一次写一个列表）
with open("m2.txt", "w", encoding="utf-8") as f:
    f.writelines(lines)
print(repr(Path("m2.txt").read_text(encoding="utf-8")))     # => '甲\n乙\n丙\n'
```

**⚠️ `writelines` 这个名字骗人——它也不会自动换行**：

```python
from pathlib import Path

with open("m3.txt", "w", encoding="utf-8") as f:
    f.writelines(["甲", "乙", "丙"])        # 元素里没有 \n

print(repr(Path("m3.txt").read_text(encoding="utf-8")))     # => '甲乙丙'      挤成一行了
```

名字里有 `lines`，实际行为却是"把列表里的字符串一个接一个写下去"，一个换行符都不加。**它等价于一个 `for` 循环，仅此而已。**

**推荐第三种写法，意图最清楚**：

```python
from pathlib import Path

with open("m4.txt", "w", encoding="utf-8") as f:
    f.write("\n".join(["甲", "乙", "丙"]) + "\n")     # join 拼好，末尾补一个

print(repr(Path("m4.txt").read_text(encoding="utf-8")))     # => '甲\n乙\n丙\n'
```

用 `"\n".join(...)` 的好处是**数据里不用带换行符**——列表就是干净的数据，换行是写文件时才加的格式。末尾那个 `+ "\n"` 是让最后一行也有换行符（文本文件的惯例）。

## 16.7 编码：中文乱码的头号原因

**示例 16-16　不写 `encoding` 的后果**

`open()` 的 `encoding` 参数不写会怎样？**用系统默认编码**。而默认编码**各平台不同**：

| 平台 | 默认编码 |
|---|---|
| Linux / macOS | UTF-8 |
| **Windows（中文版）** | **GBK / cp936** |

**这意味着同一段代码在两台机器上行为不同：**

```python
# ❌ 没写 encoding
with open("中文.txt", "w") as f:      # Windows 上用 GBK 写，Linux 上用 UTF-8 写
    f.write("你好")
```

你在自己机器上测得好好的，**同事一跑就乱码**，或者你写的文件别的程序读不了。这是中文乱码的**头号原因**。

可以看看自己机器的默认值：

```python
import locale
print(locale.getpreferredencoding(False))    # => UTF-8      我这台是 Linux
```

**示例 16-17　读懂 `UnicodeDecodeError`**

编码对不上时的真实报错：

```python
from pathlib import Path

# 造一个 GBK 编码的文件
Path("gbk.txt").write_bytes("中文内容".encode("gbk"))

# 用 UTF-8 去读它
Path("gbk.txt").read_text(encoding="utf-8")
# => UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd6 in position 0: invalid continuation byte
```

```python
from pathlib import Path

print(Path("gbk.txt").read_text(encoding="gbk"))    # => 中文内容      用对就正常
```

反过来也一样：

```python
from pathlib import Path

Path("u8.txt").write_text("中文内容", encoding="utf-8")
Path("u8.txt").read_text(encoding="gbk")
# => UnicodeDecodeError: 'gbk' codec can't decode byte 0xad in position 2: illegal multibyte sequence
```

**报错怎么读**：

```text
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd6 in position 0: invalid continuation byte
                     ↑用哪种编码解的     ↑哪个字节    ↑第几个字节
```

**三种常见成因**：

| 成因 | 判断方法 | 解决 |
|---|---|---|
| **编码猜错了** | 位置往往在第一个中文字符处 | 换 `encoding="gbk"` 试试 |
| **其实是二进制文件** | 位置在 0，且字节像 `0x89`、`0xff` | 用 `"rb"` 模式（16.8） |
| 文件被截断/损坏 | 位置在文件末尾附近 | 检查文件来源 |

第二种见识一下：

```python
from pathlib import Path

Path("bin.dat").write_bytes(bytes([0x89, 0x50, 0x4E, 0x47, 0xFF, 0xFE]))    # 假装是个 PNG
Path("bin.dat").read_text(encoding="utf-8")
# => UnicodeDecodeError: 'utf-8' codec can't decode byte 0x89 in position 0: invalid start byte
```

（`0x89 0x50 0x4E 0x47` 正是 PNG 文件的开头——把图片当文本读就是这个报错。）

> # 铁律：读写文本文件永远显式写 `encoding="utf-8"`
>
> 没有例外。哪怕文件里全是英文——因为你不知道以后会不会有人往里加中文。
>
> **要读别人给的 GBK 文件怎么办？** 显式写 `encoding="gbk"`。**关键是"显式"**，不是"用哪个"。
>
> **补充一个未来变化**：Python 3.15 起默认编码将改为 UTF-8（PEP 686）。但**现在写代码不能依赖它**——你的代码可能在 3.10、3.12 上跑，而且写清楚本身就是好事。

**读来源不明的文件时，有个实用的兜底**：

```python
# errors="replace"：解不开的字节用 � 代替，不抛异常
with open("unknown.txt", encoding="utf-8", errors="replace") as f:
    content = f.read()
```

**但这只适合"先看看里面是什么"的探查场景**，不要用在正式的数据处理上——那等于默许数据损坏。

## 16.8 二进制模式

**示例 16-18　二进制方式复制一个文件**

不关心内容、只想搬字节时，用 `"rb"` / `"wb"`：

```python
from pathlib import Path

with open("poem.txt", "rb") as f:           # rb：二进制读
    raw = f.read()

print(type(raw).__name__)                   # => bytes
print(raw[:12])                             # => b'\xe7\xac\xac\xe4\xb8\x80\xe8\xa1\x8c\n\xe7\xac'

with open("copy.txt", "wb") as f:           # wb：二进制写
    f.write(raw)

print(Path("copy.txt").read_bytes() == raw) # => True      一模一样
```

读到的是 **`bytes`**（第 5.12 节介绍过），不是 `str`。

**二进制模式不能有 `encoding` 参数**——因为它不做任何编解码：

```python
open("poem.txt", "rb", encoding="utf-8")
# => ValueError: binary mode doesn't take an encoding argument
```

顺便验证一下第 5 章那个结论：

```python
print(len("中".encode("utf-8")))     # => 3        一个中文在 UTF-8 里占 3 字节
```

所以 `第一行\n` 这 4 个字符是 3×3+1 = 10 字节，三行共 30 字节。**这就是为什么 `f.tell()` 给的数和字符数不一样。**

**什么时候用二进制模式**：

| 场景 | 原因 |
|---|---|
| 图片、Excel、PDF、压缩包 | 它们本来就不是文本 |
| **只是复制/移动文件，不看内容** | 不用管编码，也不会改坏内容 |
| 计算文件的哈希值 | 哈希是按字节算的 |

（不过纯复制文件有更省事的办法：`shutil.copy(源, 目标)`。）

## 16.9 `pathlib`：现代的路径操作方式

前面一直在用字符串当路径，那是能用但笨拙的做法。**`pathlib` 是现在的标准答案。**

**示例 16-19　`pathlib` 上手**

```python
from pathlib import Path

p = Path("data") / "reports" / "2026年报.txt"     # 用 / 拼路径！

print(p)                    # => data/reports/2026年报.txt
print(p.name)               # => 2026年报.txt        文件名（含后缀）
print(p.stem)               # => 2026年报            文件名（不含后缀）
print(p.suffix)             # => .txt                后缀（带点）
print(p.parent)             # => data/reports        所在目录
print(p.parts)              # => ('data', 'reports', '2026年报.txt')
print(p.is_absolute())      # => False               是绝对路径吗
```

**用 `/` 拼路径是 `pathlib` 最舒服的设计**，而且**跨平台**——你不用管 Windows 是 `\` 还是 Linux 是 `/`，`Path` 自己处理。

**这同时解决了第 5.2 节那个转义坑**：

```python
from pathlib import Path

# ❌ Windows 路径写成普通字符串，\n 会被当成换行符
bad = "C:\new\table.txt"
print(repr(bad))            # => 'C:\new\table.txt'      \n 和 \t 都被转义了

# ✅ 三种正确写法
print(repr(r"C:\new\table.txt"))            # => 'C:\\new\\table.txt'   原始字符串
print(Path("C:/new/table.txt"))             # => C:/new/table.txt       用正斜杠
print(Path("C:/") / "new" / "table.txt")    # => C:/new/table.txt       用 / 拼
```

**判断与信息**：

```python
from pathlib import Path

p = Path("poem.txt")
print(p.exists(), p.is_file(), p.is_dir())      # => True True False
print(p.stat().st_size)                          # => 30        字节数
print(p.with_suffix(".md"))                      # => poem.md   换后缀
print(p.with_name("other.txt"))                  # => other.txt 换文件名
```

**示例 16-20　一行读写小文件**

`pathlib` 有一对极省事的方法：

```python
from pathlib import Path

p = Path("oneline.txt")
p.write_text("一行写完\n", encoding="utf-8")            # 一行写

print(repr(p.read_text(encoding="utf-8")))              # => '一行写完\n'
print(p.read_text(encoding="utf-8").splitlines())       # => ['一行写完']
```

它们内部自己开关文件，**不用写 `with`**。

| 写法 | 什么时候用 |
|---|---|
| `p.read_text()` / `p.write_text()` | **小文件**，一次性整体读写。最短 |
| `p.read_bytes()` / `p.write_bytes()` | 同上，二进制版 |
| `with open(p) as f:` + 逐行 | **大文件**，或需要边读边处理 |

**注意 `read_text` 也是一次性读全部**，所以大文件照样不能用它——`for line in f` 无可替代。

**`splitlines()` 比 `split("\n")` 好**：它自动处理最后一行有没有换行符，也认 Windows 的 `\r\n`。

**示例 16-21　建目录**

```python
from pathlib import Path

d = Path("out") / "sub" / "deep"

# ❌ 默认不会自动建父目录
Path("out/sub/deep").mkdir()
# => FileNotFoundError: [Errno 2] No such file or directory: 'out/sub/deep'
```

```python
from pathlib import Path

d = Path("out") / "sub" / "deep"
d.mkdir(parents=True)               # ✅ parents=True：连父目录一起建
print(d.exists())                   # => True
```

```python
from pathlib import Path

d = Path("out") / "sub" / "deep"
d.mkdir(parents=True)
# => FileExistsError: [Errno 17] File exists: 'out/sub/deep'
```

```python
from pathlib import Path

d = Path("out") / "sub" / "deep"
d.mkdir(parents=True, exist_ok=True)    # ✅ exist_ok=True：已存在也不报错
```

> **记住这个组合**：**`mkdir(parents=True, exist_ok=True)`**。九成情况你要的就是它——"把这个目录准备好，已经有了就算了"。

**示例 16-23　删除与改名**

```python
from pathlib import Path

t = Path("tmp1.txt")
t.write_text("x", encoding="utf-8")

t.unlink()                          # 删除文件（不是 delete，是 unlink）
print(t.exists())                   # => False

t.unlink()
# => FileNotFoundError: [Errno 2] No such file or directory: 'tmp1.txt'
```

```python
from pathlib import Path

Path("tmp1.txt").unlink(missing_ok=True)    # ✅ 不存在也不报错（3.8+）
```

```python
from pathlib import Path

a = Path("old.txt")
a.write_text("x", encoding="utf-8")
b = a.rename("newname.txt")         # 改名，返回【新路径】

print(b)                            # => newname.txt
print(a.exists())                   # => False        旧路径没了
```

**注意 `rename` 返回新路径**，原来的 `a` 还指着旧位置（已经不存在了）。想接着操作要用返回值 `b`。

**删目录不是 `unlink`**：

| 要删的东西 | 用 |
|---|---|
| 文件 | `p.unlink(missing_ok=True)` |
| **空**目录 | `p.rmdir()` |
| **非空**目录（连内容一起删） | `shutil.rmtree(p)` ⚠️ **不可撤销，用前确认路径** |

## 16.10 遍历目录

**示例 16-22　列出目录内容**

三个方法，区别在"一层还是递归"：

```python
from pathlib import Path

# 目录结构：out/a.txt  out/b.log  out/sub/c.txt  out/sub/deep/d.txt

print(sorted(str(x) for x in Path("out").iterdir()))
# => ['out/a.txt', 'out/b.log', 'out/sub']                        只一层，含子目录本身

print(sorted(str(x) for x in Path("out").glob("*.txt")))
# => ['out/a.txt']                                                只一层，按模式过滤

print(sorted(str(x) for x in Path("out").rglob("*.txt")))
# => ['out/a.txt', 'out/sub/c.txt', 'out/sub/deep/d.txt']         递归所有子目录
```

| 方法 | 范围 | 过滤 |
|---|---|---|
| `iterdir()` | 只当前一层 | 无（文件和目录都给） |
| `glob("*.txt")` | 只当前一层 | 按通配符 |
| **`rglob("*.txt")`** | **递归所有子目录** | 按通配符 |

`rglob("*.txt")` 等价于 `glob("**/*.txt")`，前者更短。

**只要文件不要目录**，加个 `is_file()`：

```python
from pathlib import Path

print(sorted(str(x) for x in Path("out").iterdir() if x.is_file()))
# => ['out/a.txt', 'out/b.log']
```

> **两个必须注意的**：
>
> **① 一律套 `sorted()`。** 文件系统**不保证**返回顺序，同一份代码在不同机器、不同文件系统上顺序可能不同。这和第 12 章集合那个坑是同一类问题——**不报错，但结果不可复现**。
>
> **② 别边遍历边改。** 遍历目录时改名、删除、新建，行为不可预料（可能漏文件、可能重复处理）。**先收集成列表，再处理**：
>
> ```python
> files = sorted(Path("out").rglob("*.txt"))      # 先收集
> for f in files:                                  # 再处理
>     f.rename(...)
> ```
>
> 这和第 9.18 节"遍历列表时不能删元素"是同一个道理。

## 16.11 工作目录 ≠ 脚本目录

**这是"在我这儿能跑"的经典来源**，也是本章最容易困惑的一节。

**示例 16-24　工作目录不是脚本目录**

有个脚本 `demo/app_bad.py`，它要读旁边的 `demo/data.txt`：

```python
from pathlib import Path

print("当前工作目录 :", Path.cwd())
print("脚本所在目录 :", Path(__file__).resolve().parent)

# ❌ 相对路径是相对于【工作目录】，不是脚本所在目录
content = Path("data.txt").read_text(encoding="utf-8")
print("读到:", content.strip())
```

**在脚本所在目录运行——正常**：

```text
$ cd demo
$ python3.12 app_bad.py
当前工作目录 : /projects/sandbox/Python/_scratch/demo
脚本所在目录 : /projects/sandbox/Python/_scratch/demo
读到: 脚本自带的资源
```

**从上一级目录运行——崩了**：

```text
$ cd ..
$ python3.12 demo/app_bad.py
当前工作目录 : /projects/sandbox/Python/_scratch
脚本所在目录 : /projects/sandbox/Python/_scratch/demo
Traceback (most recent call last):
  ...
FileNotFoundError: [Errno 2] No such file or directory: 'data.txt'
```

**同一个脚本、同一个文件，换个地方启动就找不到了。**

看那两行打印就明白了：**工作目录变了，脚本目录没变**。而 `Path("data.txt")` 是相对于**工作目录**解析的。

> **这就是"在 PyCharm / VS Code 里能跑，在命令行里就 `FileNotFoundError`"的原因**——IDE 通常把工作目录设成项目根目录，而你的脚本在子目录里。

**解法**：以**脚本自己的位置**为基准。

```python
from pathlib import Path

# ✅ __file__ 是当前脚本的路径；resolve() 转成绝对路径；parent 取所在目录
HERE = Path(__file__).resolve().parent
content = (HERE / "data.txt").read_text(encoding="utf-8")
print("读到:", content.strip())
```

两种启动方式都正常：

```text
$ python3.12 demo/app_good.py
读到: 脚本自带的资源
$ cd demo && python3.12 app_good.py
读到: 脚本自带的资源
```

**但不是所有路径都该这么写**，这一点很重要：

| 要访问什么 | 怎么写 | 原因 |
|---|---|---|
| **程序自带的资源**（模板、内置数据、配置默认值） | `Path(__file__).parent / "..."` | 它跟着代码一起走，位置固定 |
| **用户指定的文件**（命令行参数、用户输入的路径） | **直接用用户给的路径** | 用户是站在自己的工作目录说话的 |
| 程序的输出 | 一般用相对路径（即工作目录），或让用户指定 | 用户希望输出在他当前的位置 |

**用错方向的后果**：用户在 `~/我的数据/` 目录下运行你的工具，说"处理 `input.csv`"，你却拿 `脚本目录/input.csv` 去找——**永远找不到**。

> **记住这条**：**"跟着代码走的文件"用 `Path(__file__).parent`；"用户说的文件"用原样路径。**

`Path.cwd()` 就是工作目录，需要时可以打印出来看：

```python
from pathlib import Path
print(Path.cwd())           # 你运行时的路径会不同
```

## 16.12 `os.path` 与 `pathlib` 对照

老项目里全是 `os.path`，你得看得懂。**新代码一律用 `pathlib`。**

**示例 16-25　两种写法并排**

```python
import os
from pathlib import Path

print(os.path.join("data", "a.txt"))            # => data/a.txt
print(Path("data") / "a.txt")                   # => data/a.txt

print(os.path.basename("data/a.txt"))           # => a.txt
print(Path("data/a.txt").name)                  # => a.txt

print(os.path.dirname("data/a.txt"))            # => data
print(Path("data/a.txt").parent)                # => data

print(os.path.splitext("data/a.txt"))           # => ('data/a', '.txt')
print(Path("data/a.txt").stem, Path("data/a.txt").suffix)    # => a .txt
```

完整对照表：

| `os` / `os.path` | `pathlib` |
|---|---|
| `os.path.join(a, b)` | `Path(a) / b` |
| `os.path.exists(p)` | `Path(p).exists()` |
| `os.path.isfile(p)` / `isdir(p)` | `.is_file()` / `.is_dir()` |
| `os.path.basename(p)` | `.name` |
| `os.path.dirname(p)` | `.parent` |
| `os.path.splitext(p)` | `.stem` + `.suffix` |
| `os.path.abspath(p)` | `.resolve()` |
| `os.path.getsize(p)` | `.stat().st_size` |
| `os.listdir(d)` | `.iterdir()` |
| `os.makedirs(d, exist_ok=True)` | `.mkdir(parents=True, exist_ok=True)` |
| `os.remove(p)` | `.unlink()` |
| `os.rmdir(d)` | `.rmdir()` |
| `os.rename(a, b)` | `.rename(b)` |
| `os.getcwd()` | `Path.cwd()` |
| `glob.glob("**/*.txt", recursive=True)` | `.rglob("*.txt")` |

**为什么 `pathlib` 更好**：

1. **路径是对象不是字符串**——`p.suffix` 比 `os.path.splitext(p)[1]` 好读得多
2. **`/` 拼接**，不用 `os.path.join` 套一层
3. **方法都挂在对象上**，编辑器能补全，不用记 `os.path` 下面有什么
4. 跨平台处理是内建的

**`os` 里仍然要用的东西**（`pathlib` 不管这些）：`os.environ`（环境变量，第 24 章）、`os.cpu_count()`、`os.getpid()`。

## 16.13 安全写入

**示例 16-26　先写临时文件再替换**

直接写目标文件有个风险：**写到一半程序崩了，文件就半新半旧，原数据也没了。**

```python
from pathlib import Path

target = Path("config.txt")
target.write_text("旧配置\n", encoding="utf-8")

# ✅ 先写临时文件，写完整了再一次性替换
tmp = target.with_suffix(".txt.tmp")
tmp.write_text("新配置\n", encoding="utf-8")
tmp.replace(target)                             # 原子替换

print(repr(target.read_text(encoding="utf-8")))     # => '新配置\n'
print(tmp.exists())                                  # => False     临时文件已被移走
```

**`Path.replace()` 是原子操作**——在同一个文件系统内，它要么完全成功，要么完全没发生，**不存在"替换了一半"的中间状态**。

**注意 `replace` 和 `rename` 的区别**：

| 方法 | 目标已存在时 |
|---|---|
| `p.rename(目标)` | **Windows 上报错**，Linux 上覆盖（行为不一致！） |
| **`p.replace(目标)`** | **一律覆盖**，跨平台行为一致 |

**要覆盖就用 `replace`**，别用 `rename`。

**什么时候值得这么做**：配置文件、数据文件等"**损坏了会造成麻烦**"的文件。临时的中间结果不用讲究。

### 示例 16-27　统计一个文本文件的词频

回收第 11.16 节的字典计数，这次数据来自真实文件。

**创建的文件**：`article.txt`

```python
from pathlib import Path

Path("article.txt").write_text(
    "Python is easy to learn.\n"
    "Python has a clean syntax, and Python has many libraries.\n"
    "Many people use Python for data analysis.\n",
    encoding="utf-8")

counter = {}
with open("article.txt", encoding="utf-8") as f:
    for line in f:                          # 逐行读，文件多大都不怕
        for ch in ",.!?;:":                 # 把标点换成空格，否则 "learn." 会被当一个词
            line = line.replace(ch, " ")
        for word in line.lower().split():   # lower() 让 Python 和 python 算同一个词
            counter[word] = counter.get(word, 0) + 1

print(f"共 {len(counter)} 个不同的词，{sum(counter.values())} 个词次")
# => 共 17 个不同的词，22 个词次

# 按次数降序；次数相同时按字母升序（保证输出可复现）
for word, n in sorted(counter.items(), key=lambda kv: (-kv[1], kv[0]))[:5]:
    print(f"  {word:<10} {n}")
# =>   python     4
# =>   has        2
# =>   many       2
# =>   a          1
# =>   analysis   1
```

**注意 `key=lambda kv: (-kv[1], kv[0])` 这个写法**：返回元组就是"先按第一项排，相同再按第二项排"。`-kv[1]` 取负号实现降序。**不加第二个排序依据，次数相同的词顺序就不确定了**——和第 12 章那个"顺序从未被承诺"是同一类考虑。

**这个方法对中文不适用**，得说清楚：

```python
line = "Python 的语法简洁，Python 的库很多。"
print(line.replace("，", " ").replace("。", " ").split())
# => ['Python', '的语法简洁', 'Python', '的库很多']
```

**中文词之间没有空格**，`split()` 切不开。中文分词需要专门的库（如 `jieba`），超出本书范围。

### 示例 16-28　给程序加一份运行记录

**创建的文件**：`run.log`（追加模式，不会覆盖）

```python
import time
from pathlib import Path

LOG = Path("run.log")

def record(msg):
    """往日志文件追加一行，带时间戳。"""
    stamp = time.strftime("%Y-%m-%d %H:%M:%S")      # 正规的时间处理见第 23 章
    with open(LOG, "a", encoding="utf-8") as f:     # a 模式：不会清空原有内容
        f.write(f"{stamp} {msg}\n")                 # 记得自己加 \n

record("程序启动")
record("处理了 3 个文件")
record("程序结束")

print(LOG.read_text(encoding="utf-8"), end="")
```

```text
2026-08-01 14:38:06 程序启动
2026-08-01 14:38:06 处理了 3 个文件
```

### 示例 16-29　按后缀分类整理一个目录

**验收项目 B2 的雏形。创建的文件**：`messy/` 目录及其下若干文件。

**注意它先做"干跑"**——只打印计划、不真动手。**这是处理批量文件操作的标准做法**：

```python
from pathlib import Path

messy = Path("messy")
messy.mkdir(exist_ok=True)
for name in ["报告.txt", "笔记.txt", "图.png", "照片.jpg", "数据.csv", "脚本.py", "无后缀"]:
    (messy / name).write_text("x", encoding="utf-8")

# 先分组：后缀 -> 文件列表
groups = {}
for item in sorted(messy.iterdir()):        # sorted 保证顺序可复现
    if not item.is_file():                  # 跳过子目录
        continue
    kind = item.suffix.lstrip(".").lower() or "其他"    # 没有后缀的归到"其他"
    groups.setdefault(kind, []).append(item)             # 分组（11.17 节的写法）

print("--- 干跑（只打印，不动手）---")
for kind, items in sorted(groups.items()):
    print(f"  {kind}/  <- {[i.name for i in items]}")
```

```text
--- 干跑（只打印，不动手）---
  csv/  <- ['数据.csv']
  jpg/  <- ['照片.jpg']
  png/  <- ['图.png']
  py/  <- ['脚本.py']
  txt/  <- ['报告.txt', '笔记.txt']
  其他/  <- ['无后缀']
```

**确认计划没问题，再真正执行**：

```python
for kind, items in sorted(groups.items()):
    folder = messy / kind
    folder.mkdir(exist_ok=True)             # 目录可能已经有了
    for item in items:
        item.rename(folder / item.name)     # 移动
        print(f"  移动 {item.name} -> {kind}/")
```

**这段代码有三个刻意的设计**：

| 做法 | 为什么 |
|---|---|
| **先分组收集，再统一移动** | 不能边遍历 `iterdir()` 边改名（16.10 讲过） |
| `suffix.lstrip(".").lower()` | `.TXT` 和 `.txt` 归一类；`lstrip(".")` 去掉那个点 |
| `or "其他"` | 没有后缀时 `suffix` 是空字符串（Falsy），兜一个默认值 |

> **记住这个模式**：**任何"批量改名 / 批量移动 / 批量删除"的脚本，都先写干跑版。**
>
> 理由很实在：**文件操作没有撤销**。干跑一遍看清它要动哪些文件，比出错后一个个恢复便宜得多。真实工具通常做成一个开关：`--dry-run`（第 24 章会讲怎么加命令行参数）。

### 示例 16-30　把成绩管理的数据存下来

### ⚠️ 但这个方案很脆弱

**自己定的格式，就得自己处理所有边界情况。而你一定会漏。**

**学生名字里带一个 `|`，整个方案就崩了**：

```python
from pathlib import Path

DB = Path("grades.txt")

def save(students):
    with open(DB, "w", encoding="utf-8") as f:
        for name, scores in students.items():
            parts = [name] + [f"{k}={v}" for k, v in scores.items()]
            f.write("|".join(parts) + "\n")

def load():
    students = {}
    for line in DB.read_text(encoding="utf-8").splitlines():
        name, *rest = line.split("|")
        students[name] = {}
        for pair in rest:
            k, v = pair.split("=")
            students[name][k] = float(v)
    return students

# 名字里带一个分隔符
save({"小明|同学": {"数学": 90.0}})
print(repr(DB.read_text(encoding="utf-8")))     # => '小明|同学|数学=90.0\n'

load()
# => ValueError: not enough values to unpack (expected 2, got 1)
```

**为什么？** 文件里那行被 `split("|")` 切成了三段：`小明`、`同学`、`数学=90.0`。第二段 `同学` 里没有等号，`k, v = pair.split("=")` 就炸了。

**带等号的名字更糟——它不报错，但你没法确定数据对不对**：

```python
from pathlib import Path

DB = Path("grades.txt")

def save(students):
    with open(DB, "w", encoding="utf-8") as f:
        for name, scores in students.items():
            parts = [name] + [f"{k}={v}" for k, v in scores.items()]
            f.write("|".join(parts) + "\n")

def load():
    students = {}
    for line in DB.read_text(encoding="utf-8").splitlines():
        name, *rest = line.split("|")
        students[name] = {}
        for pair in rest:
            k, v = pair.split("=")
            students[name][k] = float(v)
    return students

save({"a=b": {"数学": 90.0}})
print(repr(DB.read_text(encoding="utf-8")))     # => 'a=b|数学=90.0\n'
print(load())                                    # => {'a=b': {'数学': 90.0}}
```

这次**侥幸对了**——因为名字里的等号在 `|` 的左边，没被当成键值对去切。但**你能确定所有输入都这么幸运吗？** 分数里出现 `|`、名字里有换行符、某个字段是空的……**每一种都要你自己想到并处理，而你一定会漏掉一种。**

**要把它做对，你得实现**：分隔符转义、转义符本身的转义、空值表示、类型信息（怎么知道 `90` 该读成 `float` 还是 `str`）、嵌套结构……

**这些活儿早就有人干完了。** 第 17 章讲 JSON——上面这一整套 `save` / `load`，会被**两行**取代，而且不怕任何特殊字符。

### 六个必须注意的差异

**① `using` ≈ `with`，但 Python 里"忘了写"的后果更隐蔽。**

C# 里 `StreamWriter` 没 `Dispose` 时，终结器最终会刷缓冲；Python 里对象被回收时也会关文件，但**时机不确定**（CPython 靠引用计数通常很快，其他实现不保证）。所以 **`with` 在 Python 里不是"建议"，是"必须"**。

**② 编码默认值不同，而且这是中文乱码的头号原因。**

.NET 的 `File.ReadAllText` 默认 UTF-8（还会自动识别 BOM）。**Python 的 `open()` 默认跟随系统 locale**——Windows 中文版是 GBK，Linux 是 UTF-8。**同一段代码在两台机器上行为不同。**

所以 Python 里的规矩是：**永远显式写 `encoding="utf-8"`**。这一条在 .NET 里你可能从没操心过。

**③ `"w"` 模式清空文件，对应 `FileMode.Create`，不是 `OpenOrCreate`。**

C# 里你会明确选 `FileMode.Append` / `Create` / `CreateNew` / `Open`，语义写在名字里。Python 的单字母模式**看不出来那么多**，`"w"` 长得很无辜，实际是 `Create`（截断）。

对照关系：

| `FileMode` | Python |
|---|---|
| `Open` | `"r"` |
| `Create` | `"w"` ⚠️ |
| `CreateNew` | `"x"` |
| `Append` | `"a"` |

**④ `rename` 的跨平台行为不一致，用 `replace`。**

`Path.rename(目标)` 在目标已存在时：**Windows 报错，Linux 覆盖**。这个不一致会让你的代码"在 Linux 上测好了，部署到 Windows 就崩"。**`Path.replace()` 两个平台都覆盖**，是你想要的 `File.Move(a, b, overwrite: true)`。

**⑤ 没有 `AppDomain.BaseDirectory` 那么现成的东西。**

C# 里 `BaseDirectory` 直接给你程序所在目录。Python 要写 `Path(__file__).resolve().parent`。**而且新手极易混淆它和 `Path.cwd()`**——见 16.11 那个演示。

**⑥ `pathlib` vs `os.path` 相当于 `Path`/`FileInfo` vs 字符串拼接。**

`os.path` 那套是"函数 + 字符串"，`pathlib` 是"对象 + 方法"。**你从 C# 过来会觉得 `pathlib` 更亲切**——它就是 `FileInfo` / `DirectoryInfo` 的思路。看到老代码里的 `os.path.join`，理解成"还没用上 `pathlib` 的写法"就行，新代码不要跟。

### 一个 SQL 背景的类比

16.13 那个"先写 `.tmp` 再 `replace`"，就是**事务的思路**：

| SQL | 文件 |
|---|---|
| `BEGIN TRAN` → 改 → `COMMIT` | 写 `.tmp` → 写完 → `replace()` |
| 中途失败则 `ROLLBACK`，原数据完好 | 中途崩了，`.tmp` 是垃圾，**原文件没被碰过** |
| 原子性：要么全成要么全不成 | `replace()` 在同一文件系统内是原子的 |

而**直接 `open(目标, "w")` 就相当于不开事务就 `UPDATE`**——改到一半断了，数据就处于半新半旧的状态。你在数据库上绝不会这么干，写文件时也别这么干。

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| **用 `w` 模式打开已有文件** | **原内容全部丢失，不可撤销** | 追加用 `a`，不覆盖用 `x`，或先 `exists()` | `w` 打开即清空 |
| 输入输出文件名写成同一个 | **源数据瞬间没了** | 写之前确认路径 | 同上 |
| 忘了 `close()`，也没用 `with` | 数据没落盘 / 文件被占用 / 句柄耗尽 | **一律用 `with`** | 写入带缓冲 |
| 用 `try` 里的 `close()` | 抛异常时执行不到 | `with` 或 `try/finally` | —— |
| **不写 `encoding`** | 中文乱码；**你机器上好好的，同事一跑就坏** | **显式 `encoding="utf-8"`** | Windows 默认 GBK，Linux 默认 UTF-8 |
| 二进制模式带 `encoding` | `ValueError: binary mode doesn't take an encoding argument` | 去掉 `encoding` | 二进制不做编解码 |
| 把图片等二进制文件当文本读 | `UnicodeDecodeError: ... 0x89 in position 0` | 用 `"rb"` | —— |
| **`line == "abc"` 比较失败** | 永远 `False`，而屏幕上看着一样 | `line.strip() == "abc"` | 行尾有 `\n`，看不见 |
| 假设每行都有 `\n` | 最后一行可能没有 | 统一 `strip()` | 取决于文件怎么保存的 |
| `write` 后各行挤在一起 | 全在一行 | 自己加 `\n` | **`write` 不自动换行** |
| `writelines(["a","b"])` 以为会换行 | 得到 `'ab'` | 元素自带 `\n`，或用 `"\n".join()` | 名字骗人 |
| 读第二次得到空字符串 | 以为文件空了 | `f.seek(0)` 或重新打开 | 文件指针在末尾 |
| 用 `read()` / `readlines()` 读大文件 | 内存暴涨甚至崩溃 | `for line in f` | 一次性载入全部 |
| 把 `f.tell()` 当字符位置用 | 数字对不上 | 它是字节偏移 | 文本模式下是不透明的字节数 |
| **相对路径换个目录启动就找不到** | `FileNotFoundError`；"在 IDE 里能跑" | `Path(__file__).resolve().parent / "..."` | **工作目录 ≠ 脚本目录** |
| 对用户给的路径用 `__file__` 拼 | 永远找不到用户的文件 | 用户指定的路径原样用 | 用户站在自己的工作目录说话 |
| `mkdir()` 目录已存在 | `FileExistsError` | `mkdir(exist_ok=True)` | —— |
| `mkdir()` 建多层目录 | `FileNotFoundError` | `mkdir(parents=True)` | 不会自动建父目录 |
| `unlink()` 删不存在的文件 | `FileNotFoundError` | `unlink(missing_ok=True)` | —— |
| 用 `unlink()` 删目录 | `IsADirectoryError` | `rmdir()` 或 `shutil.rmtree()` | —— |
| 用 `rename` 覆盖已有文件 | **Windows 报错，Linux 覆盖** | 用 `replace()` | 跨平台行为不一致 |
| Windows 路径写成 `"C:\new"` | 路径被转义破坏 | `r"C:\new"` 或 `Path("C:/new")` | 回收 5.2 |
| **遍历目录不排序** | 每次 / 每台机器顺序不同 | `sorted(p.iterdir())` | 文件系统不保证顺序 |
| **边遍历目录边改名/删除** | 漏文件、重复处理 | 先 `list()` / `sorted()` 收集再处理 | 同 9.18 |
| 批量文件操作直接动手 | 出错了没法恢复 | **先写干跑版只打印** | 文件操作没有撤销 |
| 自己拼分隔符格式存数据 | 内容里出现分隔符就崩或悄悄错 | 用 JSON（第 17 章） | 边界情况你一定会漏 |

## 本章小结

### 打开文件

- **一律用 `with open(...) as f:`**，没有例外——它保证异常时也会关闭
- `with` 就是 `try/finally` 的语法糖（原理见第 32 章）
- 不关文件的三个后果：**数据没落盘**、文件被占用、句柄耗尽

### 六种模式

| 模式 | 不存在时 | 已存在时 |
|---|---|---|
| `r` 读（默认） | 报错 | 从头读 |
| **`w` 写** | 创建 | **⚠️ 清空** |
| `a` 追加 | 创建 | 从末尾接着写 |
| `x` 独占创建 | 创建 | 报错 |

- **日常九成只用 `r` / `a` / `w` 三个**
- **⚠️ `w` 一打开就清空，即使你什么都不写**——这是本章唯一能造成真实数据损失的操作

### 读

- **默认用 `for line in f`**：内存只占一行，文件多大都不怕
- `read()` / `readlines()` 会把整个文件载入内存——**几十 MB 以上禁用**
- **每行末尾都带 `\n`**（最后一行可能没有）→ 比较前先 `strip()`
- 读完一遍指针在末尾，**再读是空的** → `f.seek(0)`

### 写

- **`write` 不自动换行**，`writelines` 也不（名字骗人）
- 写多行推荐 `f.write("\n".join(lines) + "\n")`

### 编码（铁律）

> **读写文本文件永远显式写 `encoding="utf-8"`。**

- 不写就用系统默认：**Windows 是 GBK，Linux / macOS 是 UTF-8**——同一段代码两台机器行为不同
- `UnicodeDecodeError` 的三种成因：**编码猜错了** / **其实是二进制文件** / 文件损坏
- 二进制模式（`rb` / `wb`）读到 `bytes`，**不能带 `encoding`**

### `pathlib`（新代码一律用它）

```python
from pathlib import Path

p = Path("data") / "a.txt"           # 用 / 拼，跨平台
p.name / p.stem / p.suffix / p.parent
p.exists() / p.is_file() / p.is_dir()
p.read_text(encoding="utf-8")        # 小文件一行读
p.write_text(s, encoding="utf-8")    # 小文件一行写
p.mkdir(parents=True, exist_ok=True) # 记住这个组合
p.unlink(missing_ok=True)            # 删文件
p.replace(目标)                       # 移动/覆盖（别用 rename）
```

- 遍历：`iterdir()` 一层 / `glob("*.txt")` 一层过滤 / **`rglob("*.txt")` 递归**
- **遍历一律套 `sorted()`**；**别边遍历边改**，先收集再处理

### 工作目录 ≠ 脚本目录

- `open("data.txt")` 是相对于**运行时的工作目录**（`Path.cwd()`），不是脚本所在目录
- 症状：**在 IDE 里能跑，命令行 `cd` 到别处就 `FileNotFoundError`**
- **跟着代码走的文件** → `Path(__file__).resolve().parent / "..."`
- **用户指定的文件** → 原样使用用户给的路径

### 两个工作习惯

1. **批量文件操作先写干跑版**（只打印计划，不动手）——**文件操作没有撤销**
2. **重要文件用"先写 `.tmp` 再 `replace()`"**——原子替换，崩了也不会半新半旧

```python
import json
```
