## 开篇：让程序开口说话

到目前为止，你的程序处理的都是**写死在代码里**的数据。想换一个值，就得打开代码、改常量、保存、重新运行。这对你自己也许还能忍，交给别人就完全不行了。

这一章加上 `input`，程序就能**和人对话**了——它会停下来等你输入，拿到你说的话再继续。这是你的程序第一次有了"交互"，写出来会很有成就感。

同时你会踩一个坑。这个坑**没有人能躲过**，而且它不报错，只是给你一个错得莫名其妙的结果：

```python
a = input("第一个数字：")      # 你输入 10
b = input("第二个数字：")      # 你输入 5
print(a + b)                  # 输出不是 15
```

本章会把这件事讲透。

## 6.1 `print` 输出多个值

**示例 6-1　一次输出好几个值**

```python
print("小明", 18)
print("小明", 18, "工程师")
```

```text
小明 18
小明 18 工程师
```

**用逗号分隔多个值，`print` 会自动用空格把它们连起来**，末尾自动换行。

这里有个**常见误解**要纠正：很多人以为那个逗号是"字符串拼接符"。**它不是**——逗号的作用是"给 `print` 传了多个参数"。区别在下面这个例子里就体现出来了：

```python
print("小明", 18)              # ✅ 传两个参数，print 自己负责连接
print("小明" + 18)             # ❌ TypeError：这是真的在做拼接，而拼接不允许混类型
```

第二行会报错（6.5 节会详细讲），而第一行不会——**因为 `print` 会把每个参数各自转成文本再连接，不需要你操心类型**。

> **记住这条**：**逗号是"传多个参数"，不是"拼接"。** 这也是为什么 `print("年龄", 18)` 能跑而 `print("年龄" + 18)` 会崩。

## 6.2 `sep`：改变分隔符

默认用空格连接，想换成别的就用 `sep` 参数。

**示例 6-2　自定义分隔符**

```python
print(2026, 8, 1, sep="-")               # 拼日期
print("a", "b", "c", sep="")             # 空字符串 = 紧挨着，不留空隙
print("路径", "usr", "local", sep="/")    # 拼路径
```

```text
2026-8-1
abc
路径/usr/local
```

**什么时候用**：临时拼一个带固定分隔符的输出。**不过说实话，这三种情况用 f-string 或 `join`（第 5.21 节）通常更清楚**——`sep` 的主要价值是"随手输出时省事"。

**注意 `2026-8-1` 这个结果**：月份是 `8` 而不是 `08`。要补零得用 f-string 的格式说明符（`f"{8:02d}"`），`sep` 帮不了你。日期格式化的正规做法在第 23 章。

## 6.3 `end`：让输出不换行

`print` 默认在末尾加一个换行符，这个行为由 `end` 参数控制。

**示例 6-3　让几次 print 输出在同一行**

```python
print("a", end="")
print("b", end="")
print("c")            # 最后这个不带 end，正常换行
```

```text
abc
```

`end=""` 的意思是"结尾什么都不加"，所以下一个 `print` 会紧接着输出。

**`end` 也可以是别的内容**：

```python
print("加载中", end="...")
print("完成")
```

```text
加载中...完成
```

### 忘了补换行会怎样

**示例 6-4　`end=""` 的经典事故**

```python
# ❌ 错误：连续用 end="" 却忘了在最后补一次换行
print("处理中", end="")
print("完成", end="")
print("下一段内容")
```

```text
处理中完成下一段内容
```

三段内容全挤在一行，而且第三段本来是不相干的另一段输出，现在也被粘上了。

```python
# ✅ 正确：该结束的地方补一个 print()
print("处理中", end="")
print("完成")                # 这里正常换行，结束这一行
print("下一段内容")
```

```text
处理中完成
下一段内容
```

> **记住这条**：**用了 `end=""`，就要记得在某个地方结束这一行**——要么最后一个 `print` 不带 `end`，要么单独加一个 `print()`。

## 6.4 空 `print()` 打一个空行

**示例 6-5　输出空行**

```python
print("第一行")
print()
print("第三行")
```

```text
第一行

第三行
```

`print()` 是"零个参数 + 默认换行"——没有内容要输出，但那个换行还是会加上，于是就得到一个空行。

**别小看空行的作用**。在交互式程序里，**用空行把"输入区"和"输出区"分开**，观感差别很大（本章末的名片生成器会用到）。

## 6.5 三种输出风格，该用哪个

同一句话，三种写法：

**示例 6-6　三种风格对照**

```python
name, age = "小明", 18

print(name, "今年", age, "岁")                    # ① 逗号传多个参数
print(name + " 今年 " + str(age) + " 岁")         # ② 用 + 拼接
print(f"{name} 今年 {age} 岁")                    # ③ f-string
```

```text
小明 今年 18 岁
小明 今年 18 岁
小明 今年 18 岁
```

**输出一样，但优劣差别很大**：

| 写法 | 问题 |
|---|---|
| ① 逗号 | **控制不了细节**：分隔符只能全局改（`sep`），想让某两项之间不留空格做不到；也没法控制小数位数 |
| ② `+` 拼接 | **必须手工转类型**（漏了 `str()` 就报错）；引号和空格容易数错；长了以后完全读不懂 |
| ③ f-string | 变量在句子里的位置一眼可见；自动处理类型；能控制格式（`:.2f`、`:>10`） |

第 ② 种的类型问题值得单独看：

```python
age = 18
print("年龄" + age)
```

```text
TypeError: can only concatenate str (not "int") to str
```

报错说得很直白："字符串只能和字符串拼接"。三种解法：

```python
print("年龄" + str(age))       # ✅ 手工转
print("年龄", age)             # ✅ 改用逗号
print(f"年龄{age}")            # ✅ 推荐：f-string 自动处理
```

> **记住这条**：**输出一律用 f-string。** 逗号形式适合随手调试（`print(x, y)` 打两个变量看看），`+` 拼接在输出场景里没有任何优势，不要用。

## 6.6 `input`：让程序停下来问

**示例 6-7　让程序问你一句话**

```python
name = input("请输入名字：")
print(f"你好，{name}！")
```

在终端里运行，你会看到（`小明` 是你敲进去的）：

```text
请输入名字：小明
你好，小明！
```

**三件事要说清**：

**① 程序会真的停下来。** 执行到 `input` 那一行，程序**暂停**，光标停在提示语后面等你。你按回车之前，后面的代码一行都不会执行。这是你第一次遇到"程序暂停"，不要以为它卡死了。

**② 括号里的内容是提示语。** 它会被原样打印出来（不换行），然后等输入。不写提示语也行（`input()`），但那样用户看着一个空白光标不知道要干什么。

**③ 你输入的内容变成了 `input` 的返回值。** 所以要用 `name = input(...)` 把它接住——不接住就丢了（回想第 5.6 节的教训：**这行有没有等号**）。

### 提示语的一个小细节

**示例 6-8　提示语末尾留个空格**

```python
name1 = input("姓名:")        # 光标紧贴冒号
name2 = input("姓名: ")       # 留一个空格，好看一些
```

用中文冒号 `：` 时不用留空格（全角冒号本身带空隙），用英文冒号 `:` 时建议留一个。**这是纯观感问题，但你的程序会因此显得专业一点。**

## 6.7 `input` 永远返回字符串

**这是本章最重要的一节。**

**示例 6-9　`input` 拿到的到底是什么类型**

```python
a = input("第一个数字：")      # 输入 10
print(type(a))
print(repr(a))                # repr 显示"代码里的样子"，能看清引号
```

```text
第一个数字：10
<class 'str'>
'10'
```

**你输入的是数字 10，拿到的是字符串 `'10'`。**

**为什么**：Python 无法猜测你想要什么。你可能要数字、可能要文本、可能要日期——它索性统一给字符串，让你自己决定怎么转。

### 由此产生的必踩之坑

**示例 6-10　两个数字相加，结果却拼在一起了**（样板示例）

```python
a = input("第一个数字：")      # 输入 10
b = input("第二个数字：")      # 输入 5
print(a + b)
```

```text
第一个数字：10
第二个数字：5
105
```

**`105`，不是 `15`。**

原因现在很清楚了：`a` 是字符串 `'10'`、`b` 是字符串 `'5'`，而字符串的 `+` 是**拼接**（第 5.1 节），所以 `'10' + '5'` 得到 `'105'`。

**换成减法反而会报错**：

```python
print(a - b)
```

```text
TypeError: unsupported operand type(s) for -: 'str' and 'str'
```

因为字符串没有"减法"这个操作。**加法的坑比减法更危险**——减法当场报错，加法却给你一个错误的结果继续往下跑。

**正确做法是显式转换**：

```python
# ❌ 错误：直接对 input 的结果做算术
a = input("第一个数字：")
b = input("第二个数字：")
print(a + b)                       # => 105

# ✅ 正确：先转成数字
a = int(input("第一个数字："))       # int(...) 套在外面，一步完成输入和转换
b = int(input("第二个数字："))
print(a + b)                       # => 15
```

```text
第一个数字：10
第二个数字：5
15
```

> **记住这条**：**`input` 出来的是字符串。要做算术，先 `int()` 或 `float()`。**
>
> **一个自查习惯**：每写完一个 `input`，问自己一句——**"这个值我要拿来算数还是拿来显示？"** 要算数就当场包上 `int()` / `float()`，别留到后面。

## 6.8 输入的清洗与转换

用户的输入是**不可信**的——会多敲空格、会大小写混用、会输入你没想到的东西。

### 先 strip

**示例 6-11　用户多打了空格**

```python
print(int(" 10 "))         # => 10     两端的空格 int() 能自己忽略
```

```python
print(int("1 0"))          # ❌ ValueError: invalid literal for int() with base 10: '1 0'
```

`int()` 会自动忽略**两端**的空白，但中间有空格就没救了（那本来就是无效输入）。

**尽管如此，仍然建议养成 `strip()` 的习惯**：

```python
name = input("姓名：").strip()          # 处理文本时 strip 是必须的
age = int(input("年龄：").strip())      # 转数字时 strip 可省，但写上无害
```

**为什么处理文本时必须 strip**：用户输入 `"小明 "`（末尾多一个空格），你拿去和 `"小明"` 比较就会不相等——这是很难发现的 bug。

### 转换失败的三种情况

**示例 6-12　`int()` 什么时候会失败**

```python
print(int(""))         # ❌ ValueError: invalid literal for int() with base 10: ''
```

```python
print(int("abc"))      # ❌ ValueError: invalid literal for int() with base 10: 'abc'
```

```python
print(int("10.5"))     # ❌ ValueError: invalid literal for int() with base 10: '10.5'
```

三种失败：**空输入**（用户直接按回车）、**非数字**、**小数形式**（回收第 3.8 节：`int()` 不认小数点）。

需要小数就用 `float()`：

```python
print(float("10.5"))       # => 10.5
print(float("10"))         # => 10.0    整数形式也能转成浮点数
```

### 转成小数做计算

**示例 6-13　算 BMI**

```python
weight = float(input("体重（公斤）：").strip())
height = float(input("身高（米）：").strip())

bmi = weight / (height * height)
print(f"你的 BMI 是 {round(bmi, 1)}")     # round 保留一位小数（第 3.4 节）
```

```text
体重（公斤）：70
身高（米）：1.75
你的 BMI 是 22.9
```

### 统一大小写再比较

**示例 6-14　让 `YES`、`yes`、`Yes` 都能识别**

```python
answer = input("确认吗？(yes/no) ").strip().lower()      # 方法可以连着调用

print(f"你输入的规范化结果是：{answer!r}")
print(f"等于 yes 吗？{answer == 'yes'}")
```

```text
确认吗？(yes/no) YES
你输入的规范化结果是：'yes'
等于 yes 吗？True
```

**`.strip().lower()` 是处理用户输入的标准搭配**（回收第 5.17 节）：去掉误敲的空格、消除大小写差异。

### `isdigit()` 能当校验用吗

**示例 6-15　`isdigit()` 的局限**

第 5.13 节提过它，这里正式回答"能不能用它来校验数字输入"：

```python
print("12".isdigit())        # => True
print("-12".isdigit())       # => False     负数不算！
print("1.5".isdigit())       # => False     小数不算！
print("".isdigit())          # => False
print("  ".isdigit())        # => False
print("12abc".isdigit())     # => False
```

**结论：不能。** 它只判断"是不是全由 0-9 组成"，负数和小数都会被误判为非法。

用它写出来的校验会拒绝合法输入（`-5`、`3.14` 都是正当的数字）。**真正可靠的做法是"直接转，转不成再说"**——那需要第 15 章的 `try`。到那时我们会回来把输入校验重写一遍，代码更短也更可靠。

> **记住这条**：**`isdigit()` 不是数字校验。** 判断"这段文本能不能当数字用"，正确姿势是 `try` + `float()`（第 15 章）。

## 6.9 一次输入多个值

**示例 6-16　用空格分隔一次输入三项**

```python
parts = input("姓名 科目 分数（空格分隔）：").split()      # split() 按任意空白拆（第 5.20 节）

print(parts)                    # 先看看拆成了什么
print(parts[0], parts[2])       # 按位置取出其中两项
```

```text
姓名 科目 分数（空格分隔）：小明 数学 92
['小明', '数学', '92']
小明 92
```

`split()` 拆出来的是**列表**（第 9 章的正题）。现在只用它做两件事：整个打印出来看，以及用下标取某一项。

**这个写法有个明显的脆弱点**：

```python
parts = input("姓名 科目 分数：").split()
print(parts[2])
```

```text
姓名 科目 分数：小明 数学
IndexError: list index out of range
```

用户少输了一项，`parts[2]` 就越界了。

**所以这是"临时凑合"的写法**——适合自己用的小脚本，不适合给别人用的程序。要做得健壮，需要判断个数（第 7 章）和异常处理（第 15 章）。

## 6.10 输出缓冲与 `flush`

有时候 `print` 的内容**不会立刻出现在屏幕上**。这不是 bug，是"缓冲"。

**为什么要缓冲**：往屏幕（或文件）写数据是有开销的，攒够一批再一次写出去更快。

**什么时候会攒着不发**：`print` 没有换行的时候（因为终端默认是"遇到换行才刷出"）。

**示例 6-17　`flush` 的实际差别**

```python
import time                              # 标准库，让程序暂停一会儿；第 23 章详讲

print("处理中...", end="")                # 注意 end=""，没有换行
time.sleep(2)                            # 假装在干一件耗时 2 秒的事
print("完成")
```

运行这段代码，你会看到**前 2 秒屏幕上什么都没有**，然后 `处理中...完成` 一起冒出来。

我实测验证过这一点——在那 2 秒里去读程序的输出，读到的是**空的**：

```text
不加 flush：sleep 期间读到 = ''
不加 flush：最终补上     = '处理中...完成\n'
```

加上 `flush=True` 就不一样了：

```python
import time

print("处理中...", end="", flush=True)    # flush=True 表示"立刻输出，别攒着"
time.sleep(2)
print("完成")
```

```text
加 flush：sleep 期间读到 = '处理中...'
加 flush：最终补上       = '完成\n'
```

**这次"处理中..."立刻就显示了**，2 秒后才补上"完成"。

**什么时候需要 `flush=True`**：

| 场景 | 原因 |
|---|---|
| 显示"处理中..."这类进度提示 | 不 flush 的话，提示要等任务干完才出现——完全失去意义 |
| 长时间运行的程序打日志 | 想实时看到进展，而不是等程序结束才一起出来 |
| **程序卡住了，定位卡在哪一步** | 这是排查问题的实用技巧：加了 `flush=True` 的 print 才能保证"最后一条输出"确实是卡住的位置 |

> **记住这条**：**`print` 带 `end=""` 时输出可能被攒着**。需要立刻看到就加 `flush=True`。
>
> 顺带说一句：这个"攒着"的行为在第 21 章（日志）还会遇到——那时候有更专业的解决办法。

## 6.11 标准输出与标准错误

程序其实有**两条**输出通道：

| 通道 | 名字 | 用来输出 |
|---|---|---|
| 标准输出 | `stdout` | **正常结果**（`print` 默认走这里） |
| 标准错误 | `stderr` | **错误和提示信息** |

**示例 6-18　把结果和错误分开输出**

```python
import sys                                        # 标准库；import 的完整机制见第 18 章

print("这是正常结果")                              # 默认走 stdout
print("这是错误信息", file=sys.stderr)             # 明确指定走 stderr
```

直接运行时，两者都显示在屏幕上，看不出区别：

```text
这是正常结果
这是错误信息
```

**区别在重定向的时候才显现**。命令行里的 `>` 可以把输出存进文件：

```bash
python streams.py > out.txt
```

```text
这是错误信息
```

屏幕上**只剩下错误信息**了，而 `out.txt` 里是：

```text
这是正常结果
```

**`>` 只重定向 stdout，stderr 依然走屏幕。**

**为什么要这样分**：这样用户可以把结果存起来（`> result.csv`）而**错误信息照样能看到**。如果全都混在 stdout，存下来的文件里就会夹着错误提示，污染数据。

> **记住这条**：**正常结果走 `stdout`，出错和提示走 `stderr`。**
>
> **这条原则在第 21 章（日志）和第 24 章（命令行程序）会正式用上**：命令行工具的输出结果用 `print`，日志和错误走 `stderr` 或文件——这样你的程序才能和别的工具通过管道配合。

### 一个能证明缓冲存在的现象

把 6.10 和 6.11 连起来看，有个有意思的实测结果。同样那段代码：

| 运行方式 | 输出顺序 |
|---|---|
| 直接在终端运行 | `这是正常结果` → `这是错误信息`（**代码顺序**） |
| 重定向 stdout（`> out.txt`） | 屏幕上先出现 `这是错误信息` |

**为什么顺序会变**：`stderr` 不缓冲（错误信息要第一时间让人看到），而 `stdout` 在重定向到文件时会**块缓冲**（攒一大批再写）。于是后写的 stderr 反而先出现。

**这个现象说明一件事**：`print` 的输出**什么时候真正落地，取决于它去哪里**——去终端是行缓冲、去文件是块缓冲。知道这一点，以后遇到"日志顺序看起来不对"就不会困惑了。

## 6.12 `print` 也能写文件

`file` 参数除了指向 `sys.stderr`，也可以指向一个打开的文件：

**示例 6-19　用 `print` 往文件里写**

```python
with open("note.txt", "w", encoding="utf-8") as f:      # 完整用法见第 16 章
    print("第一行", file=f)
    print("第二行", file=f)

print(open("note.txt", encoding="utf-8").read(), end="")
```

```text
第一行
第二行
```

**这个写法能用，而且有个小优势**：`print` 会自动加换行，而第 16 章要学的 `write()` 不会。

不过**文件操作的正规做法还是第 16 章**——那里会讲 `with`、编码、读写模式这些必须搞清楚的东西。**这里只是让你知道 `file` 参数不止能写 stderr。**

## 6.13 中文对齐的现实

第 5.29 节留下一个问题，这里再确认一次它的表现。

看本章末尾名片生成器的实际输出：

```text
+----------------------------+
|             小明             |
|            工程师             |
|        13800138000         |
+----------------------------+
```

**"工程师"那一行的右边比左边多一个空格**——因为 `f"{title:^28}"` 是把 3 个字符居中于 28 个字符宽，`(28 - 3) / 2 = 12.5`，没法平分，Python 选择**左边 12 个、右边 13 个**。

而且中英文混排时看起来更歪，原因第 5.29 节讲过：**f-string 按"字符个数"算宽度，终端按"显示宽度"渲染**，一个汉字占两格。

**现在的态度**：知道原因就行。真要输出规整的中文表格，用 `wcwidth` 或 `tabulate` 这类第三方库，比手工对齐划算。

## 综合示例

**示例 6-20　交互式名片生成器**（样板示例）

把本章的 `input`、`strip`、空行，和第 5 章的 f-string 格式化合起来：

```python
# 三次询问。strip() 是必须的：用户很容易在名字后面多敲一个空格
name = input("姓名：").strip()
title = input("职位：").strip()
phone = input("电话：").strip()

width = 30                                       # 名片宽度用变量，改起来方便

print()                                          # 空行：把输入区和输出区分开
print("+" + "-" * (width - 2) + "+")              # 上边框："-" * 28 重复 28 次（第 5 章）
print("|" + f"{name:^{width - 2}}" + "|")         # 嵌套花括号：宽度本身也用变量算
print("|" + f"{title:^{width - 2}}" + "|")        # ^ 表示居中
print("|" + f"{phone:^{width - 2}}" + "|")
print("+" + "-" * (width - 2) + "+")
```

真实运行画面（三行输入是你敲的）：

```text
姓名：小明
职位：工程师
电话：13800138000

+----------------------------+
|             小明             |
|            工程师             |
|        13800138000         |
+----------------------------+
```

**两个值得记住的点**：

1. **`f"{name:^{width - 2}}"` 里有两层花括号**——外层是 f-string 的占位符，内层 `{width - 2}` 让**宽度本身也变成动态的**。这是第 5 章没讲的新东西：**格式说明符里可以放变量**。改一下 `width` 的值，整张名片的宽度就跟着变。
2. **中文行的对齐不完美**，原因见 6.13。

**示例 6-21　汇率换算小工具**

```python
amount = float(input("请输入美元金额：").strip())     # 一步完成：输入 → 去空格 → 转小数
rate = 7.23                                        # 汇率写死，实际应该从接口取（专项 D）

print()
print(f"美元：{amount:>12,.2f}")                    # >12 右对齐占 12 宽，,.2f 千分位两位小数
print(f"汇率：{rate:>12.4f}")
print(f"人民币：{amount * rate:>10,.2f}")
```

```text
请输入美元金额：1234.5

美元：    1,234.50
汇率：      7.2300
人民币：  8,925.44
```

**注意最后一行的宽度是 `>10` 而不是 `>12`**——因为"人民币："比"美元："多一个字，要少留 2 格才能让数字右端对齐。**这种手工调整很烦，正是 6.13 说的中文对齐问题的具体表现。**

> **这个程序还很脆弱**：用户输入 `abc` 会直接崩（`ValueError`）。第 15 章学了异常处理后，我们会回来给它加上防护。

<summary><b>给有 C# / Java / SQL 经验的读者</b></summary>

| 你熟悉的 | Python |
|---|---|
| `Console.WriteLine("a")` / `System.out.println("a")` | `print("a")` |
| `Console.Write("a")`（不换行） | `print("a", end="")` |
| `Console.WriteLine("{0} {1}", a, b)` | `print(f"{a} {b}")` |
| `Console.ReadLine()` | `input()` |
| `int.Parse(Console.ReadLine())` | `int(input())` |
| `int.TryParse(s, out n)` | **没有对应物**——用 `try` + `int()`（第 15 章） |
| `Console.Error.WriteLine("err")` | `print("err", file=sys.stderr)` |
| `Console.Out.Flush()` | `print(..., flush=True)` |
| `string.Format(...)` | f-string |

**三个需要注意的**：

1. **没有 `TryParse`。** C# 里校验数字输入的标准做法是 `int.TryParse`（不抛异常，用返回值告诉你成不成）。Python 没有这个模式——它的做法是**直接转，出错就抛异常，你用 `try` 接住**（第 15 章）。这是两种语言错误处理哲学的差别（第 15.14 节会正式讲 EAFP 与 LBYL）。
2. **`print` 的逗号不是格式化占位符。** C# 的 `Console.WriteLine("{0}", a)` 是模板 + 参数，而 Python 的 `print(a, b)` 就是"传两个值进去"。想用模板就用 f-string。
3. **`input` 不区分类型。** 不像某些语言有 `readInt()` / `readLine()` 之分，Python 只有一个 `input()`，永远给字符串。**类型转换是你的责任。**

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| `input()` 结果直接做算术 | `"10" + "5"` 得 `"105"`（不报错，结果是错的） | `int(input(...))` | input 恒返回字符串 |
| `input()` 结果做减法 | `TypeError: unsupported operand type(s) for -` | 同上 | 字符串没有减法 |
| `"年龄" + 18` | `TypeError: can only concatenate str` | `f"年龄{18}"` 或 `str(18)` | Python 不做隐式转换 |
| `int("")`（用户直接回车） | `ValueError` | 第 15 章用 `try` 处理 | 空字符串不是数字 |
| `int("10.5")` | `ValueError` | 用 `float("10.5")` | `int()` 不认小数点 |
| `int("1 0")` | `ValueError` | 中间有空格是真无效输入 | `strip` 只去两端 |
| 忘了 `strip()` 就比较文本 | `"小明 " == "小明"` 是 `False` | 输入后先 `.strip()` | 用户会多敲空格 |
| 用 `isdigit()` 校验数字 | 负数、小数被拒绝 | `try` + `float()`（第 15 章） | 只认 0-9 |
| 连续 `end=""` 忘了补换行 | 后面的输出粘在同一行 | 补一个 `print()` | `end=""` 取消了换行 |
| 以为 `print(a, b)` 是拼接 | 想改分隔符不知从何改 | 用 `sep=`，或改用 f-string | 逗号是传多个参数 |
| 进度提示不加 `flush=True` | 提示等任务结束才出现 | `print(..., end="", flush=True)` | 输出被缓冲 |
| 日志和结果都走 stdout | 重定向时数据被污染 | 错误走 `file=sys.stderr` | 两条通道用途不同 |
| 提示语不带空格 `input("姓名:")` | 光标紧贴冒号，观感差 | `input("姓名: ")` | 观感问题 |
| 在某些 IDE 里 `input` 没反应 | 程序像卡住了 | 改用终端运行；VS Code 里设 `"console": "integratedTerminal"`（见 T5.4） | 部分运行窗口不支持交互 |

## 本章小结

- **逗号是"传多个参数"不是"拼接"**——所以 `print("年龄", 18)` 能跑而 `print("年龄" + 18)` 报错
- `sep` 改分隔符、`end` 改结尾、`print()` 打空行；**用了 `end=""` 记得补换行**
- **输出一律用 f-string**，`+` 拼接在输出场景没有优势
- `input` 会让程序**停下来等**，返回值要用等号接住
- **`input` 永远返回字符串**——要算术必须先 `int()` / `float()`
- 处理输入的标准动作：**`.strip()`**，需要比较时再加 `.lower()`
- **`isdigit()` 不是数字校验**（负数小数都会被拒），可靠做法要等第 15 章
- `flush=True` 让输出立刻出现；正常结果走 `stdout`、错误走 `stderr`

### API 速查

| 写法 | 作用 |
|---|---|
| `print(a, b)` | 输出多个值，空格连接 |
| `print(a, b, sep="-")` | 改分隔符 |
| `print(a, end="")` | 不换行 |
| `print()` | 输出空行 |
| `print(a, flush=True)` | 立刻输出，不缓冲 |
| `print(a, file=sys.stderr)` | 输出到标准错误 |
| `print(a, file=f)` | 输出到文件（正规做法见第 16 章） |
| `input("提示")` | 显示提示并等待输入，**返回字符串** |
| `int(input(...))` / `float(input(...))` | 输入并转成数字 |
| `input().strip()` | 输入并去掉两端空白（**处理文本时必做**） |
| `input().strip().lower()` | 输入 + 去空格 + 转小写（比较前的标准动作） |
| `input().split()` | 一次输入多个值（返回列表，第 9 章详讲） |
