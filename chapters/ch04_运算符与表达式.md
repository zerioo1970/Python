## 开篇：三个反直觉的结果

先猜三个答案：

```python
print(4 / 2)          # 是 2 还是 2.0？
```

## 4.1 算术运算符

**示例 4-1　七个算术运算符**

```python
print(7 + 2)         # => 9      加
print(7 - 2)         # => 5      减
print(7 * 2)         # => 14     乘
print(7 / 2)         # => 3.5    除（结果是小数）

print(7 ** 2)        # => 49     幂（7 的 2 次方）
```

前三个没什么可说的。后四个每个都有坑，接下来逐个讲。

## 4.2 三种除法

### `/` 永远返回小数

**示例 4-2　`/` 的结果一定是浮点数**

```python
print(4 / 2)              # => 2.0        不是 2
print(type(4 / 2))        # => <class 'float'>
print(6 / 3)              # => 2.0        即使除得尽，也是浮点数
```

**这是 Python 3 的一个重要设计**：`/` 叫"真除法"，它的结果**一律是浮点数**，哪怕能整除。

**为什么这么设计**：Python 2 里 `1 / 2` 得 `0`（整数除法），这让无数人算错数——你以为在算比例，实际结果被截断了。Python 3 改成了"除法就是数学上的除法"，要整数结果就明确用 `//`。

**什么时候会踩到**：把 `/` 的结果当下标用（第 9 章会遇到）。列表下标必须是整数，`lst[len(lst) / 2]` 会直接报 `TypeError`，得写成 `lst[len(lst) // 2]`。

### `//` 整除，`%` 取余

```python
print(7 // 2)        # => 3      7 里面有 3 个完整的 2
print(7 % 2)         # => 1      余下 1
```

这两个是一对，`//` 拿商、`%` 拿余数。

**`%` 最常见的三个实际用途**：

**示例 4-3　取模的三个典型场景**

```python
# ① 判断奇偶：能不能被 2 整除
print(10 % 2)        # => 0      余 0 就是偶数
print(7 % 2)         # => 1      余 1 就是奇数

# ② 判断整除关系：能不能被 3 整除
print(9 % 3)         # => 0

# ③ 循环取值：让数字在 0~6 之间转圈（比如算星期几）
print(8 % 7)         # => 1
print(15 % 7)        # => 1
```

第三种用法后面会经常见到——**任何数对 n 取模，结果一定在 `0` 到 `n-1` 之间**，很适合做"循环编号"。

### 一次拿到商和余数：divmod

**示例 4-4　`divmod` 一步到位**

```python
print(divmod(17, 5))      # => (3, 2)     商 3，余 2
```

它返回的 `(3, 2)` 是一个**元组**（第 10 章讲），可以直接拆成两个变量：

```python
q, r = divmod(17, 5)
print(q, r)               # => 3 2
```

**什么时候用**：需要同时用到商和余数的时候（下面 4.13 的时间换算就是典型例子），比分别写 `//` 和 `%` 少算一次。

## 4.3 负数的整除和取模（与其他语言不同）

**示例 4-5　负数的 `//` 和 `%`**

```python
print(7 // 2)        # => 3      符合直觉
print(-7 // 2)       # => -4     注意！不是 -3
print(7 % 2)         # => 1
print(-7 % 2)        # => 1      注意！不是 -1
```

### 为什么 -7 // 2 是 -4

`//` 的正式名字叫**地板除**（floor division），意思是"**朝小的方向取整**"，而不是"砍掉小数"。

`-7 / 2` 等于 `-3.5`。朝小的方向走，`-3.5` 的下一站是 `-4`（不是 `-3`，因为 `-4` 比 `-3.5` 小）。

```text
数轴：  -5    -4   -3.5   -3    -2
         ↑     ↑     ●     ↑
              这里 ←──── 朝小的方向
```

想要"砍掉小数"的效果，用 `int()`（第 3.8 节讲过，它是朝 0 的方向）：

```python
print(-7 // 2)            # => -4     地板除：朝更小的方向
print(int(-7 / 2))        # => -3     int()：朝 0 的方向（砍掉小数）
```

### 为什么 -7 % 2 是 1

Python 的规则是：**余数的符号跟除数一致**。除数 `2` 是正的，所以余数也是正的。

验证一下除数为负的情况：

```python
print(7 // -2)       # => -4
print(7 % -2)        # => -1     除数是负的，余数也是负的
```

### 这是 Python 和 C# / Java 的真实差异

| 表达式 | Python | C# / Java / C |
|---|---|---|
| `-7 / 2`（整数除法） | `-7 // 2` = **-4** | `-7 / 2` = **-3** |
| `-7 % 2` | **1** | **-1** |

**从这些语言转过来的人一定要注意**。而且 Python 的行为在实用上更好——它保证了 `%` 的结果永远在 `0` 到 `n-1` 之间（除数为正时），这让"循环取值"的用法始终可靠。C 系语言里 `-1 % 7` 得 `-1`，用来做数组下标会直接越界。

**什么时候会踩到**：用 `//` 算分页数、算索引偏移，而数据里出现了负数——结果会和预期差 1，而且不报错。

> **记住这条**：**`//` 是"朝小的方向取整"，不是"砍掉小数"；`%` 的余数符号跟除数。** 想砍掉小数用 `int()`。

## 4.4 幂运算与开方

**示例 4-6　`**` 的两个用法**

```python
print(2 ** 10)            # => 1024                幂运算
print(9 ** 0.5)           # => 3.0                 0.5 次方就是开平方
print(2 ** 0.5)           # => 1.4142135623730951  √2
```

**开方不需要专门的函数**——`x ** 0.5` 就是 `√x`。（`math.sqrt()` 也可以，但要先 `import math`，用 `** 0.5` 更省事。）

### -2 ** 2 等于几

**示例 4-7　一个优先级陷阱**

```python
print(-2 ** 2)            # => -4     不是 4！
print((-2) ** 2)          # => 4
```

**因为 `**` 的优先级比负号高**。`-2 ** 2` 实际是 `-(2 ** 2)` = `-(4)` = `-4`。

要算"负 2 的平方"，必须加括号。

### 顺便：** 是右结合的

```python
print(2 ** 3 ** 2)        # => 512
```

它算的是 `2 ** (3 ** 2)` = `2 ** 9` = `512`，而不是 `(2 ** 3) ** 2` = `64`。

**`**` 是唯一从右往左算的运算符**，其他运算符都是从左往右。这个细节记不住也没关系——**不确定就加括号**，这是本章会反复说的一句话。

## 4.5 复合赋值

**示例 4-8　`+=` 及其同类**

```python
x = 5
x += 3               # 等价于 x = x + 3
print(x)             # => 8

x *= 2               # 等价于 x = x * 2
print(x)             # => 16

x //= 3              # 等价于 x = x // 3
print(x)             # => 5
```

所有算术运算符都有对应的复合形式：`+=` `-=` `*=` `/=` `//=` `%=` `**=`。

**它们只是简写，没有别的魔法**——至少对数字来说是这样。（对列表，`x += [1]` 和 `x = x + [1]` 有微妙的区别，第 13 章会讲，现在不用管。）

**Python 没有 `++` 和 `--`**。想加 1 就写 `x += 1`，没有 `x++` 这种写法。

## 4.6 比较运算符

**示例 4-9　比较的结果是布尔值**

```python
print(3 > 2)              # => True
print(3 == 3.0)           # => True     整数和浮点数可以比较，值相等就是相等
print("abc" == "abc")     # => True
print(3 != 2)             # => True
```

六个比较运算符：`==` `!=` `>` `<` `>=` `<=`，结果都是 `True` 或 `False`。

**注意 `==` 是两个等号**。一个等号是赋值，两个是比较。写错了会怎样：

```python
if x = 5:        # ❌ SyntaxError: invalid syntax
```

Python 从**语法层面**禁止了在条件里赋值——**这是好事**。C / C# / Java 里 `if (x = 5)` 能编译通过，然后产生一个极难发现的 bug。（第 7 章讲 `if` 时会再提这件事。）

### 字符串也能比大小

**示例 4-10　字符串怎么比大小**

```python
print("apple" < "banana")     # => True     a 在 b 前面
print("A" < "a")              # => True     大写字母排在小写字母前面
print("Z" < "a")              # => True     所有大写都在所有小写前面
```

字符串比较是**按字符的编码顺序，从左到右逐个比**。用 `ord()` 可以看到每个字符的编码：

```python
print(ord("A"), ord("Z"), ord("a"))    # => 65 90 97
```

`A`~`Z` 是 65~90，`a`~`z` 是 97~122——**所以所有大写字母都小于所有小写字母**。

**这个特性的实际后果**：给名字排序时，`"Zhang"` 会排在 `"alice"` 前面（因为 `Z`=90 < `a`=97），看起来很奇怪。**解决办法是比较前统一大小写**（第 5 章学 `.lower()` 后就能做到）。

## 4.7 链式比较：Python 特有的好东西

**示例 4-11　判断一个数在不在区间内**

```python
score = 85
print(0 <= score <= 100)      # => True
```

这个写法在大多数语言里是**非法**的，Python 支持，而且语义就是数学上的意思。

对比一下不用链式比较的写法：

```python
print(score >= 0 and score <= 100)     # => True    功能相同，但啰嗦
print(0 <= score <= 100)               # => True    更短、更像数学
```

链式可以接更多：

```python
print(1 < 2 < 3)         # => True
print(3 > 2 > 1)         # => True
print(0 <= 150 <= 100)   # => False
```

> **记住这条**：**判断区间用链式比较 `0 <= x <= 100`**，比 `and` 连接更清楚。

## 4.8 逻辑运算符

**示例 4-12　`and` / `or` / `not`**

```python
print(True and False)     # => False    and：两个都真才真
print(True or False)      # => True     or：有一个真就真
print(not True)           # => False    not：取反
```

**注意 Python 用的是英文单词**，不是 `&&` `||` `!`。从 C 系语言转过来的人要改手指习惯。

**三者的优先级**：`not` > `and` > `or`

```python
print(True or False and False)          # => True
print((True or False) and False)        # => False
```

第一行 Python 实际算的是 `True or (False and False)` = `True or False` = `True`。**如果你以为它从左往右算，就会得到错误的预期。**

**建议**：**混用 `and` 和 `or` 时一律加括号**，不为语法，为了让读代码的人（包括三个月后的你）不用回忆优先级。

## 4.9 短路求值与"取默认值"技巧

### 什么是短路

`and` 和 `or` 有一个特性：**结果已经确定时，后面的就不算了**。

- `A and B`：如果 A 是假，整体必然是假，**B 不会被计算**
- `A or B`：如果 A 是真，整体必然是真，**B 不会被计算**

**这个特性有个重要的实际用途**：把"安全检查"放在前面。比如"如果这个东西存在，并且它满足某个条件"——先检查存在，不存在就短路掉，后面那个可能出错的判断根本不会执行。（第 7、11 章会看到具体例子。）

### and / or 返回的不是 True / False

**示例 4-13　`and` 和 `or` 返回的是操作数本身**

```python
print(1 and 2)       # => 2      不是 True！
print(0 and 2)       # => 0      不是 False！
print(1 or 2)        # => 1
print(0 or 2)        # => 2
```

**规律**：

| 表达式 | 返回什么 |
|---|---|
| `A and B` | A 为假就返回 **A**，否则返回 **B** |
| `A or B` | A 为真就返回 **A**，否则返回 **B** |

这不是 bug，是设计。因为它带来一个非常好用的写法：

**示例 4-14　用 `or` 取默认值**

```python
name = ""                          # 假设这是用户没填的输入
print(name or "游客")               # => 游客

name = "小明"
print(name or "游客")               # => 小明
```

**`x or 默认值`** 的含义是"**x 有内容就用 x，没有就用默认值**"。这个写法在真实代码里到处都是，比写三行 `if` 判断简洁得多。

**但它有个陷阱**（第 7 章会详讲）：**它把所有"假值"都当成"没有"**。

```python
count = 0
print(count or 10)        # => 10     ！用户明明填了 0，被当成"没填"
```

`0`、`""`、`None` 都是假值（第 3.8 节讲过），`or` 分不清"用户填了 0"和"用户没填"。**需要区分时，必须用明确的判断**（第 7 章教怎么写）。

> **记住这条**：**`x or 默认值` 很好用，但 `0` 和 `""` 会被当成"没有"。** 数值型的默认值要小心用这招。

## 4.11 is 和 ==：一个必须讲透的区别

### 两者的定义

| 运算符 | 比什么 | 类比 |
|---|---|---|
| `==` | **值**是否相等 | 两个人身份证号一样吗 |
| `is` | 是不是**同一个对象** | 这两个名字指的是同一个人吗 |

回到第 3.1 节的标签模型：`==` 比的是"标签指向的东西内容一样吗"，`is` 比的是"两张标签贴在同一个对象上吗"。

**示例 4-16　列表上的区别一目了然**

```python
a = [1, 2]
b = [1, 2]           # 内容相同，但是另一个列表对象

print(a == b)        # => True     内容一样
print(a is b)        # => False    是两个不同的对象
```

```python
c = a                # 贴同一张标签
print(c is a)        # => True
```

### 数字和字符串上的行为：不可预测

这里有个非常诡异的现象，**也正是"永远不要用 `is` 比值"的理由**。

**示例 4-17　同样的代码，两种环境两种结果**

把下面代码存成脚本运行：

```python
a = 257
b = 257
print(a == b)        # => True
print(a is b)        # => True     ？？

x = "hello world!"
y = "hello world!"
print(x is y)        # => True     ？？
```

`is` 居然是 `True`——两个分开写的 `257` 竟然是"同一个对象"。

**同样的代码在 REPL 里逐行输入**：

```text
>>> a = 257
>>> b = 257
>>> a is b
False
>>> x = "hello world!"
>>> y = "hello world!"
>>> x is y
False
```

**结果完全相反。**

而且差异不止"脚本 vs REPL"这一种。同样这三行代码，**整块一起执行**和**一行一行执行**结果也不同：

```text
整个文件一起运行  → 257 is 257 : True
一行一行执行      → 257 is 257 : False
```

### 为什么会这样

Python 为了省内存，会**复用**一些对象：

- 小整数（约 -5 到 256）和短字符串，解释器启动时就预先创建好，反复使用同一个
- 写在**同一段代码里**的相同常量，编译时会被合并成一个对象——这就是为什么整个文件一起运行时 `257 is 257` 成了 `True`，而分开逐行输入时不会合并

所以 `is` 的结果取决于：**你的 Python 版本、代码是整块编译还是逐行输入、甚至这个数字有多大、这个字符串有多长**。

**这就是问题所在**——它不可预测。你在 REPL 里试出 `False`，写进脚本变成 `True`；今天用 3.12 是这个结果，明天升级到 3.14 可能就变了。

**基于这种"碰巧"写出来的判断，是定时炸弹。**

### 结论：is 只用在一个地方

```python
# ✅ is 的唯一正当用途：判断是不是 None
value = None
print(value is None)          # => True
print(value is not None)      # => False

# ✅ 值比较一律用 ==
print(257 == 257)             # => True     永远可靠
print("hello" == "hello")     # => True     永远可靠

# ❌ 永远不要这样
print(257 is 257)             # 结果不可预测，别写
```

**为什么判断 `None` 反而要用 `is`**：因为 `None` 在整个程序里**只有一个对象**，这是语言保证的。所以 `is None` 是 100% 可靠的，而且比 `== None` 更快、更规范（第 15 章会看到 `== None` 在某些情况下还会出错）。

> **记住这条**：**`==` 比值，`is` 比身份。除了 `is None` / `is not None`，其他场合一律用 `==`。**

## 4.12 浮点数怎么比较（兑现第 3 章）

第 3 章我们发现 `0.1 + 0.2 != 0.3`，当时只给了"先 `round` 再比"的临时办法。现在给正规做法。

**示例 4-18　三种比较方式**

```python
import math                                    # 标准库，import 的完整用法见第 18 章

# ❌ 直接比较：结果和预期相反
print(0.1 + 0.2 == 0.3)                        # => False

# ✅ 办法一：判断两者的差距足够小
print(abs((0.1 + 0.2) - 0.3) < 1e-9)           # => True

# ✅ 办法二（推荐）：用标准库的 math.isclose
print(math.isclose(0.1 + 0.2, 0.3))            # => True
```

`1e-9` 是 0.000000001，意思是"差距小于十亿分之一就算相等"。这个数叫**容差**，具体取多少看业务需要。

**为什么推荐 `math.isclose`**：它用的是**相对误差**——容差会随数字的大小自动缩放，而不是固定一个绝对值。

这个区别很实际。假设你用固定容差 `1e-9`：

- 比较 `0.1 + 0.2` 和 `0.3`，差距约 `5.5e-17`，远小于容差 → 判为相等 ✅
- 比较两个上亿的数，它们的浮点误差本身就可能超过 `1e-9` → 明明该算相等，却判为不等 ❌

**数字越大，浮点误差的绝对值也越大**，所以固定容差在大数上会失效。`isclose` 改成看"差距占数值的比例"，就不受数字量级影响了。

它的默认容差是 `rel_tol=1e-9`，也就是"**相对差距小于十亿分之一**才算相等"，相当严格：

```python
print(math.isclose(1000000.0, 1000000.1))                  # => False
```

这两个数只差 `0.1`，但相对差距是 `0.1 / 1000000 = 1e-7`，比默认的 `1e-9` 大，所以判为不相等。

觉得太严就自己放宽：

```python
print(math.isclose(1000000.0, 1000000.1, rel_tol=1e-6))    # => True
```

**容差取多少，由业务决定**：算物理量可能 `1e-9` 都不够严，算用户填的体重 `1e-3` 就够了。**没有万能的数值**，但默认值在多数情况下够用。

**用哪种方法的判断标准**：

| 情况 | 用什么 |
|---|---|
| 一般的浮点比较 | `math.isclose(a, b)` |
| 需要自己定容差 | `math.isclose(a, b, rel_tol=1e-6)` 或 `abs(a-b) < 容差` |
| **算钱** | **都不要用** ——用整数存"分"或 `decimal`（第 3.4 节、工具箱 T2） |

> **记住这条**：**浮点数不能用 `==` 比，用 `math.isclose()`。** 整数可以放心用 `==`，它是精确的。

## 4.13 优先级：不确定就加括号

**示例 4-19　三个常见的优先级误会**

```python
# 误会一：以为从左往右算
print(2 + 3 * 4)              # => 14     先乘后加，不是 (2+3)*4=20
print((2 + 3) * 4)            # => 20

# 误会二：以为 not 只管紧跟着的那个变量
print(not 3 == 3)             # => False  实际是 not (3 == 3)，因为 == 优先级高于 not

# 误会三：以为 and / or 从左往右
print(True or False and False)          # => True   实际是 True or (False and False)
print((True or False) and False)        # => False
```

### 精简优先级表（从高到低）

| 优先级 | 运算符 | 说明 |
|---|---|---|
| 1 | `**` | 幂（**右结合**） |
| 2 | `-x` | 取负 |
| 3 | `*` `/` `//` `%` | 乘除 |
| 4 | `+` `-` | 加减 |
| 5 | `<` `<=` `>` `>=` `==` `!=` `in` `is` | 比较、成员、身份 |
| 6 | `not` | 逻辑非 |
| 7 | `and` | 逻辑与 |
| 8 | `or` | 逻辑或 |

**不用背这张表。** 记住三件事就够了：

1. **算术 > 比较 > 逻辑**（先算数、再比较、最后组合逻辑）
2. `not` > `and` > `or`
3. **不确定就加括号——加括号从来不是错**

多余的括号不会让程序变慢，但会让代码变清楚。**为了少打两个字符去赌优先级，不值得。**

## 4.14 位运算（★ 见到不慌就行）

**示例 4-20　六个位运算符**

```python
print(5 & 3)         # => 1      按位与
print(5 | 3)         # => 7      按位或
print(5 ^ 3)         # => 6      按位异或
print(~5)            # => -6     按位取反
print(5 << 1)        # => 10     左移一位（相当于 ×2）
print(5 >> 1)        # => 2      右移一位（相当于 ÷2 取整）
```

它们操作的是数字的**二进制形式**：

```python
print(bin(5), bin(3))        # => 0b101 0b11
```

`5` 是 `101`，`3` 是 `011`，逐位做"与"运算得 `001`，也就是 `1`。

**一个真实用途：权限位掩码**

假设一个系统有三种权限，各占一个二进制位：

```python
READ = 1             # 二进制 001
WRITE = 2            # 二进制 010
DELETE = 4           # 二进制 100

# 给用户"读 + 写"权限：用 | 合起来
perms = READ | WRITE
print(perms)                      # => 3        二进制 011

# 检查有没有"写"权限：用 & 取出那一位
print(perms & WRITE)              # => 2        非 0 就是有
print(perms & DELETE)             # => 0        0 就是没有
```

这种写法在操作系统权限（Linux 的 `0o755`）、图形库的选项标志里很常见。

**日常业务开发几乎用不到位运算**，用集合（第 12 章）或几个布尔变量更清楚。**但读别人代码时会遇到，认得出就行。**

<details>
<summary><b>给有 C# / Java / SQL 经验的读者</b></summary>

本章最需要注意的几处差异：

| | 你熟悉的 | Python |
|---|---|---|
| 整数除法 | `7 / 2` = `3`（整数相除得整数） | `7 / 2` = `3.5`，要整数用 `7 // 2` |
| **负数整除** | `-7 / 2` = `-3` | `-7 // 2` = **`-4`**（朝小的方向） |
| **负数取模** | `-7 % 2` = `-1` | `-7 % 2` = **`1`**（符号跟除数） |
| 逻辑运算 | `&&` `\|\|` `!` | `and` `or` `not` |
| 自增 | `i++` / `i--` | **没有**，写 `i += 1` |
| 三元运算 | `cond ? a : b` | `a if cond else b`（第 7 章） |
| 区间判断 | `x >= 0 && x <= 100` | `0 <= x <= 100`（链式比较） |
| 引用相等 | `ReferenceEquals(a, b)` / `a == b`（引用类型） | `a is b`（**但只该用于 `None`**） |
| 值相等 | `a.Equals(b)` / `a == b` | `a == b` |
| 幂运算 | `Math.Pow(2, 10)` | `2 ** 10` |
| 开方 | `Math.Sqrt(9)` | `9 ** 0.5` |

**特别提醒 SQL 背景的读者**：SQL 里 `NULL = NULL` 结果是 `NULL`（未知），要用 `IS NULL` 判断。Python 里 `None == None` 是 `True`，但**规范写法仍然是 `is None`**——习惯上和 SQL 一致，理由不同（SQL 是因为三值逻辑，Python 是因为 `None` 是单例）。

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| 以为 `4 / 2` 得 `2` | 得 `2.0`，当下标用时报 TypeError | 要整数用 `4 // 2` | `/` 恒返回浮点数 |
| 以为 `-7 // 2` 是 `-3` | 差 1 的诡异 bug，不报错 | 想砍小数用 `int(-7 / 2)` | `//` 朝小的方向取整 |
| 以为 `-7 % 2` 是 `-1` | 与 C#/Java 习惯不同 | 记住余数符号跟除数 | 语言设计差异 |
| `-2 ** 2` 以为得 `4` | 得 `-4` | 写 `(-2) ** 2` | `**` 优先级高于取负 |
| `2 ** 3 ** 2` 以为得 64 | 得 `512` | 加括号明确意图 | `**` 是右结合 |
| 用 `&&` `\|\|` `!` | `SyntaxError` | 用 `and` `or` `not` | Python 用英文单词 |
| 写 `i++` | `SyntaxError` | 写 `i += 1` | Python 没有自增运算符 |
| `if x = 5` | `SyntaxError` | `if x == 5` | 一个等号是赋值 |
| `not a == b` 理解成 `(not a) == b` | 逻辑反了 | 实际是 `not (a == b)`，加括号 | 比较优先级高于 `not` |
| `A or B and C` 以为从左往右 | 结果不对 | 加括号 | `and` 优先级高于 `or` |
| 用 `is` 比较数字或字符串 | 时对时错，换环境就变 | 一律用 `==` | 对象复用不可预测 |
| `x == None` | 能跑但不规范 | `x is None` | `None` 是单例 |
| `0.1 + 0.2 == 0.3` | `False` | `math.isclose(a, b)` | 浮点精度（第 3.4 节） |
| `count or 10` 想取默认值 | 用户填的 `0` 被当成"没填" | 用明确判断（第 7 章） | `0` 是假值 |
| 给名字排序 `"Zhang" < "alice"` | `True`，大写排在小写前 | 比较前统一 `.lower()`（第 5 章） | 大写字母编码更小 |

## 本章小结

- **三种除法**：`/` 恒返回浮点数、`//` 整除、`%` 取余；`divmod` 一次拿到商和余数
- **`//` 是朝小的方向取整**，`-7 // 2` 得 `-4`；`%` 的余数符号跟除数——**这两条和 C#/Java 都不同**
- `x ** 0.5` 就是开方；`-2 ** 2` 得 `-4`（`**` 优先级最高且右结合）
- 逻辑运算用 **`and` / `or` / `not`**，优先级 `not` > `and` > `or`
- **`and` / `or` 返回操作数本身**，所以有 `x or 默认值` 这个好用的写法——但 `0` 和 `""` 会被当成"没有"
- **区间判断用链式比较** `0 <= x <= 100`
- **`==` 比值，`is` 比身份**；`is` 对数字和字符串的结果**不可预测**，除了 `is None` 一律用 `==`
- **浮点数用 `math.isclose()` 比较**，不能用 `==`
- 优先级记三条：算术 > 比较 > 逻辑；`not` > `and` > `or`；**不确定就加括号**

### 运算符速查

| 运算符 | 作用 | 注意 |
|---|---|---|
| `/` | 除法 | **恒返回浮点数** |
| `//` | 整除 | **朝小的方向取整** |
| `%` | 取余 | 余数符号跟除数 |
| `**` | 幂 | 优先级最高、右结合；`x ** 0.5` 是开方 |
| `+=` `-=` `*=` … | 复合赋值 | 没有 `++` / `--` |
| `==` `!=` | 值比较 | 两个等号 |
| `<` `<=` `>` `>=` | 大小比较 | 支持链式 `0 <= x <= 100` |
| `and` `or` `not` | 逻辑 | 返回操作数本身；`not`>`and`>`or` |
| `in` `not in` | 成员 | 字符串判子串，容器判元素 |
| `is` `is not` | 身份 | **只用于 `None`** |
| `&` `\|` `^` `~` `<<` `>>` | 位运算 | 日常少用，认得出即可 |

### 相关函数

| 函数 | 作用 |
|---|---|
| `divmod(a, b)` | 一次返回商和余数 |
| `abs(x)` | 绝对值 |
| `ord(c)` | 字符的编码值 |
| `bin(x)` / `hex(x)` / `oct(x)` | 转进制字符串 |
| `math.isclose(a, b)` | **浮点数比较** |
