## 开篇：只有键，没有值

上一章的字典长这样：

```python
scores = {"小明": 92, "小红": 88}
```

如果我们**只要键、不要值**呢？

```python
names = {"小明", "小红"}
```

**这就是集合。** 一句话记住它：

> **集合 = 只有键、没有值的字典。**

这个类比能一口气解释集合的全部性质，不用单独背：

| 字典的性质 | 集合因此也有 |
|---|---|
| 键不能重复 | **元素不能重复**——重复的自动合并 |
| 键必须可哈希 | **元素必须可哈希**——不能放列表 |
| 按键查找极快（不用扫表） | **判断"在不在里面"极快** |
| 靠键取值，不靠位置 | **不能按下标取元素**，也没有切片 |

**什么时候该想到用集合？** 只有两个信号，看到就条件反射：

1. **"去重"**——一份名单里有重复的，要弄干净。
2. **"两批数据比对"**——新旧名单谁多了谁少了、两个班共同开了哪些课、必填字段哪个没填。

第 2 条是本章最有价值的部分。这类活儿很多人写了几年代码还在用双层 `for` 循环做，其实**三行差集就够了**。

本章语法极其简单，半小时就能看完。真正要花时间的是 12.13 和 12.14 两个实战示例——请务必自己敲一遍。

## 12.1 创建集合

**示例 12-1　创建一个集合**

```python
s = {1, 2, 3}

print(s)                # => {1, 2, 3}
print(type(s))          # => <class 'set'>
print(len(s))           # => 3
```

**格式**：`{元素, 元素, 元素}`——花括号，元素之间逗号分隔，**没有冒号**（有冒号就是字典了）。

也可以用 `set()` 把别的容器"倒"进集合里：

```python
print(set([3, 1, 2, 3, 1]))     # => {1, 2, 3}                      列表 → 集合，顺便去重
print(set(("a", "b", "a")))     # => {'a', 'b'}                    元组 → 集合，顺序不定
print(set("hello"))             # => {'h', 'e', 'l', 'o'}           顺序不定，见 12.4
```

`set("hello")` 把字符串**拆成一个个字符**再去重，所以两个 `l` 只剩一个。

## 12.2 空集合必须写 `set()`

**这是集合唯一的语法坑**，而且几乎人人都踩过一次。

**示例 12-2　空集合的正确写法**

```python
# ❌ 想建空集合，结果建出了空字典
s = {}
print(type(s))          # => <class 'dict'>       它是字典！
print(s)                # => {}
```

为什么？因为 `{}` 这个写法**早就被字典占用了**。空的花括号里既没有元素也没有冒号，Python 无法判断你想要哪个，于是规定：**归字典**。

```python
# ✅ 空集合只有这一种写法
s = set()
print(type(s))          # => <class 'set'>
print(s)                # => set()               打印出来是 set()，不是 {}
```

注意最后一行：**空集合打印出来是 `set()`**，不是 `{}`。看到输出里有 `set()`，就知道那是个空集合。

```python
print({1} - {1})        # => set()               运算结果为空时也这样显示
print(len(set()))       # => 0
print(bool(set()))      # => False               空集合是"假"，和空列表空字典一样
```

判空还是老规矩，直接拿它当条件：

```python
if not set():
    print("空集合是假")   # => 空集合是假
```

> **记住这条**：**`{}` 是空字典，空集合是 `set()`。** 但**非空**的时候 `{1, 2}` 就是集合了，因为有元素能区分——歧义只存在于"空"这一种情况。

## 12.3 重复元素自动消失

**示例 12-3　重复元素自动消失**

```python
print({1, 1, 2, 2, 2, 3})       # => {1, 2, 3}       重复的悄悄合并了
print({"a", "a"})               # => {'a'}
```

**不报错、不警告，直接合并**——这正是我们要的（去重靠的就是这个），但也意味着**你写重复了它不会提醒你**。

有个边界情况得知道，和字典的键完全同源（11.5 节讲过 `True` 和 `1` 是同一个键）：

```python
print({1, True})                # => {1}         True == 1，被当成同一个元素
print({1, 1.0, True})           # => {1}         三个都相等，只留最先出现的那个
print({0, False})               # => {0}         同理
```

**判定标准是 `==` 相等**，不是"类型相同"。日常几乎碰不到，但混着放布尔和数字时要留个心。

## 12.4 无序：不能索引，顺序不保证

集合**没有"第几个"的概念**。

**示例 12-4　集合不能按位置取**

```python
s = {10, 20, 30}

# ❌ 集合不支持下标
print(s[0])
# => TypeError: 'set' object is not subscriptable
```

切片也一样不行（`s[0:2]` 报同样的错）。**记住这个报错文字 `not subscriptable`**——第 10 章元组报的是"不支持赋值"，集合报的是"不支持取下标"，是两回事。

需要"第几个"怎么办？**先排序变成列表**：

```python
s = {10, 20, 30}
print(sorted(s))        # => [10, 20, 30]        sorted 返回的是列表
print(sorted(s)[0])     # => 10                  在列表上取下标就行
```

**示例 12-5　顺序不保证**

这一条比"不能索引"更容易吃亏，因为它**不报错**。

```python
s = {"香蕉", "苹果", "橘子", "西瓜"}
print(s)                # => {'香蕉', '橘子', '苹果', '西瓜'}    你运行时顺序会不同
```

**请你自己连着运行三次**，你会看到三种不同的顺序。原因是 Python 对字符串的哈希做了随机化——**每启动一次解释器，种子就换一次**。

但整数集合看着却是"有序"的：

```python
print({3, 1, 2})            # => {1, 2, 3}           看着像排好序了
print({100, 1, 50, 7})      # => {1, 50, 100, 7}     其实没有！
```

第一行纯属巧合（小整数的哈希值就是它自己），第二行就露馅了。

> **记住这条**：**集合的顺序从来没有被承诺过。** 看着有序是巧合，不能依赖。
>
> **这是个很隐蔽的坑**：本地跑几次顺序都正常，上线到别的机器就变了，或者今天对明天错。凡是要给人看的输出，**一律 `sorted()` 再打印**。

## 12.5 元素必须可哈希

**示例 12-9　集合不能装列表**

```python
# ❌ 列表不能当集合的元素
s = {[1, 2]}
# => TypeError: unhashable type: 'list'
```

`unhashable`（不可哈希）这个词你在 11.5 节见过——**和"列表不能当字典键"是同一个原因**：集合要靠哈希值快速定位元素，而列表可以被改，改了哈希值就变了，之前存的位置就找不着了。

字典和集合本身也不能放进集合：

```python
s = {{"a": 1}}      # => TypeError: unhashable type: 'dict'
s = {{1, 2}}        # => TypeError: unhashable type: 'set'
```

能放什么？**不可变的东西**：

```python
print({(1, 2), (3, 4)})                     # => {(1, 2), (3, 4)}         元组可以
print({1, "a", 3.5, True, None, (1, 2)})    # => {None, 1, (1, 2), 3.5, 'a'}   顺序不定
```

需要"一组可变数据"进集合时，**转成元组**：

```python
points = [[1, 2], [3, 4], [1, 2]]
print({tuple(p) for p in points})       # => {(1, 2), (3, 4)}     去掉了重复的点
```

（花括号里带 `for` 的写法是**集合推导式**，12.10 节讲。）

## 12.6 增和删

**示例 12-6　add 和 update**

```python
s = {1, 2}

s.add(3)                # 加一个元素
print(s)                # => {1, 2, 3}

s.add(3)                # 加已经有的，什么也不会发生（不报错）
print(s)                # => {1, 2, 3}
```

批量加用 `update`，它**能吃任何可迭代对象**：

```python
s = {1, 2, 3}
s.update([4, 5])            # 吃列表
print(s)                    # => {1, 2, 3, 4, 5}

s.update({6, 7}, [8])       # 一次吃多个容器都行
print(s)                    # => {1, 2, 3, 4, 5, 6, 7, 8}
```

**一个容易搞混的地方**：`update` 吃字符串时会把它**拆成字符**（因为字符串就是可迭代的）：

```python
t = {"a"}
t.update("xy")              # 不是加了 "xy" 这一个元素
print(t)                    # => {'y', 'a', 'x'}      顺序不定；是加了 'x' 和 'y' 两个
```

想加"xy"整体，用 `add`：`t.add("xy")`。**`add` 加一个整体，`update` 拆开来加**。

`add` 也受可哈希的限制：

```python
u = {1}
u.add([2, 3])
# => TypeError: unhashable type: 'list'
```

**示例 12-7　remove 和 discard**

删元素有两个方法，区别就在"删不存在的东西"时：

```python
s = {1, 2, 3}

s.remove(2)             # 删掉 2
print(s)                # => {1, 3}

# ❌ remove 删不存在的元素会报错
s.remove(99)
# => KeyError: 99
```

注意报的是 **`KeyError`**——又一次印证"集合就是只有键的字典"。

```python
s = {1, 3}

s.discard(99)           # ✅ discard 删不存在的，静默什么都不做
print(s)                # => {1, 3}

s.discard(3)            # 存在的照样删
print(s)                # => {1}
```

**怎么选**：不确定元素在不在，就用 `discard`（等于自带了一个 `if x in s`）；确信必须存在、不在就是有 bug，用 `remove` 让它报出来。**日常 `discard` 用得多。**

**示例 12-8　pop 是随机删的**

```python
s = {"a", "b", "c"}
x = s.pop()             # 删掉"某一个"并返回它——哪一个不确定
print(x)                # => 'a'        你运行时可能是别的
print(len(s))           # => 2
```

`s.pop()` **不接受参数**，删哪个由内部顺序决定。列表的 `pop()` 删的是明确的"最后一个"，集合的 `pop()` 是**没有承诺的**。

空集合上 `pop` 会报错：

```python
set().pop()
# => KeyError: 'pop from an empty set'
```

> **记住这条**：**集合的 `pop()` 几乎没有正当用途。** 想删指定元素用 `discard` / `remove`；想"随便拿一个看看"，`next(iter(s))` 更清楚（且不破坏数据）。见到别人代码里的 `s.pop()`，先怀疑是写错了。

清空用 `clear()`，和列表字典一样：

```python
s = {1, 2}
s.clear()
print(s)                # => set()
```

## 12.7 去重：本章最常用的一招

**示例 12-10　一行给列表去重**

```python
nums = [3, 1, 2, 3, 1, 5]

print(list(set(nums)))          # => [1, 2, 3, 5]
```

`set(nums)` 去重 → `list(...)` 变回列表。**这是 Python 里去重的标准一行**。

但它有代价：

```python
names = ["小明", "小红", "小明", "小刚", "小红"]
print(list(set(names)))         # => ['小刚', '小红', '小明']       顺序不定，乱了！
```

**顺序丢了**，而且每次运行还可能不一样（12.4 节讲的原因）。如果这份名单是报名先后、或者要打印给人看，这就不能接受。

**示例 12-11　去重还想保持原顺序**

保序去重的标准写法是**借用字典**：

```python
names = ["小明", "小红", "小明", "小刚", "小红"]

# dict.fromkeys 用这些元素当键造一个字典，重复的键自动合并；
# 字典从 3.7 起保持插入顺序（11.19 节），所以首次出现的顺序就保住了
unique = list(dict.fromkeys(names))
print(unique)                   # => ['小明', '小红', '小刚']      与首次出现顺序一致
```

中间那个字典长这样，我们只要它的键：

```python
print(dict.fromkeys(names))     # => {'小明': None, '小红': None, '小刚': None}
```

数字、字符串同样适用：

```python
print(list(dict.fromkeys([3, 1, 2, 3, 1, 5])))      # => [3, 1, 2, 5]     3 留在最前
print("".join(dict.fromkeys("abracadabra")))        # => abrcd            字符串去重
```

三种去重写法，按需要选：

| 需求 | 写法 | 说明 |
|---|---|---|
| 只是去重，不在乎顺序 | `set(lst)` | 最快最短；后面还要做集合运算时更该用它 |
| 去重且保持首次出现的顺序 | `list(dict.fromkeys(lst))` | 慢一点点，但顺序可预测 |
| 去重后要排好序输出 | `sorted(set(lst))` | 顺序由排序规则定，与原顺序无关 |

> **记住这条**：**`set` 去重会打乱顺序，`dict.fromkeys` 去重会保住顺序。** 给人看的数据基本都要保序。
>
> **一个常见的隐蔽 bug**：有人用 `list(set(lst))` 去重后直接输出，本地跑几次看着正常就上线了，换台机器顺序就变了。集合的顺序**从来没承诺过**。

顺手记一个小技巧——**判断一个列表里有没有重复**：

```python
lst1 = [1, 2, 3]
lst2 = [1, 2, 2]

print(len(lst1) == len(set(lst1)))      # => True      长度没变 → 没有重复
print(len(lst2) == len(set(lst2)))      # => False     长度缩了 → 有重复
```

## 12.8 成员测试：集合比列表快得离谱

`x in 列表`要**从头一个个比**；`x in 集合`直接**算哈希值定位**，一步到位。

**示例 12-12　in 对集合和列表的速度差别**

```python
import time

big_list = list(range(100000))       # 10 万条数据
big_set = set(big_list)              # 同样的数据装进集合
targets = [i * 97 % 100000 for i in range(1000)]    # 1000 个散布在各处的查找目标

t0 = time.perf_counter()
for t in targets:
    t in big_list                    # 在列表里找
t1 = time.perf_counter()
for t in targets:
    t in big_set                     # 在集合里找
t2 = time.perf_counter()

print(f"列表用了 {t1 - t0:.3f} 秒")
print(f"集合用了 {t2 - t1:.5f} 秒")
print(f"集合快了约 {(t1 - t0) / (t2 - t1):.0f} 倍")
```

我这台机器上的结果（**你的数字会不同，但量级是一样的**）：

```text
列表用了 0.248 秒
集合用了 0.00008 秒
集合快了约 3166 倍
```

**三千倍。** 而且这个差距会随数据量增长——列表是数据翻倍耗时翻倍，集合基本不受数据量影响。

但**数据量小的时候完全没必要折腾**：

```python
small_list = list(range(20))
small_set = set(small_list)
# 各查 1000 次的结果：列表 0.00014 秒，集合 0.00004 秒
```

20 个元素时两者都是"眨眼之间"，差别毫无意义。

**转换本身也有开销**——它要把整个列表遍历一遍：

```python
# 把 10 万条列表转成集合，本身要 0.0031 秒
big_set = set(big_list)
```

> **记住这条**：**要反复判断"在不在里面"，才值得先转成集合。**
>
> ```python
> # ❌ 只判断一次，转换的开销白花了
> if x in set(big_list):
>     ...
>
> # ✅ 循环里反复判断，转一次赚一万次
> blacklist = set(blacklist_lines)      # 循环外转好
> for row in rows:
>     if row["id"] in blacklist:
>         ...
> ```
>
> **判断标准很简单**：`in` 写在循环里面 → 集合值得；只用一次 → 列表就行。

**给有 SQL 背景的读者**：这就是**全表扫描 vs 索引查找**。列表的 `in` 是 `WHERE id = ?` 走全表，集合的 `in` 是走主键索引。你对这个差距应该很有体感——建索引本身要花时间（`set()` 转换），但之后每次查询都受益。

## 12.9 四种集合运算：本章的重点

这是集合真正值钱的地方。四种运算，四个符号：

| 运算 | 符号 | 读作 | 结果是 |
|---|---|---|---|
| 交集 | `a & b` | 与 | **两边都有**的 |
| 并集 | `a \| b` | 或 | **合起来**（自动去重） |
| 差集 | `a - b` | 减 | **a 有、b 没有**的（**有方向！**） |
| 对称差 | `a ^ b` | 异或 | **只在一边出现**的 |

用同一组数据把四种都跑一遍。

**示例 12-13　交集：两边都有的**

```python
a = {1, 2, 3, 4}
b = {3, 4, 5, 6}

print(a & b)            # => {3, 4}          只有 3 和 4 是两边都有的
```

**示例 12-14　并集：合起来**

```python
print(a | b)            # => {1, 2, 3, 4, 5, 6}      合并，重复的 3、4 只留一份
```

**示例 12-15　差集有方向**

```python
print(a - b)            # => {1, 2}          a 有、b 没有的
print(b - a)            # => {5, 6}          b 有、a 没有的
```

**这两个结果完全不同**，这是本章最容易出错的一点。念一遍就不会记错：**`a - b` 是"从 a 里把 b 也有的那些划掉"**。

**示例 12-16　对称差：只在一边的**

```python
print(a ^ b)                # => {1, 2, 5, 6}        3、4 因为两边都有，被排除了
print((a - b) | (b - a))    # => {1, 2, 5, 6}        等价写法，看清它的含义
```

**示例 12-17　四种运算一张表**

```python
a = {1, 2, 3, 4}
b = {3, 4, 5, 6}

print(f"a       = {sorted(a)}")             # => a       = [1, 2, 3, 4]
print(f"b       = {sorted(b)}")             # => b       = [3, 4, 5, 6]
print(f"a & b   = {sorted(a & b)}")         # => a & b   = [3, 4]
print(f"a | b   = {sorted(a | b)}")         # => a | b   = [1, 2, 3, 4, 5, 6]
print(f"a - b   = {sorted(a - b)}")         # => a - b   = [1, 2]
print(f"b - a   = {sorted(b - a)}")         # => b - a   = [5, 6]
print(f"a ^ b   = {sorted(a ^ b)}")         # => a ^ b   = [1, 2, 5, 6]
```

哪些运算换个顺序结果一样，哪些不一样：

```python
print(a & b == b & a)       # => True       交集、并集、对称差都不看顺序
print(a - b == b - a)       # => False      只有差集看顺序
```

多个集合也能连起来算：

```python
print(a & b & {3})          # => {3}
print(a | b | {9})          # => {1, 2, 3, 4, 5, 6, 9}
```

想改自己而不是生成新集合，用**复合赋值**（和 `+=` 一个道理）：

```python
s = {1, 2, 3}
s |= {4}                # 并进来
print(s)                # => {1, 2, 3, 4}
s -= {1}                # 减掉
print(s)                # => {2, 3, 4}
s &= {2, 3, 9}          # 只留交集
print(s)                # => {2, 3}
```

## 12.10 运算符和方法：方法能吃列表

四种运算都有对应的方法名：

| 运算符 | 方法 |
|---|---|
| `a & b` | `a.intersection(b)` |
| `a \| b` | `a.union(b)` |
| `a - b` | `a.difference(b)` |
| `a ^ b` | `a.symmetric_difference(b)` |

结果完全一样。那为什么还要有方法？**因为运算符要求两边都是集合，方法不要求。**

**示例 12-18　运算符和方法的区别**

```python
a = {1, 2, 3}

# ❌ 运算符右边必须也是集合
print(a & [2, 3])
# => TypeError: unsupported operand type(s) for &: 'set' and 'list'
```

```python
a = {1, 2, 3}

# ✅ 方法可以直接吃列表，省一次 set() 转换
print(a.intersection([2, 3]))       # => {2, 3}
print(a.union([4, 5]))              # => {1, 2, 3, 4, 5}
print(a.difference([1]))            # => {2, 3}
print(a.union(range(5)))            # => {0, 1, 2, 3, 4}      范围也行
```

**什么时候用方法**：另一边本来就是列表，且你不想多写一次 `set()`。其余情况**运算符更短更好读**，优先用运算符。

有个坑要注意——方法吃字符串时同样会**拆成字符**：

```python
a = {1, 2, 3}
print(a.intersection("123"))        # => set()      字符 '1' 不等于数字 1，交集为空
```

## 12.11 子集与超集

**示例 12-19　子集与权限检查**

判断"一组元素是否被另一组完全包含"：

```python
owned = {"读", "写", "删除"}        # 用户实际拥有的权限
required = {"读", "写"}             # 这个操作需要的权限

print(required <= owned)            # => True       需要的权限都有 → 放行
print(required.issubset(owned))     # => True       同一件事的方法写法
print(owned >= required)            # => True       反过来读：拥有的覆盖了需要的
```

`<=` 读作"是……的子集"。这个写法比手写循环清楚太多：

```python
# ❌ 手写版：五行，还容易漏
for p in required:
    if p not in owned:
        print("权限不足")
        break
```

权限不够时，还能一步算出**缺哪些**：

```python
owned = {"读", "写", "删除"}
need = {"读", "改"}

print(need <= owned)                # => False
print(sorted(need - owned))         # => ['改']      差集直接告诉你缺什么
```

`<` 和 `>` 是**真**子集/超集——多一条"不能相等"：

```python
owned = {"读", "写", "删除"}
print(owned <= owned)               # => True       自己是自己的子集
print(owned < owned)                # => False      但不是"真"子集
print({"读", "写"} < owned)         # => True       确实少几个 → 真子集
```

日常用 `<=` / `>=` 就够，`<` / `>` 很少需要。

**这几个运算符也要求两边都是集合**，想吃列表得用方法：

```python
required = {"读", "写"}
print(required <= ["读", "写"])
# => TypeError: '<=' not supported between instances of 'set' and 'list'
```

```python
required = {"读", "写"}
print(required.issubset(["读", "写"]))      # => True       方法版可以
```

**示例 12-20　判断两组数据完全不相干**

```python
print({1, 2}.isdisjoint({3, 4}))    # => True       毫无交集
print({1, 2}.isdisjoint({2, 3}))    # => False      有交集（2）
```

等价于 `len(a & b) == 0`，但 `isdisjoint` **找到第一个共同元素就停**，不用算完整个交集，数据大时更快。

## 12.12 集合推导式

和列表推导式（9.16 节）、字典推导式（11.14 节）同一个套路，只是外面套花括号、里面**没有冒号**。

**示例 12-21　集合推导式**

```python
records = [
    ("小明", "一班", 92),
    ("小红", "二班", 88),
    ("小刚", "一班", 76),
    ("小丽", "三班", 95),
]

# 这批数据里一共涉及哪几个班？——提取 + 去重一步完成
classes = {r[1] for r in records}
print(sorted(classes))              # => ['一班', '三班', '二班']
```

> **顺便解释一下这个排序结果**：`sorted()` 对中文是按**字符编码**排的，不是按"一二三"的语义。"一 三 二" 的编码正好是这个顺序。想按语义排，得自己给个顺序表（第 14 章讲了函数以后会容易得多）。

```python
print({x * x for x in range(-3, 4)})                    # => {0, 9, 4, 1}   顺序不定
print(sorted({len(w) for w in ["a", "bb", "cc", "ddd"]}))    # => [1, 2, 3]
```

第一个例子里 `-3` 和 `3` 的平方都是 9，**自动合并成一个**——这正是用集合推导式而不是列表推导式的理由：**既转换又去重**。

前面 12.5 节那个例子现在能看懂了：

```python
points = [[1, 2], [3, 4], [1, 2]]
print({tuple(p) for p in points})       # => {(1, 2), (3, 4)}    转成元组才能进集合
```

**空推导式没有 `{}` 的歧义问题**——只要花括号里有 `for`，Python 就知道是推导式；有冒号是字典推导式，没冒号是集合推导式。

## 12.13 遍历集合

**示例 12-22　遍历集合并固定顺序**

```python
s = {"香蕉", "苹果", "橘子"}

for x in s:             # 能遍历，但顺序不保证
    print(x)
```

**要给人看就一定套 `sorted()`**：

```python
s = {"香蕉", "苹果", "橘子"}

for x in sorted(s):
    print(x)
# => 橘子
# => 苹果
# => 香蕉
```

要编号就配 `enumerate`（8.11 节）：

```python
s = {"香蕉", "苹果", "橘子"}

for i, x in enumerate(sorted(s), 1):
    print(i, x)
# => 1 橘子
# => 2 苹果
# => 3 香蕉
```

**和字典一样，遍历集合时不能增删元素**，会抛 `RuntimeError: Set changed size during iteration`。需要边遍历边改，就遍历一份副本：`for x in list(s):`。

## 综合示例

### 示例 12-23　新旧名单对比

**这是集合最实用的场景**：数据同步时要知道哪些是新增的、哪些被删了、哪些没动。

先看很多人的写法：

```python
old_list = ["小明", "小红", "小刚"]
new_list = ["小红", "小刚", "小华", "小丽"]

# ❌ 双层循环：能出结果，但代码长、慢，而且只算出了"新增"这一项
added = []
for n in new_list:
    found = False
    for o in old_list:
        if n == o:
            found = True
            break
    if not found:
        added.append(n)

print(added)            # => ['小华', '小丽']
```

十行代码只解决了三分之一的问题，还得再写十行算"删除"。用集合三行搞定全部：

```python
old = {"小明", "小红", "小刚"}
new = {"小红", "小刚", "小华", "小丽"}

added = new - old           # 新名单有、老名单没有 → 新增
removed = old - new         # 老名单有、新名单没有 → 删除
kept = old & new            # 两边都有 → 保留不变

# 集合无序，给人看的输出一律 sorted()
print(f"新增 {len(added)} 人：{sorted(added)}")       # => 新增 2 人：['小丽', '小华']
print(f"删除 {len(removed)} 人：{sorted(removed)}")   # => 删除 1 人：['小明']
print(f"保留 {len(kept)} 人：{sorted(kept)}")         # => 保留 2 人：['小刚', '小红']
print(f"两边合计 {len(old | new)} 人")                # => 两边合计 5 人
print(f"有变动的 {len(old ^ new)} 人")                # => 有变动的 3 人
```

三个运算的方向不能记混，画出来就清楚了：

```text
        old（老名单）              new（新名单）
     ┌──────────────┐        ┌──────────────┐
     │              │        │              │
     │    小明      │        │   小华 小丽   │
     │              │        │              │
     │        ┌─────┴────────┴─────┐        │
     │        │     小红  小刚     │        │
     │        └─────┬────────┬─────┘        │
     └──────────────┘        └──────────────┘

       old - new         old & new        new - old
       （删除）           （保留）          （新增）
```

原始数据通常是列表（从文件或数据库读来的），转一下就行：

```python
old_list = ["小明", "小红", "小刚"]
new_list = ["小红", "小刚", "小华", "小丽"]

added = set(new_list) - set(old_list)       # 临时转成集合做运算
print(sorted(added))                         # => ['小丽', '小华']
```

> **记住这条**：**看到"两批数据要比对"，第一反应就该是 `-` 和 `&`，而不是双层循环。**
>
> **同一个套路能干的活**：数据库同步算增量、对比两份配置文件的差异、检查必填字段有没有漏、找出重复上报的记录、看两个版本的依赖包差在哪。都是三五行的事。
>
> **一个前提**：集合运算会去重，也会丢掉顺序和"出现次数"。如果你需要"小明出现了两次"这种信息，那要用第 11 章的字典计数，不是集合——见下面这段。

顺手把"必填字段检查"也写出来，同一个套路：

```python
required = {"姓名", "手机", "地址"}
form = {"姓名": "小明", "手机": "13800138000"}       # 用户提交的表单（字典）

# set(form) 取的是字典的键（11.7 节：直接遍历字典给的是键）
missing = required - set(form)
print(f"缺少字段：{sorted(missing)}")        # => 缺少字段：['地址']
print(f"填全了吗：{required <= set(form)}")  # => 填全了吗：False

form["地址"] = "北京"
print(f"填全了吗：{required <= set(form)}")  # => 填全了吗：True
print(f"多填的字段：{sorted(set(form) - required)}")     # => 多填的字段：[]
```

再看一眼**集合办不到的事**，避免用错工具：

```python
votes = ["A", "B", "A", "C", "A", "B"]

print(set(votes))               # => {'B', 'A', 'C'}     顺序不定；只知道"有哪些"

# 想知道"各有几票"，集合无能为力 → 用字典计数（11.16 节）
counter = {}
for v in votes:
    counter[v] = counter.get(v, 0) + 1
print(counter)                  # => {'A': 3, 'B': 2, 'C': 1}

# 反过来，有了计数就能挑出"重复的是哪些"（列表推导式，9.16 节）
print(f"有重复的选项：{sorted([k for k, n in counter.items() if n > 1])}")
# => 有重复的选项：['A', 'B']
print(f"总共 {len(votes)} 票，{len(set(votes))} 个不同选项")
# => 总共 6 票，3 个不同选项
```

**分工很清楚**：**集合管"有没有"，字典管"有几个"。**

### 示例 12-24　两个班的选课分析

把四种运算 + 子集判断放在一个真实场景里跑一遍。

```python
class1 = {"语文", "数学", "英语", "物理", "体育"}
class2 = {"语文", "数学", "英语", "化学", "音乐"}

# 交集：两个班都开的课
print(f"共同开的课（{len(class1 & class2)} 门）：{sorted(class1 & class2)}")
# => 共同开的课（3 门）：['数学', '英语', '语文']

# 差集：各自独有的课，注意两个方向
print(f"只有一班开的：{sorted(class1 - class2)}")       # => 只有一班开的：['体育', '物理']
print(f"只有二班开的：{sorted(class2 - class1)}")       # => 只有二班开的：['化学', '音乐']

# 并集：两个班加起来一共涉及多少门课（重复的只算一次）
print(f"两班一共开了 {len(class1 | class2)} 门")        # => 两班一共开了 7 门

# 对称差：有差异的课（= 只有一边开的全部）
print(f"有差异的课：{sorted(class1 ^ class2)}")
# => 有差异的课：['体育', '化学', '物理', '音乐']

# 子集：必修课开齐了吗
base = {"语文", "数学", "英语"}
print(f"一班开齐必修课了吗：{base <= class1}")          # => 一班开齐必修课了吗：True
print(f"一班缺的必修课：{sorted(base - class1)}")       # => 一班缺的必修课：[]
```

**每一行都对应一个自然语言的问题**——这就是集合的价值：**问题怎么说，代码就怎么写**。换成循环，同样的六个问题得写六七十行。

<details>
<summary><b>示例 12-25　frozenset（不可变集合，一瞥即可）</b></summary>

集合本身是可变的（能 `add`），所以它**不可哈希**，不能当字典的键、也不能放进另一个集合。`frozenset` 就是它的"不可变版"，因此**可哈希**——和"列表 vs 元组"的关系一模一样。

```python
f = frozenset({1, 2, 3})

print(f)                # => frozenset({1, 2, 3})       打印时带类型名
print(len(f), 2 in f)   # => 3 True                     查询功能一样

f.add(4)
# => AttributeError: 'frozenset' object has no attribute 'add'      改不了
```

**什么时候用**：需要拿"一组元素"当字典键的时候。

```python
# 用"权限组合"当键——普通集合做不到
combo = {frozenset({"读", "写"}): "编辑", frozenset({"读"}): "只读"}

# 顺序无关，因为集合相等只看内容
print(combo[frozenset({"写", "读"})])       # => 编辑
```

也能放进集合里（去掉重复的"组合"）：

```python
print({frozenset({1, 2}), frozenset({1, 2}), frozenset({3})})
# => {frozenset({3}), frozenset({1, 2})}       两个相同的组合合并了
```

对比一下普通集合：

```python
d = {{1, 2}: "x"}
# => TypeError: unhashable type: 'set'
```

四种运算照样能用，结果类型跟左边走：

```python
f = frozenset({1, 2, 3})
print(f | {4})          # => frozenset({1, 2, 3, 4})
print(type({4} | f))    # => <class 'set'>       左边是普通集合，结果就是普通集合
```

**日常几乎用不到**，认得出来就行。

<details>
<summary><b>给有 C# / Java / SQL 经验的读者</b></summary>

| 你熟悉的 | Python |
|---|---|
| `HashSet<T>` | `set` |
| `new HashSet<int> {1, 2, 3}` | `{1, 2, 3}` |
| `new HashSet<int>()` | **`set()`**（不是 `{}`！） |
| `ImmutableHashSet<T>` | `frozenset` |
| `s.Add(x)`（返回 bool 表示是否真加了） | `s.add(x)`（**没有返回值**，想知道加没加就先 `x in s`） |
| `s.Remove(x)`（返回 bool） | `s.remove(x)`（不存在抛 `KeyError`）/ `s.discard(x)`（静默） |
| `s.Contains(x)` | `x in s` |
| `s.Count` | `len(s)` |
| `s.IntersectWith(t)`（**原地改**） | `s &= t` 或 `s.intersection_update(t)` |
| `s.Intersect(t)`（LINQ，**返回新的**） | `s & t` 或 `s.intersection(t)` |
| `s.UnionWith(t)` / LINQ `Union` | `s \|= t` / `s \| t` |
| `s.ExceptWith(t)` / LINQ `Except` | `s -= t` / `s - t` |
| `s.SymmetricExceptWith(t)` | `s ^= t` / `s ^ t` |
| `s.IsSubsetOf(t)` | `s <= t` |
| `s.IsProperSubsetOf(t)` | `s < t` |
| `s.Overlaps(t)` | `not s.isdisjoint(t)` |
| LINQ `.Distinct()` | `set(lst)`（乱序）或 `list(dict.fromkeys(lst))`（**保序**） |

**四个需要注意的**：

1. **`{}` 是字典不是空集合。** C# 里 `new HashSet<int>()` 和 `new Dictionary<...>()` 写法明显不同，Python 这里是共用花括号导致的历史包袱。
2. **原地改 vs 返回新的，Python 分得比 C# 清楚。** 运算符（`&` `|` `-` `^`）**一律返回新集合**，复合赋值（`&=` `|=` `-=` `^=`）**一律原地改**。不像 C# 需要记住 `IntersectWith` 和 `Intersect` 哪个是哪个。
3. **`add` 没有返回值。** C# 的 `HashSet.Add` 返回 bool 告诉你"是不是新元素"，Python 的 `add` 返回 `None`。要这个信息只能先判断：`is_new = x not in s`。
4. **LINQ 的 `Distinct()` 是保序的，Python 的 `set()` 不是。** 这是个容易直接踩的差异——从 C# 过来的人很容易以为 `list(set(lst))` 会保序。

**SQL 背景的读者**，这一章你会觉得格外熟悉，因为**集合运算就是 SQL 的集合运算**：

| SQL | Python |
|---|---|
| `SELECT DISTINCT col FROM t` | `set(col_values)` |
| `A INTERSECT B` | `a & b` |
| `A UNION B`（去重） | `a \| b` |
| `A UNION ALL B`（不去重） | `list_a + list_b`（**用列表，不是集合**） |
| `A EXCEPT B` / `MINUS` | `a - b` |
| `WHERE id IN (...)` | `id in s` |
| `WHERE NOT EXISTS (...)` 找差异 | `a - b` |

12.13 那个"新旧名单对比"，对应的 SQL 就是一组 `EXCEPT` / `INTERSECT`。你平时写 SQL 不会用双层游标做这件事，**在 Python 里也别用双层循环**——是同一个道理，只是换了个地方。

另外 12.8 节的效率对比，本质上就是**全表扫描 vs 索引查找**：`set()` 转换相当于建索引（一次性成本），之后每次 `in` 都是索引命中。

</details>

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| **`s = {}` 想建空集合** | 得到的是**空字典** | `s = set()` | `{}` 被字典占用了 |
| `s[0]` | `TypeError: not subscriptable` | 要按位置取先 `sorted(s)` | 集合无序，没有"第几个" |
| **依赖集合的遍历顺序** | 本地正常，换机器就变 | 输出前一律 `sorted()` | 顺序从未被承诺 |
| `list(set(lst))` 后直接输出 | 顺序不可预测 | `list(dict.fromkeys(lst))` | 同上 |
| `{[1, 2]}` | `unhashable type: 'list'` | 改用元组 `{(1, 2)}` | 元素必须可哈希 |
| 把字典或集合放进集合 | `unhashable type: 'dict'` / `'set'` | 用 `frozenset` 或元组 | 同上 |
| `s.remove(x)` 删不存在的 | `KeyError` | 用 `s.discard(x)` | `remove` 要求元素存在 |
| **差集方向搞反** | 算出来的"新增"其实是"删除" | 记住 `a - b` 是"a 有 b 没有" | 只有差集看方向 |
| `a & [1, 2]` | `TypeError: unsupported operand` | `a.intersection([1, 2])` | 运算符要求两边都是集合 |
| `required <= ["读"]` | `TypeError: '<=' not supported` | `required.issubset(["读"])` | 同上 |
| `s.update("xy")` 想加一个元素 | 加进去的是 `'x'` 和 `'y'` | 用 `s.add("xy")` | `update` 拆开可迭代对象 |
| 用 `s.pop()` 想删指定元素 | 删掉的是不确定的某一个 | 用 `remove` / `discard` | `pop` 不接受参数 |
| `set().pop()` | `KeyError: 'pop from an empty set'` | 先判断 `if s:` | 空集合没东西可删 |
| 用集合处理需要计数的场景 | 丢失了"出现几次"的信息 | 改用字典计数（11.16） | 集合只记"有没有" |
| 只判断一次就把大列表转集合 | 转换开销超过收益 | 反复判断才值得转 | 转换要遍历一遍 |
| `a.intersection("123")` 想匹配数字 | 得到 `set()` | 字符 `'1'` 不等于数字 `1` | 字符串被拆成了字符 |
| 遍历集合时增删 | `RuntimeError: Set changed size` | 遍历 `list(s)` 副本 | 迭代中结构不能变 |
| 以为 `s.add()` 返回是否新增 | 得到 `None` | 先 `x not in s` 判断 | `add` 无返回值 |

## 本章小结

- **集合 = 只有键、没有值的字典**——记住这一句，它的所有性质都能推出来
- **两个使用信号**：① 要**去重** ② 要**两批数据比对**
- **`{}` 是空字典，空集合只能写 `set()`**；空集合打印出来是 `set()`
- 元素**不重复**（按 `==` 判定）、**必须可哈希**（不能放列表/字典/集合）
- **无序**：不能索引、不能切片；**输出给人看之前一律 `sorted()`**
- 增：`add` 加一个整体，**`update` 拆开来加**；删：`remove` 报错、**`discard` 静默**、`pop` 随机（别用）
- **去重**：`set(lst)` 乱序，**`list(dict.fromkeys(lst))` 保序**
- **`in` 对集合快几千倍**；但只判断一次不值得转，**`in` 写在循环里才转**
- **四种运算**：`&` 交集、`|` 并集、`-` 差集（**有方向**）、`^` 对称差；只有差集看顺序
- **运算符要求两边都是集合，方法能吃列表**（`a.intersection(lst)`）
- 复合赋值 `&=` `|=` `-=` `^=` 是**原地改**，运算符是**返回新的**
- 子集 `<=`、超集 `>=`、真子集 `<`、毫无交集 `isdisjoint()`
- 集合推导式 `{x for x in ...}`：**又转换又去重**
- **集合管"有没有"，字典管"有几个"**
- `frozenset` 是不可变集合，因此可哈希，能当字典键（日常少见）

### 方法与运算速查

| 写法 | 作用 | 注意 |
|---|---|---|
| `{1, 2}` / `set(可迭代对象)` | 创建 | **空集合必须 `set()`** |
| `s.add(x)` | 加一个 | 加整体；无返回值 |
| `s.update(可迭代对象)` | 批量加 | **会拆开**字符串 |
| `s.remove(x)` | 删 | 不存在 `KeyError` |
| `s.discard(x)` | 删 | **不存在也不报错，常用** |
| `s.pop()` / `s.clear()` | 随机删一个 / 清空 | `pop` 基本别用 |
| `x in s` | 成员测试 | **比列表快几千倍** |
| `len(s)` / `if s:` | 个数 / 判空 | —— |
| `a & b` / `a.intersection(b)` | 交集 | 两边都有的 |
| `a \| b` / `a.union(b)` | 并集 | 合起来，自动去重 |
| `a - b` / `a.difference(b)` | 差集 | **a 有 b 没有，有方向** |
| `a ^ b` / `a.symmetric_difference(b)` | 对称差 | 只在一边的 |
| `a &= b` / `\|=` / `-=` / `^=` | 同上但**原地改** | 不产生新集合 |
| `a <= b` / `a.issubset(b)` | 子集 | `<` 是真子集 |
| `a >= b` / `a.issuperset(b)` | 超集 | —— |
| `a.isdisjoint(b)` | 毫无交集 | 比 `len(a&b)==0` 快 |
| `a.copy()` | 浅拷贝 | 第 13 章讲清"浅" |
| `{x for x in ...}` | 集合推导式 | 转换 + 去重 |
| `sorted(s)` | 排序 | 结果是**列表** |
| `set(lst)` | 去重（**乱序**） | 最快 |
| `list(dict.fromkeys(lst))` | 去重（**保序**） | 给人看的数据用这个 |
| `len(lst) == len(set(lst))` | 判断有无重复 | —— |
| `frozenset({...})` | 不可变集合 | 可哈希，能当键 |

### 四种运算记忆卡

```text
a = {1, 2, 3, 4}        b = {3, 4, 5, 6}

a & b  →  {3, 4}              两边都有         "and"
a | b  →  {1,2,3,4,5,6}       合起来           "or"
a - b  →  {1, 2}              a 有 b 没有  ←── 只有这个看方向
b - a  →  {5, 6}              b 有 a 没有
a ^ b  →  {1, 2, 5, 6}        只在一边的       = (a-b) | (b-a)
```
