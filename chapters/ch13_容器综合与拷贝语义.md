## 13.1 四大容器选型

先看一张总表。**不用背，用的时候回来查**：

| | 列表 `list` | 元组 `tuple` | 字典 `dict` | 集合 `set` |
|---|---|---|---|---|
| 写法 | `[1, 2]` | `(1, 2)` | `{"a": 1}` | `{1, 2}` |
| **能不能改** | ✅ 能 | ❌ 不能 | ✅ 能 | ✅ 能 |
| **有没有顺序** | ✅ 有 | ✅ 有 | ✅ 有（3.7+） | ❌ 没有 |
| **能不能重复** | ✅ 能 | ✅ 能 | 键不能 | ❌ 不能 |
| **按什么取值** | 位置 `lst[0]` | 位置 `t[0]` | **键** `d["a"]` | **取不了** |
| 能不能切片 | ✅ | ✅ | ❌ | ❌ |
| 能当字典键吗 | ❌ | ✅（元素也不可变时） | ❌ | ❌（用 `frozenset`） |
| 空的写法 | `[]` | `()` | `{}` | **`set()`** |
| **典型用途** | 一批同类数据，会增删 | 固定搭配的几项、当字典键 | 名字→值的对应关系 | 去重、两批数据比对 |

**示例 13-1　同一个需求，四种容器各写一遍**

需求是"记录班上的学生"。四种容器都能装，但**能干的事完全不同**。

```python
# ① 列表：一批学生，会增会删，按顺序排
names_list = ["小明", "小红", "小刚"]
print(names_list[0])          # => 小明        能按位置取
names_list.append("小丽")      # 能加
print(names_list)             # => ['小明', '小红', '小刚', '小丽']
```

```python
# ② 元组：名单定下来就不许改（比如已经打印出去的座位表）
names_tuple = ("小明", "小红", "小刚")
print(names_tuple[0])         # => 小明        照样能按位置取

names_tuple.append("小丽")
# => AttributeError: 'tuple' object has no attribute 'append'    改不了，这正是它的价值
```

```python
# ③ 字典：不只记名字，还要记每人的分数——名字和分数要对应起来
scores_dict = {"小明": 92, "小红": 88, "小刚": 76}
print(scores_dict["小明"])     # => 92         按【名字】取，不用管他排第几
scores_dict["小丽"] = 95       # 加一个人
print(len(scores_dict))       # => 4
```

```python
# ④ 集合：只关心"这个班有哪些人"，重复报名的自动合并
names_set = {"小明", "小红", "小刚", "小明"}     # 小明写了两遍
print(len(names_set))         # => 3          重复的没了
print("小明" in names_set)     # => True       查"在不在"极快

names_set[0]
# => TypeError: 'set' object is not subscriptable    但取不出"第一个"
```

**同一批数据，四种装法，能力各不相同**：

| 我想…… | 列表 | 元组 | 字典 | 集合 |
|---|---|---|---|---|
| 取第一个学生 | ✅ | ✅ | ❌ | ❌ |
| 加一个学生 | ✅ | ❌ | ✅ | ✅ |
| 查小明的分数 | ❌ 要先找位置 | ❌ | ✅ 直接取 | ❌ 没存分数 |
| 快速判断"小明在不在" | ⚠️ 慢（要扫） | ⚠️ 慢 | ✅ 快 | ✅ 快 |
| 自动去掉重复报名 | ❌ | ❌ | ✅ 键自动去重 | ✅ |
| 防止别人改坏名单 | ❌ | ✅ | ❌ | ❌ |

**示例 13-2　选型决策流程**

真正实用的不是那张大表，而是**按顺序问自己四个问题**：

```text
① 数据是"名字 → 值"的对应关系吗？
   （学号→姓名、商品→价格、配置项→取值、单词→出现次数）
   是 ──────────────────────→ 【字典】
   否 ↓

② 只关心"有哪些 / 在不在"，不关心顺序和个数吗？
   （去重、两批数据比对、黑名单查询）
   是 ──────────────────────→ 【集合】
   否 ↓

③ 这批数据定了之后还要增删改吗？
   要 ──────────────────────→ 【列表】
   不要 ↓

④ 【元组】
   （固定搭配的几项、要当字典键、要防止被改）
```

**九成的情况在第 ① 和 ③ 步就落地了**——字典和列表是绝对的主力，元组和集合是有明确理由时才用。

几个真实需求走一遍流程：

| 需求 | 走到第几步 | 选 |
|---|---|---|
| 统计每个词出现几次 | ①（词 → 次数） | 字典 |
| 读一个文件的所有行 | ③（要能增删） | 列表 |
| 一个点的坐标 `(x, y)` | ④（固定两项） | 元组 |
| 新旧名单比对谁走了 | ②（只关心有哪些） | 集合 |
| 待办事项清单 | ③ | 列表 |
| 函数返回两个结果 | ④ | 元组（自动的） |
| 已处理过的订单号 | ②（快速查"处理过没"） | 集合 |
| 一条数据库记录 | ①（字段名 → 值） | 字典 |

> **记住这条**：**先问"是不是名字对值"，再问"要不要去重"，再问"要不要改"。** 三个问题解决绝大多数选型。
>
> **一个常见的选型错误**：用两个平行列表存对应关系（`names` 和 `scores` 靠下标对齐）。第 11 章开头讲过，**这种写法一旦某一边增删就会错位，而且不报错**。看到两个列表要靠下标对应，立刻改成字典。

## 13.2 三个概念：可迭代、序列、映射

这三个词你会在报错信息和文档里反复看到，**分清了才能看懂报错**。

它们的关系是**包含关系**：

```text
┌─────────────────────────────────────────────┐
│  可迭代对象 iterable                          │
│  ——能用 for 一个个取出来                       │
│  字符串 列表 元组 字典 集合 range 文件对象...    │
│                                             │
│   ┌───────────────────────┐  ┌───────────┐  │
│   │  序列 sequence         │  │ 映射       │  │
│   │  ——有顺序、能按下标取   │  │ mapping   │  │
│   │  字符串 列表 元组 range │  │ 字典       │  │
│   └───────────────────────┘  └───────────┘  │
│                                             │
│   集合既不是序列也不是映射（无序、没有键值对）    │
└─────────────────────────────────────────────┘
```

| 概念 | 定义 | 谁是 | 能做什么 |
|---|---|---|---|
| **可迭代对象** | 能被 `for` 一个个取出来 | 字符串、四大容器、`range`、文件对象 | `for x in it:`、`in`、`len`（多数）、能喂给 `list()` / `set()` |
| **序列** | **有顺序**，能按下标取 | 字符串、列表、元组、`range` | 上面全部 + **索引 `x[0]`** + **切片 `x[1:3]`** |
| **映射** | 存**键 → 值**的对应 | 字典 | 上面的可迭代 + **按键取值 `d["a"]`** |

**为什么要分清？因为它决定了哪些操作能用。**

```python
# 序列：能索引、能切片
print([1, 2, 3][0])      # => 1
print([1, 2, 3][0:2])    # => [1, 2]
print((1, 2, 3)[0:2])    # => (1, 2)      元组切出来还是元组
print("abc"[0:2])        # => ab          字符串切出来还是字符串
```

```python
# 映射：方括号里放的是【键】，不是位置
d = {0: "零"}
print(d[0])              # => 零        这里的 0 是键，不是"第一个"

d2 = {"a": 1}
d2[0]
# => KeyError: 0        没有 0 这个键（注意报的是 KeyError，不是 IndexError）
```

**这里有个新手常犯的误会**：`d[0]` 看着像"取第一个"，其实是"取键为 0 的值"。字典**永远没有"第几个"的概念**，方括号里只能是键。

```python
# 集合：既不能索引也不能切片
{1, 2}[0]
# => TypeError: 'set' object is not subscriptable
```

**光看报错就能推断问题**——这是分清概念最直接的收益：

| 报错 | 说明 | 常见原因 |
|---|---|---|
| `not subscriptable` | 这东西**不支持方括号** | 对集合用了下标，或对 `None` 用了下标 |
| `IndexError` | 支持下标，但**超出范围** | 序列越界 |
| `KeyError` | 是映射，但**没这个键** | 字典键写错 |
| `not iterable` | **连 `for` 都不能用** | 对数字用了 `for`，或函数返回了 `None` |

顺便认识几个"只能迭代、不是容器"的东西——它们不存数据，只负责一个个往外交：

```python
print(list(range(3)))                    # => [0, 1, 2]
print(list(enumerate(["a", "b"])))       # => [(0, 'a'), (1, 'b')]
print(list(zip([1, 2], "ab")))           # => [(1, 'a'), (2, 'b')]
print(list({"a": 1, "b": 2}.items()))    # => [('a', 1), ('b', 2)]
```

**它们都是可迭代对象，但都不是列表**——想按下标取、想打印看内容，都得先 `list()` 一下。这也解释了为什么前面章节里 `zip`、`enumerate`、`d.items()` 老是要套一层 `list()`。

## 13.3 一批函数，四种容器通用

Python 的一致性设计有个很实在的好处：**同一批内置函数对所有容器都能用**。学一次，四处通用。

**示例 13-3　len / min / max / sum / sorted 通用**

```python
lst = [3, 1, 2]
tup = (3, 1, 2)
st = {3, 1, 2}

print(len(lst), len(tup), len(st))          # => 3 3 3
print(min(lst), max(lst), sum(lst))         # => 1 3 6
print(min(st), max(st), sum(st))            # => 1 3 6      集合一样能用
print(sorted(tup))                          # => [1, 2, 3]  返回的总是【列表】
```

**注意 `sorted()` 的返回值永远是列表**，不管你喂进去的是什么：

```python
print(sorted((3, 1, 2)))            # => [1, 2, 3]        元组进，列表出
print(sorted({3, 1, 2}))            # => [1, 2, 3]        集合进，列表出
print(sorted("312"))                # => ['1', '2', '3']  字符串进，【字符列表】出
print("".join(sorted("312")))       # => 123              想要字符串得自己拼回去
```

**示例 13-4　`in` 对四种容器分别查什么**

`in` 的语法一样，**查的东西不一样**：

```python
print(2 in [1, 2, 3])           # => True      列表：查元素
print(2 in (1, 2, 3))           # => True      元组：查元素
print(2 in {1, 2})              # => True      集合：查元素
print("a" in {"a": 1})          # => True      字典：查【键】
print(1 in {"a": 1})            # => False     ！1 是值不是键，查不到
print(1 in {"a": 1}.values())   # => True      要查值得写 .values()
print("ell" in "hello")         # => True      字符串：查【子串】，不是单个字符
```

**两个要留心的**：字典的 `in` 查键（第 11.3 节讲过），字符串的 `in` 查子串（连续的一段，不是"包含这些字符"）。

**示例 13-5　`sorted` 对字典排的是键**

```python
d = {"c": 3, "a": 1, "b": 2}

print(sorted(d))                # => ['a', 'b', 'c']                  只有键
print(sorted(d.values()))       # => [1, 2, 3]                        只有值
print(sorted(d.items()))        # => [('a', 1), ('b', 2), ('c', 3)]   键值对
```

**规律很好记**：凡是**直接把字典交给某个函数**，它拿到的都是键（因为遍历字典默认给键）。要值就写 `.values()`，要两者就写 `.items()`。

`reversed()` 也通用，但**集合用不了**——它无序，"倒过来"没有意义：

```python
print(list(reversed([1, 2, 3])))        # => [3, 2, 1]
print(list(reversed("abc")))            # => ['c', 'b', 'a']
print(list(reversed({"a": 1, "b": 2}))) # => ['b', 'a']    字典可以（按插入顺序倒过来）

list(reversed({1, 2, 3}))
# => TypeError: 'set' object is not reversible
```

**示例 13-6　空容器和类型不对的边界**

这几个边界值得单独记，因为**一半安静一半报错**：

```python
print(sum([]))          # => 0        ✅ 空的和是 0，很合理
print(len([]))          # => 0        ✅
print(sorted([]))       # => []       ✅

max([])
# => ValueError: max() iterable argument is empty      ❌ 空的最大值？没有答案
```

`min` / `max` 遇到空容器**会崩**，因为"没有元素"时最大值确实不存在。要兜底就给 `default`：

```python
print(max([], default="空"))        # => 空            指定"空的时候返回什么"
print(max([3, 1], default="空"))    # => 3             非空时 default 不起作用
```

`sum` 只能加数字：

```python
sum(["a", "b"])
# => TypeError: unsupported operand type(s) for +: 'int' and 'str'
```

报错文字很有意思——`int` 和 `str` 相加。为什么有 `int`？因为 **`sum` 是从 0 开始加的**，第一步就是 `0 + "a"`。拼字符串要用 `join`：

```python
print("".join(["a", "b"]))      # => ab
```

同理，把字典直接扔给 `sum` 也会崩，因为它加的是键：

```python
sum({"a": 1})
# => TypeError: unsupported operand type(s) for +: 'int' and 'str'      加的是键 "a"
```

```python
print(sum({"a": 1, "b": 2}.values()))   # => 3      要加值就写清楚
```

`min` / `max` 还能带 `key`，用法和 `sorted` 一样（第 11.17 节见过）：

```python
records = [("小明", 92), ("小红", 88)]
print(max(records, key=lambda r: r[1]))     # => ('小明', 92)     按分数比，不是按名字
print(min(records, key=lambda r: r[1]))     # => ('小红', 88)
```

不给 `key` 时，元组是**按第一项比**的，那样比的就是名字了。

## 13.4 `any` 和 `all`：一个反直觉的边界

**示例 13-7　any 和 all 的基本用法**

```python
print(any([False, True]))       # => True       有一个真就为真
print(all([False, True]))       # => False      要全部为真才为真
print(any([0, 0, 1]))           # => True       0 是假，1 是真
print(all([1, 2, 3]))           # => True       全都是真
print(all([1, 2, 0]))           # => False      0 拖后腿
```

配上列表推导式（第 9.16 节）就非常好用——**一行完成"全体检查"**：

```python
scores = [90, 85, 70]

print(all([x >= 60 for x in scores]))   # => True      全部及格吗？
print(any([x > 100 for x in scores]))   # => False     有没有异常数据？
```

**示例 13-8　空容器让 `all` 返回 `True`**

现在是本节的重点，**这个边界会真的坑到你**：

```python
print(any([]))          # => False      空的里面找不到真的 → 假。合理
print(all([]))          # => True       ！空的居然是 True
```

第二行看着不讲道理，但换个说法就通了：

> **`all` 的语义不是"全部都真"，而是"没有一个假的"。**
>
> 空容器里当然找不到假的 → 所以是 `True`。

数学上这叫"空真"（vacuous truth）。你不用记这个词，记那句"**没有反例**"就够了。

**什么时候会踩到？校验一批数据的时候**：

```python
scores = [90, 85, 70]
print(all([x >= 60 for x in scores]))   # => True      三个人都及格，正确

empty = []                               # 万一这批数据是空的（文件是空的、筛选后没剩下）
print(all([x >= 60 for x in empty]))    # => True      ！空数据"通过了"检查
```

**这就是 bug 的来源**：你的代码写着"所有数据都合格才继续"，结果数据一条都没有的时候，它也说"合格"，然后带着空数据往下跑。

**正确写法是先判断非空**：

```python
data = []                                # 数据是空的

# ❌ 空数据被当成了"全部合格"
if all([x >= 60 for x in data]):
    print("全部合格")                     # => 全部合格      ！明明一条数据都没有

# ✅ 明确要求"有数据 且 全部合格"
if data and all([x >= 60 for x in data]):
    print("全部合格")
else:
    print("没有数据，或有不合格的")          # => 没有数据，或有不合格的
```

> **记住这条**：**`all([])` 是 `True`。** 凡是用 `all` 做校验，先问一句"数据可能是空的吗"——可能就加上 `if data and ...`。
>
> **为什么 Python 这样设计**：因为 `all` 的实现就是"遍历，遇到假的就返回 `False`，一个都没遇到就返回 `True`"。空容器一次循环都不进，直接走到最后。这个设计和数学惯例一致，也让 `all(a + b) == (all(a) and all(b))` 这类性质成立。**不是设计失误，但你必须知道它。**

## 13.5 回到"标签"模型

从这里开始进入本章的重点。**前面五笔账，从这一节开始还。**

第 3.3 节说过一句话，当时只是个比方，现在要把它当作严格的规则来用：

> **变量不是装东西的盒子，而是贴在对象上的标签。`=` 是贴标签，不是复制。**

```text
❌ 错误的想象（盒子模型）：

   a ┌───────────┐        b ┌───────────┐
     │ [1, 2, 3] │          │ [1, 2, 3] │
     └───────────┘          └───────────┘
   b = a 时把内容复制了一份 —— Python 不是这样工作的


✅ 正确的想象（标签模型）：

           ┌───────────┐
   a ─────→│ [1, 2, 3] │←───── b
           └───────────┘
   b = a 只是给【同一个对象】贴上第二个标签
```

**为什么 Python 选了这个设计？** 因为复制一份数据是要付代价的——时间和内存。而**绝大多数时候你并不需要复制**，你只是想换个名字用它，或者把它传给别处。语言默认选了便宜的那个，需要复制时你再明确说。

C# / Java 里引用类型也是这个行为，只是那些语言的 `int`、`struct` 是值类型，形成了对照，所以你比较有感觉；Python 里**所有东西都是对象，一律走引用**，没有例外。

## 13.6 `b = a` 的真相

**示例 13-9　`b = a` 之后，它们是同一个对象**

```python
a = [1, 2, 3]
b = a

print(a is b)               # => True      is 问的是"是不是同一个对象"
print(id(a) == id(b))       # => True      id 是对象的身份证号，相同就是同一个
```

`is` 和 `==` 的区别（第 4 章讲过）在这里特别关键：

- `a == b` 问的是**内容一样吗**
- `a is b` 问的是**根本就是同一个吗**

**示例 13-10　改 `b`，`a` 当然也变**

```python
a = [1, 2, 3]
b = a               # 只是贴了第二个标签，没有第二个列表

b.append(4)         # 通过 b 这个标签去改那个列表

print(a)            # => [1, 2, 3, 4]      a 看到的是同一个列表，当然也变了
print(b)            # => [1, 2, 3, 4]
```

**这就是第 9.21 节那个现象的全部原因**——不是"赋值有 bug"，而是从来就只有一个列表。

字典、集合完全一样：

```python
d1 = {"x": 1}
d2 = d1
d2["y"] = 2
print(d1)           # => {'x': 1, 'y': 2}      同一个字典
```

**换个说法帮你记住**：`b.append(4)` 里的 `b` 不重要，重要的是它指向哪个对象。**你不是在改 `b`，你是在改"那个列表"**——而 `a` 和 `b` 指的是同一个。

## 13.7 为什么数字和字符串"看起来没事"

**示例 13-11　数字和字符串为什么不会互相影响**

同样的写法，换成数字就"正常"了：

```python
x = 10
y = x
print(x is y)       # => True       注意：它们也是同一个对象！

y = 20              # 关键在这一行
print(x, y)         # => 10 20      x 没变
print(x is y)       # => False      现在不是同一个了
```

**很多人以为这说明"数字是值类型、复制了一份"。不是的。** 真正的原因是：

> `y = 20` 不是"把那个 10 改成 20"，而是"**把 y 这张标签撕下来，贴到 20 上去**"。

数字 `10` 那个对象**从头到尾没被动过**，`x` 还贴在它身上。

```text
y = x 之后：              y = 20 之后：

   x ──→ 10 ←── y            x ──→ 10
                              y ──→ 20     （y 换了个对象贴）
```

**这里有个关键区分，务必分清**：

| 写法 | 做的事 | 影响别的标签吗 |
|---|---|---|
| `b.append(4)`、`d["k"]=v`、`b[0]=9` | **改那个对象本身** | ✅ 会，所有标签都看到 |
| `b = 新东西` | **把 b 撕下来贴到别处** | ❌ 不会，别的标签没动 |

**上面那一行是本章最重要的一张表。** `b = ...` 永远只影响 `b` 自己；`b.什么方法(...)` 才是在动对象。

那为什么数字、字符串、元组**永远**不会出问题？因为它们**没有任何方法能改自己**：

```python
s1 = "hello"
s2 = s1
s2 = s2.upper()         # upper() 返回【新字符串】，不是改原来那个
print(s1, s2)           # => hello HELLO      s1 完好

t1 = (1, 2)
t2 = t1
t2 += (3,)              # 第 10.16 节讲过：这是重新赋值，产生了新元组
print(t1, t2)           # => (1, 2) (1, 2, 3)
```

> **记住这条**：**不可变对象永远不需要拷贝。** 数字、字符串、`bool`、`None`、（元素也不可变的）元组，随便共享，因为谁都改不了它们。
>
> **需要操心拷贝的只有三个：列表、字典、集合。**

## 13.8 浅拷贝的三种写法

想要"真的两份"，就得明确说出来。

**示例 13-12　浅拷贝的三种写法，效果完全一样**

```python
import copy               # 标准库，第 18 章会讲 import 的完整规则，先照着写

a = [1, 2, 3]

b1 = a[:]                 # ① 切片：只有序列（列表、元组、字符串）能用
b2 = list(a)              # ② 构造函数：list() / dict() / set()
b3 = copy.copy(a)         # ③ copy 模块：通用，什么容器都行

print(b1, b2, b3)                       # => [1, 2, 3] [1, 2, 3] [1, 2, 3]
print(a is b1, a is b2, a is b3)        # => False False False    都是新对象
print(a == b1, a == b2, a == b3)        # => True True True       但内容相同
```

**三种没有优劣，看容器类型和习惯选**：

| 容器 | 常用写法 |
|---|---|
| 列表 | `a[:]` 或 `list(a)` |
| 字典 | `d.copy()` 或 `dict(d)` |
| 集合 | `s.copy()` 或 `set(s)` |
| 不确定类型 / 写通用代码 | `copy.copy(x)` |

先确认它在**单层**数据上确实好用：

```python
a = [1, 2, 3]
b = a[:]

b.append(4)
print(a)            # => [1, 2, 3]         ✅ 原件没受影响
print(b)            # => [1, 2, 3, 4]
print(a is b)       # => False             确实是两个对象
```

## 13.9 浅拷贝的边界：只管第一层

**这一节是本章最容易吃亏的地方。**

**示例 13-13　浅拷贝管不到里面那一层**

数据一嵌套，浅拷贝就不够了：

```python
a = [[1, 2], [3, 4]]        # 外层列表里装了两个内层列表
b = a[:]                     # 还是切片拷贝

b[0].append(99)              # 注意：改的是 b 里面那个【内层】列表

print(a)                     # => [[1, 2, 99], [3, 4]]    ！原件的内层也变了
print(b)                     # => [[1, 2, 99], [3, 4]]
```

原因是**切片只复制了外层那个列表**。新列表里装的仍然是**指向同样两个内层列表的引用**：

```python
a = [[1, 2], [3, 4]]
b = a[:]

print(a is b)               # => False     外层：两个不同的列表 ✅
print(a[0] is b[0])         # => True      内层：还是同一个对象 ❌
```

画出来：

```text
浅拷贝之后：

  a ──→ [ ●, ● ]
          │  │
          │  └──→ [3, 4] ←───┐
          └────→ [1, 2] ←──┐ │
                           │ │
  b ──→ [ ●, ● ]───────────┘ │
          └──────────────────┘

  外层是两个不同的列表（所以 a is b 为 False）
  但两个外层列表里装的是【同样的】内层列表引用
```

另外两种浅拷贝写法一模一样，别指望换个写法能解决：

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)            # copy.copy 也是浅拷贝
b[0].append(99)
print(a)                    # => [[1, 2, 99], [3, 4]]     一样的问题
```

```python
a = [[1, 2], [3, 4]]
b = list(a)                 # list() 也是浅拷贝
b[0].append(99)
print(a)                    # => [[1, 2, 99], [3, 4]]     一样的问题
```

**"浅"这个字就是"只到第一层就停了"的意思。**

## 13.10 深拷贝：递归复制每一层

**示例 13-14　`deepcopy` 彻底断开**

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.deepcopy(a)        # 递归复制每一层

b[0].append(99)

print(a)                    # => [[1, 2], [3, 4]]         ✅ 原件安然无恙
print(b)                    # => [[1, 2, 99], [3, 4]]
print(a[0] is b[0])         # => False                    连内层都是独立的了
```

`deepcopy` 会**一层层往下走**，遇到可变对象就复制一份，直到走到不可变的叶子（数字、字符串）为止。结果是两份数据**彻底无关**，改任何一层都互不影响。

## 13.11 三种情况对照实验

**示例 13-15　同一份数据，三种做法各改一次**

**这个实验做完，拷贝这件事就通了。** 请一定自己敲一遍。

```python
import copy

# --- ① b = a ---
orig = [[1, 2], [3, 4]]
b = orig
b[0].append("A")
print(orig)                 # => [[1, 2, 'A'], [3, 4]]    原件变了

# --- ② 浅拷贝 ---
orig = [[1, 2], [3, 4]]
b = orig[:]
b[0].append("B")
print(orig)                 # => [[1, 2, 'B'], [3, 4]]    原件【也】变了！

# --- ③ 深拷贝 ---
orig = [[1, 2], [3, 4]]
b = copy.deepcopy(orig)
b[0].append("C")
print(orig)                 # => [[1, 2], [3, 4]]         ✅ 原件没变
```

**注意 ① 和 ② 的结果一样**——这是最容易让人误判的地方。你以为"我拷贝过了应该没问题"，但只要改的是**内层**，浅拷贝和不拷贝**效果完全相同**。

再用 `is` 把三种情况的身份关系看清楚：

```python
import copy

orig = [[1, 2], [3, 4]]

v1 = orig                    # 直接赋值
v2 = orig[:]                 # 浅拷贝
v3 = copy.deepcopy(orig)     # 深拷贝

print(orig is v1,    orig is v2,    orig is v3)         # => True False False
print(orig[0] is v1[0], orig[0] is v2[0], orig[0] is v3[0])  # => True True False
```

**一张表看清全部**（这张表要背下来）：

| 写法 | 外层 | 内层 | 什么时候够用 |
|---|---|---|---|
| `b = a` | 共享 | 共享 | 只是想换个名字用，**不打算改** |
| `b = a[:]` / `list(a)` / `copy.copy(a)` | **独立** | 共享 | 数据只有一层，或**只改最外层的增删** |
| `b = copy.deepcopy(a)` | **独立** | **独立** | 数据有嵌套，且**要改里面的内容** |

**示例 13-16　字典和集合的拷贝：同样只到第一层**

```python
d = {"a": 1, "inner": [1, 2]}
d2 = d.copy()

d2["a"] = 99                # 改第一层的值
print(d)                    # => {'a': 1, 'inner': [1, 2]}         ✅ 没影响原件

d2["inner"].append(3)       # 改第二层（那个列表）
print(d)                    # => {'a': 1, 'inner': [1, 2, 3]}      ❌ 原件被改了
```

**同一份代码里一半正常一半出错**——`d2["a"] = 99` 是"重新贴标签"（安全），`d2["inner"].append(3)` 是"改对象"（危险）。这正是 13.7 节那张表的应用。**这种 bug 最难查**，因为它不是"总是错"，而是"有时候错"。

`dict()` 和 `deepcopy` 的对照：

```python
import copy

d = {"a": 1, "inner": [1, 2]}
print(dict(d)["inner"] is d["inner"])       # => True      dict() 也是浅拷贝

d4 = copy.deepcopy(d)
d4["inner"].append(100)
print(d["inner"], d4["inner"])              # => [1, 2] [1, 2, 100]    ✅ 独立
```

集合稍特殊：**集合的元素必须可哈希、也就是不可变**，所以集合里根本装不了列表和字典——**集合永远不需要深拷贝**：

```python
s = {1, 2}
s2 = s.copy()
s2.add(3)
print(s, sorted(s2))        # => {1, 2} [1, 2, 3]      浅拷贝就够了
```

## 13.12 判断依据：只要问一句话

**这一节是本章的实操结论。**

> ### 我要改的东西在第几层？
>
> | 回答 | 做法 |
> |---|---|
> | 我不打算改 | **什么都不用做**，`b = a` 就行 |
> | 数据是数字/字符串/元组（不可变） | **什么都不用做**，它改不了 |
> | 只在最外层增删元素 | **浅拷贝**（`a[:]` / `d.copy()`） |
> | 要改嵌套在里面的内容 | **深拷贝**（`copy.deepcopy(a)`） |

**换个更省事的问法**："改了 `b` 会不会影响 `a`？如果会，我能接受吗？"

现在回头看开篇那五笔账，**它们是同一件事**：

| 现象 | 真相 |
|---|---|
| 3.3 变量是标签 | `=` 贴标签，不复制对象 |
| 9.21 `b = a` 后改 `b`，`a` 也变 | 从来只有一个列表 |
| 9.20 `[[0]*3]*3` 改一行三行全变 | `*` 复制的是引用（下面 13.13 验证） |
| 10.4 元组里的列表能改 | 元组冻住的是"指向谁"，不是"那个东西的内容"（13.14） |
| 11.23 `d.copy()` 后内层还共享 | 浅拷贝只到第一层（刚才 13-16 验证过） |

**一句话总括**：**复制的是引用，不是对象。**

## 13.13 回收伏笔：`[[0]*3]*3` 的真相

**示例 13-17　三行其实是同一个列表**

第 9.20 节留的账，现在能解释了：

```python
grid = [[0] * 3] * 3
print(grid)             # => [[0, 0, 0], [0, 0, 0], [0, 0, 0]]     看着是个 3×3 表格

grid[0][0] = 9          # 只想改第一行第一格
print(grid)             # => [[9, 0, 0], [9, 0, 0], [9, 0, 0]]     ！三行都变了
```

用 `is` 一验就明白：

```python
grid = [[0] * 3] * 3
print(grid[0] is grid[1])       # => True      第一行和第二行是同一个列表
print(grid[1] is grid[2])       # => True      第三行也是
```

**因为 `列表 * 3` 做的是"把里面的引用重复三遍"，不是"造三个列表"**：

```text
[[0]*3] * 3 得到：

  grid ──→ [ ●, ●, ● ]
             │  │  │
             └──┴──┴──→ [0, 0, 0]      只有这一个列表，被指了三次
```

**正确写法用推导式**——因为 `for` 每转一圈，`[0]*3` 都会**重新执行一次**，每次造一个新列表：

```python
grid = [[0] * 3 for _ in range(3)]      # 循环三次，每次现造一个新列表

grid[0][0] = 9
print(grid)                     # => [[9, 0, 0], [0, 0, 0], [0, 0, 0]]     ✅
print(grid[0] is grid[1])       # => False                                 三个独立的列表
```

**注意内层的 `[0] * 3` 是安全的**，因为 `0` 是不可变的数字，重复三个 `0` 的引用毫无问题。**只有元素本身可变时，`*` 才会出事**。

## 13.14 回收伏笔：元组不可变的边界

**示例 13-18　元组里的列表能改**

第 10.4 节留的账：

```python
t = (1, [2, 3])

t[1].append(4)          # 改元组【里面】那个列表
print(t)                # => (1, [2, 3, 4])       ！"不可变"的元组变了

t[0] = 99
# => TypeError: 'tuple' object does not support item assignment
```

**两件事其实不矛盾**，区别就是 13.7 节那张表：

- `t[0] = 99` 是**改元组本身**（换第 0 位指向谁）→ ❌ 元组禁止
- `t[1].append(4)` 是**改元组指向的那个列表**（元组第 1 位还是指着它）→ ✅ 元组管不着

```text
t = (1, [2, 3])

  t ──→ ( ●, ● )
          │  │
          │  └──→ [2, 3]      ← 元组只保证这个箭头不变
          └──→ 1                 箭头指向的列表内容，元组管不了
```

> **记住这条**：**元组的"不可变"是浅层的**——它冻住的是"每一位指向谁"，不是"那些东西的内容"。
>
> **实用结论**：想要一份真正改不了的数据，**元组里只能装不可变的东西**（数字、字符串、其他这样的元组）。这也解释了第 10.9 节那个规则——含列表的元组不可哈希，不能当字典键：

```python
hash((1, [2, 3]))
# => TypeError: unhashable type: 'list'
```

`deepcopy` 对元组同样有效（它会连里面的列表一起复制）：

```python
import copy

t = (1, [2, 3])
t2 = copy.deepcopy(t)
t2[1].append(5)
print(t, t2)            # => (1, [2, 3]) (1, [2, 3, 5])      ✅ 互不影响
```

## 13.15 深拷贝的代价

`deepcopy` 看着万无一失，于是很多人养成"不确定就 `deepcopy`"的习惯。**这个习惯要不得**，它有三个实实在在的代价。

**示例 13-19　`deepcopy` 有多慢**

```python
import copy, time

# 造一份两万条的嵌套数据（列表套字典，里面还有列表和字典）
data = [{"id": i, "tags": ["a", "b", "c"], "meta": {"x": i, "y": i * 2}}
        for i in range(20000)]

t0 = time.perf_counter(); s = copy.copy(data);     t1 = time.perf_counter()
t2 = time.perf_counter(); d = copy.deepcopy(data); t3 = time.perf_counter()

print(f"浅拷贝：{t1 - t0:.6f} 秒")
print(f"深拷贝：{t3 - t2:.4f} 秒")
print(f"深拷贝慢了约 {(t3 - t2) / (t1 - t0):.0f} 倍")
```

我这台机器的结果（**你的数字会不同，量级是一样的**）：

```text
浅拷贝：0.000198 秒
深拷贝：0.0823 秒
深拷贝慢了约 416 倍
```

**三个代价**：

| 代价 | 说明 |
|---|---|
| **慢** | 要递归走遍整个结构，还要记录"哪些对象已经拷过"（防止循环引用死循环） |
| **内存翻倍** | 每一层都造了新对象，原来占 100MB 就再占 100MB |
| **有些东西拷不了** | 文件句柄、网络连接、锁、数据库连接 |

第三条会直接报错，见识一下：

```python
import copy, threading

copy.deepcopy(threading.Lock())
# => TypeError: cannot pickle '_thread.lock' object
```

```python
import copy

f = open("/dev/null")
copy.deepcopy(f)
# => TypeError: cannot pickle 'TextIOWrapper' instances
```

（Windows 上把 `/dev/null` 换成任意一个存在的文件即可。）

报错里出现 `pickle` 这个词，是因为 `deepcopy` 对付不认识的对象时会借用序列化机制——而**"打开的文件"这种东西本质上无法复制**：你不可能凭空多出一个指向同一位置的操作系统句柄。

> **记住这条**：**不要养成"不确定就 `deepcopy`"的习惯。** 先花五秒钟问 13.12 那句话——**我要改的东西在第几层**。只改第一层，浅拷贝够用，快 400 倍。

## 13.16 什么时候真的需要深拷贝

三个真实场景，都有共同特征：**一份数据要复制出多份分别修改，而且它是嵌套的**。

### 场景一：配置模板

**示例 13-20　默认配置复制多份**

```python
import copy

default = {
    "host": "localhost",
    "retry": {"times": 3, "delay": 1},         # 嵌套
    "tags": [],                                 # 嵌套
}

dev = copy.deepcopy(default)
prod = copy.deepcopy(default)

dev["host"] = "dev.example.com"
prod["host"] = "prod.example.com"
prod["retry"]["times"] = 10                    # 改的是内层
prod["tags"].append("生产环境")                  # 改的是内层

print(dev["retry"]["times"], dev["tags"])      # => 3 []                    ✅ 没被影响
print(prod["retry"]["times"], prod["tags"])    # => 10 ['生产环境']
print(default["retry"]["times"])               # => 3                       ✅ 模板干净
```

### 场景二：撤销功能

**示例 13-25　撤销功能雏形**

每次操作前存一份快照，快照必须和当前数据**彻底断开**，否则数据一改快照跟着改，那就等于没存。

```python
import copy

history = []                                    # 快照栈
data = {"标题": "报告", "章节": ["引言"]}

history.append(copy.deepcopy(data))             # 存快照（必须深拷贝！）
data["章节"].append("正文")

history.append(copy.deepcopy(data))             # 再存一份
data["章节"].append("结论")

print("当前：", data)                            # => 当前： {'标题': '报告', '章节': ['引言', '正文', '结论']}

data = history.pop()                            # 撤销：取回上一个快照
print("撤销一步：", data)                        # => 撤销一步： {'标题': '报告', '章节': ['引言', '正文']}

data = history.pop()
print("再撤一步：", data)                        # => 再撤一步： {'标题': '报告', '章节': ['引言']}
```

**如果这里用的是浅拷贝**，`history` 里存的三份快照的 `章节` 会是同一个列表，撤销回去会发现三份内容完全一样——**撤销功能等于没做**。

### 场景三：最常见的数据形状——列表套字典

**示例 13-21　列表套字典的拷贝陷阱**

`[{...}, {...}]` 这个形状你以后会天天见到——**从 JSON、CSV、数据库读出来的数据几乎都是它**（第 17 章会大量出现）。

```python
records = [
    {"name": "小明", "scores": {"数学": 80}},
    {"name": "小红", "scores": {"数学": 90}},
]

# ❌ 想备份一份，用了浅拷贝
backup = records[:]
backup[0]["name"] = "改过了"        # 改的是内层那个字典

print(records[0]["name"])           # => 改过了       原数据被污染了
```

`records[:]` 复制的是**外层那个列表**（装着两个引用的容器），而你要改的恰恰是**里面的字典**。

```python
import copy

records = [
    {"name": "小明", "scores": {"数学": 80}},
    {"name": "小红", "scores": {"数学": 90}},
]

# ✅ 列表套字典要备份，必须 deepcopy
backup = copy.deepcopy(records)
backup[0]["name"] = "改过了"
backup[0]["scores"]["数学"] = 100

print(records[0])       # => {'name': '小明', 'scores': {'数学': 80}}      ✅ 原数据完好
print(backup[0])        # => {'name': '改过了', 'scores': {'数学': 100}}
```

> **记住这条**：**看到 `[{...}, {...}]` 这个形状要备份，直接 `deepcopy`。** 因为你想改的几乎永远是里面的字典，浅拷贝一定不够。

**归纳成一句判断**：

| 场景 | 为什么必须深拷贝 |
|---|---|
| 一份模板生成多个实例 | 各实例要独立修改**嵌套的**配置项 |
| 撤销 / 回滚快照 | 快照必须和当前数据彻底断开 |
| 单元测试的初始数据（第 29 章） | 每个测试用例都要拿到干净的数据 |
| 把数据交给别处处理前 | 防止对方在你不知道的情况下改了它 |

## 13.17 预告：函数参数也是同一件事

**示例 13-16 的第三种面貌**——把列表传给函数，函数里改了它，外面也变：

```python
lst = [1, 2, 3]

# 下一章会讲 def，这里只看现象
def add_one(items):
    items.append(999)       # 函数里改了传进来的列表

add_one(lst)
print(lst)                  # => [1, 2, 3, 999]      外面的列表被改了
```

**这是"传引用"的第三次现身**（3.3 标签 → 本章拷贝 → 函数参数）。原理完全一样：`items` 只是贴在同一个列表上的**又一张标签**。

## 13.18 三种推导式统一回顾

四个容器学完了，三种推导式也该摆在一起看看——**它们只差括号和有没有冒号**。

**示例 13-22　三种推导式并排看**

```python
records = [("小明", 92), ("小红", 88), ("小刚", 92)]

# 列表推导式：[表达式 for ...]           → 列表
print([r[0] for r in records])           # => ['小明', '小红', '小刚']

# 字典推导式：{键: 值 for ...}   有冒号   → 字典
print({r[0]: r[1] for r in records})     # => {'小明': 92, '小红': 88, '小刚': 92}

# 集合推导式：{表达式 for ...}   无冒号   → 集合（自动去重）
print(sorted({r[1] for r in records}))   # => [88, 92]     两个 92 合并了
```

| 想要 | 写法 | 记忆点 |
|---|---|---|
| 列表 | `[x for x in it]` | 方括号 |
| 字典 | `{k: v for ... in it}` | 花括号 + **冒号** |
| 集合 | `{x for x in it}` | 花括号 + **没有冒号** |

**示例 13-23　`(x for x in ...)` 不是"元组推导式"**

按上面的规律，圆括号是不是元组推导式？**不是——元组没有推导式。**

```python
g = (x * 2 for x in [1, 2, 3])

print(g)            # => <generator object <genexpr> at 0x...>      你运行时地址会不同
print(type(g))      # => <class 'generator'>
```

圆括号得到的是**生成器表达式**，一个"用的时候才算"的懒家伙。它有个要留神的性质——**只能用一次**：

```python
g = (x * 2 for x in [1, 2, 3])
print(list(g))      # => [2, 4, 6]
print(list(g))      # => []          ！已经用光了，第二次是空的
```

想要元组，**明确写 `tuple()`**：

```python
print(tuple(x * 2 for x in [1, 2, 3]))      # => (2, 4, 6)
```

生成器表达式最实用的地方是**喂给 `sum` / `max` / `any` / `all` 这类函数**——省掉中间那个列表：

```python
print(sum(x * 2 for x in [1, 2, 3]))        # => 12      不用先造 [2, 4, 6]
```

**为什么元组没有推导式？** 因为推导式的核心价值是"边算边攒"，而元组是不可变的，攒不了——只能先攒成别的再转。完整讨论（含"什么时候该用生成器省内存"）在第 33 章。

## 综合示例

### 示例 13-24　学生档案模板批量生成

把本章的核心结论用在一个真实场景上：有一份默认档案模板，要为每个学生生成一份并分别填写。

先看**错误做法**，注意它错得多隐蔽：

```python
template = {
    "name": "",
    "scores": {"数学": 0, "语文": 0},        # 嵌套字典
    "notes": [],                             # 嵌套列表
}

# ❌ 一个用赋值，一个用浅拷贝，两个都不对
a = template                     # 同一个对象
b = template.copy()              # 浅拷贝：scores 和 notes 还是共享的

a["name"] = "小明"                # 通过 a 改，直接改到模板身上
b["name"] = "小红"                # 第一层，浅拷贝保护住了
b["scores"]["数学"] = 95          # 第二层，没保护住
b["notes"].append("需要补课")      # 第二层，没保护住

print(template)
# => {'name': '小明', 'scores': {'数学': 95, '语文': 0}, 'notes': ['需要补课']}
#    模板被彻底污染：名字被 a 改了，成绩和备注被 b 改了
```

**这种 bug 特别难查**：`b["name"]` 是第一层，`b.copy()` 保护住了，看着"拷贝生效了"；`b["scores"]` 在第二层，没保护住。**同一份代码里一半正常一半出错**，你会怀疑一切，就是想不到是拷贝的问题。

正确做法：

```python
import copy

template = {
    "name": "",
    "scores": {"数学": 0, "语文": 0},
    "notes": [],
}

# ✅ 每份档案都从模板深拷贝一份，彼此完全独立
a = copy.deepcopy(template)
b = copy.deepcopy(template)

a["name"] = "小明"
a["scores"]["数学"] = 88

b["name"] = "小红"
b["scores"]["数学"] = 95
b["notes"].append("需要补课")

print(a)         # => {'name': '小明', 'scores': {'数学': 88, '语文': 0}, 'notes': []}
print(b)         # => {'name': '小红', 'scores': {'数学': 95, '语文': 0}, 'notes': ['需要补课']}
print(template)  # => {'name': '', 'scores': {'数学': 0, '语文': 0}, 'notes': []}
#                     ✅ 模板干干净净，还能继续用
```

这个模式有个名字叫**原型复制**：留一份干净的原型，每次要用就复制一份去改。第 14 章学了函数之后，可以把它包成 `new_profile()` 一行调用。

### 拷贝语义

| 你熟悉的 | Python |
|---|---|
| 引用类型赋值（`List<T> b = a;`） | `b = a`——**完全一样的行为** |
| 值类型 / `struct` 赋值会复制 | **Python 没有值类型**，一切都是对象、一律走引用 |
| `new List<T>(a)` / `a.ToList()` | `list(a)` / `a[:]`（浅拷贝） |
| `Dictionary<K,V>(d)` | `dict(d)` / `d.copy()` |
| `MemberwiseClone()` | `copy.copy(x)` |
| 深拷贝（要自己实现或序列化一圈） | **`copy.deepcopy(x)`——语言自带** |
| `ICloneable` | 不需要，`copy` 模块通吃 |
| `readonly` / `const` | 没有真正的等价物；靠**选用不可变类型**（元组、`frozenset`）来达到类似效果 |
| `ImmutableList<T>` | `tuple`（但只保证浅层不可变） |

**四个必须注意的差异**：

1. **Python 没有值类型，所以没有"赋值就复制"的情形。** C# 里 `int a = b` 复制了值，`List<T> a = b` 共享引用，你靠**类型**就能判断。Python 里 `a = b` **永远是共享引用**——数字看着"没问题"，是因为数字改不了（13.7），不是因为它被复制了。

2. **深拷贝在 Python 里是一行，在 C# 里是件麻烦事。** 这是好事，但也带来坏习惯——因为太容易写，很多人到处 `deepcopy`。**它比浅拷贝慢约 400 倍**（13-19 实测）。

3. **元组不等于 `readonly`。** `ImmutableList<T>` 里如果装的是可变对象，那些对象照样能改——Python 的元组一样。**"不可变"在两种语言里都是浅层的**，这一点是共通的坑。

4. **`is` 不是 `==`，别弄反。** C# 的 `==` 对引用类型默认比引用（除非重载），`Equals` 比内容；Python 反过来——**`==` 比内容（默认行为很智能），`is` 比引用**。从 C# 过来的人容易把 `is` 当 `==` 用。

### `all([])` 是 `True`

LINQ 的行为**完全一致**，可以拿来印证：

```csharp
new int[]{}.All(x => x > 60)   // true   —— 和 Python 的 all([]) 一样
new int[]{}.Any(x => x > 60)   // false  —— 和 Python 的 any([]) 一样
```

SQL 里也有对应的坑：`WHERE NOT EXISTS (子查询为空)` 恒为真、`SELECT AVG(col)` 在无行时给 `NULL` 而不是 0。**"空集合"的边界在哪门语言里都要单独想一遍。**

### 容器选型对照

| 你熟悉的 | Python |
|---|---|
| `List<T>` / `ArrayList` | `list` |
| `T[]`（定长数组） | 没有直接对应；用 `list`，或 `array` 模块（工具箱 T2） |
| `Tuple<T1,T2>` / `ValueTuple` | `tuple` |
| `Dictionary<K,V>` | `dict` |
| `SortedDictionary<K,V>` | 没有内置；`dict` + `sorted(d.items())`（第 25 章讲更多） |
| `HashSet<T>` | `set` |
| `IEnumerable<T>` | **可迭代对象**（13.2） |
| `IList<T>` / `IReadOnlyList<T>` | **序列**（13.2） |
| `IDictionary<K,V>` | **映射**（13.2） |
| `record` / 匿名类型 | `dict`，或 `dataclass`（第 27 章）、`NamedTuple`（第 10 章折叠块） |

**一个观念差异**：C# 里你会为"一条记录"定义一个 `class` 或 `record`；**Python 里绝大多数人先用 `dict`**，等结构稳定了再考虑 `dataclass`。这不是偷懒——从 JSON / 数据库读出来的数据天然就是 `dict`，硬转成对象反而多一层。**代价是失去了编译期检查**（字段名打错了要到运行时才知道），第 33 章的类型注解能补回一部分。

### `sum([])` 是 0 但 `max([])` 报错

这个不对称在 SQL 里也一样：`SUM` 对空结果集给 `NULL`，`COUNT` 给 0，而 `MAX` 给 `NULL`。Python 选择让 `sum([])` 返回 0（数学上加法单位元），`max([])` 直接报错（没有合理答案）。**要兜底就用 `max(x, default=...)`**，相当于 SQL 里的 `COALESCE(MAX(col), 默认值)`。

## 本章易错点

| ❌ 情况 | 症状 | ✅ 解法 | 原因 |
|---|---|---|---|
| **`b = a` 以为复制了** | 改 `b` 影响 `a` | 按需浅拷贝或深拷贝 | `=` 是贴标签 |
| **嵌套数据用浅拷贝** | 改内层时原件也变 | `copy.deepcopy(a)` | 浅拷贝只到第一层 |
| `d.copy()` 后改内层字典 | 原字典的内层也变 | `deepcopy` | 同上 |
| **`[{...}, {...}]` 用 `[:]` 备份** | 改某条记录，原数据被改 | `deepcopy` | 要改的恰是内层字典 |
| `[[0]*3]*3` | 改一格整列都变 | `[[0]*3 for _ in range(3)]` | `*` 复制引用 |
| 以为元组里的数据安全 | 元组里的列表被别处改了 | 元组里只装不可变元素 | 不可变是浅层的 |
| **不确定就 `deepcopy`** | 程序慢 400 倍、内存翻倍 | 先问"要改第几层" | 深拷贝要递归走全部 |
| `deepcopy` 文件/锁/连接 | `TypeError: cannot pickle ...` | 只拷数据部分 | 这类对象无法复制 |
| **`all([])` 以为是 `False`** | 空数据通过了校验 | `if data and all(...)` | `all` 是"没有反例" |
| `sum(["a", "b"])` | `TypeError: ... 'int' and 'str'` | `"".join(...)` | `sum` 从 0 开始加 |
| `sum(字典)` | 同上 | `sum(d.values())` | 直接给字典 = 给键 |
| `max([])` | `ValueError: ... is empty` | `max(x, default=...)` | 空的没有最大值 |
| `reversed(集合)` | `TypeError: not reversible` | `sorted(s)` 或 `sorted(s, reverse=True)` | 集合无序 |
| `d[0]` 想取"第一个" | `KeyError: 0` | 字典没有"第几个" | 方括号里只能是键 |
| `sorted(d)` 以为得到值 | 得到的是键 | `sorted(d.values())` | 直接给字典 = 给键 |
| 以为 `(x for x in lst)` 是元组 | 得到 generator | `tuple(x for x in lst)` | 元组没有推导式 |
| 生成器用第二次 | 得到空结果 | 用 `list()` 存下来 | 生成器只能走一遍 |
| 两个平行列表靠下标对应 | 一边增删就错位，不报错 | 改用字典 | 选型错误 |
| 把列表传进函数后被改 | 外面的数据变了 | 见 14.10 | 传的是引用 |

## 本章小结

### 选型

- **三个问题定容器**：① 是"名字→值"吗 → **字典** ② 只关心"有哪些" → **集合** ③ 要不要增删 → 要用**列表**，不要用**元组**
- 九成情况落在**字典和列表**上；元组和集合是有明确理由时才用
- **看到两个列表靠下标对应，立刻改成字典**

### 三个概念

- **可迭代对象** ⊃ **序列**（能索引、能切片：字符串/列表/元组/`range`）；**映射**是字典；**集合两者都不是**
- 报错能反推问题：`not subscriptable`（不支持方括号）/ `IndexError`（越界）/ `KeyError`（没这个键）/ `not iterable`（连 `for` 都不行）

### 通用函数

- `len` / `min` / `max` / `sum` / `sorted` / `reversed` / `in` **四种容器通吃**
- **`sorted()` 永远返回列表**；直接把字典交给函数，函数拿到的是**键**
- `sum([])` 是 **0**，`max([])` **报错**（用 `default=`）；`sum` 只加数字
- **`all([])` 是 `True`**——它的语义是"没有反例"。用 `all` 校验时先问"数据可能为空吗"

### 拷贝（本章重点）

- **变量是标签，`=` 是贴标签不是复制**
- 区分两种操作：**`b = 新东西`** 只影响 `b` 自己；**`b.append(...)` / `b[0] = ...`** 是改对象，所有标签都看到
- **不可变对象（数字、字符串、元组）永远不需要拷贝**——需要操心的只有列表、字典、集合
- **浅拷贝**：`a[:]` / `list(a)` / `d.copy()` / `copy.copy(a)`——只复制**第一层**
- **深拷贝**：`copy.deepcopy(a)`——**递归复制每一层**
- **判断只需一句话：我要改的东西在第几层？** 第一层 → 浅拷贝；更里面 → 深拷贝
- 深拷贝**慢约 400 倍、内存翻倍、有些对象拷不了**，别当默认选项
- **`[{...}, {...}]` 要备份就直接 `deepcopy`**——这是最常见的数据形状
- **一句话总括本章：复制的是引用，不是对象。**

### 三种拷贝对照表（背下来）

| 写法 | 外层 | 内层 |
|---|---|---|
| `b = a` | 共享 | 共享 |
| `b = a[:]` / `list(a)` / `copy.copy(a)` | 独立 | **共享** |
| `b = copy.deepcopy(a)` | 独立 | 独立 |

### 推导式

| 想要 | 写法 |
|---|---|
| 列表 | `[x for x in it]` |
| 字典 | `{k: v for ... in it}`（**有冒号**） |
| 集合 | `{x for x in it}`（**无冒号**） |
| 元组 | **没有推导式**，写 `tuple(x for x in it)` |
| 生成器 | `(x for x in it)`——**懒、只能用一次**（第 33 章） |
