# 本仓库是一份 Python 3 中文新手教程（写作项目）

## ⚠️ 第一步：先读 `00_写作交接.md`

**在动手写任何正文、图纸、或修改任何文件之前，完整读一遍 `00_写作交接.md`。**

那一页是这个项目的单一入口，读完就能恢复全部上下文：当前进度、写作流程、十条铁律、已定决策（附理由，防止被推翻重议）、质检办法、用户情况、以及"下一章该写什么"。

**不要凭这个文件里的摘要就开始写作**——摘要只够让你判断该去读哪里。

## 即使没读文档也必须遵守的红线

1. **所有输出必须实测**，不能凭记忆写。用 `python3.12`（系统 `python3` 是 3.9）。
2. **写完必须跑三个质检脚本**，它们查的是互补的盲区，只跑一个会漏：
   ```bash
   python3.12 tools/check_outputs.py     chapters/chNN_*.md   # 逐行比对
   python3.12 tools/check_blocks.py      chapters/chNN_*.md   # 整块真跑，治 is 比较
   python3.12 tools/check_text_blocks.py chapters/chNN_*.md   # 多行输出块
   ```
3. **禁用 `fs_append`**——它会让文件在浏览器预览里变成 "Binary file"，用户就打不开了。要追加内容就写临时文件 + 用 python 脚本整体读入再整体写回。
4. **不设字数上限**，唯一标准是把概念讲清楚。用户明确要求过，不要重新提议加限制。
5. **推送一律直推 `main`，不开 PR**，写完主动推送不要询问。用户不熟 Git 且不愿为流程费心。
6. **用中文回答。** 用户有 20 年 C# ASP.NET WebForm + SQL Server 经验，Python 入门，大学数学已遗忘 → 每章末尾的 C#/SQL 对照折叠块有真实价值；**不做数学推导**。
7. **改正文必须同步改对应图纸**（`02_施工图.md` 里该章的打样记录），否则下次接手会照着过时的图纸写。
8. **一次只写一章**，写完就质检 + 推送 + 汇报。用户反馈过"三章一起写花的时间和 token 都太多"。

## 工作副本

唯一工作副本是 `/projects/sandbox/Python`（git 仓库本身），**不要另建目录**。

## 每写完一章要做的四件事

1. 跑三个质检脚本，全部通过
2. `python3.12 tools/sync_toc.py 章号 内容文件.txt` 同步目录小节
3. 回填 `02_施工图.md` 该章的**打样记录**（写清偏离图纸之处、实测发现、踩到的坑）
4. 更新三处进度表（`01_目录.md` / `README.md` / `00_写作交接.md`），改写交接文档末尾的"下一章"，然后提交推送
